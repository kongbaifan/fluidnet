## 2. 技术方案

### 2.1 执行方式

沿用 A1 的做法：新增一个**制冷站执行域**（与 A1 thermal 域并列），由内置集总设备按固定拓扑组成。每步先由设备关系算出各股质量流量与换热量，再对容器和库房状态做隐式 Euler；不经过通用管网求解器。两相物性只在设备模型内部查询（`state_ph`、`saturation_*`），与 ALGORITHM“管网内两相流不在计划内”的边界一致，B1 落地时在 ALGORITHM 补一句说明集总制冷站的适用范围。

会话、参数写入、PID、Python 项目控制、命令、历史、归档、重启读取全部复用 `SimulationSession`/`ThermalSession` 已有协议。

### 2.2 状态与方程

状态共 8 个：高压贮液器、低压循环桶、CO₂ 容器各 `(M, U)`，两库温度各 1 个。容器体积固定，每步由 `(M, U, V)` 和饱和物性反求压力、液位、液/气比焓：

```text
V = M_l/ρ_l(p) + M_v/ρ_v(p),   U = M_l·u_l(p) + M_v·u_v(p)
```

| 容器 | 质量 | 能量 |
| --- | --- | --- |
| 高压贮液器 | `dM = m_comp − m_valve` | `dU = m_comp·h_dis − Q_cond − m_valve·h_l,HP` |
| 低压循环桶（满液式板换，NH₃ 蒸气直接回桶） | `dM = m_valve − m_comp` | `dU = m_valve·h_l,HP + Q_hx − m_comp·h_v,LP` |
| CO₂ 容器（闭式循环，质量不变） | `dM = 0` | `dU = Q_coil,1 + Q_coil,2 + W_pump − Q_hx` |

设备关系：

```text
压缩机 i： m_i = EN_i · load_i · V_disp · n · ρ_v(p_LP) · η_vol；h_dis = h_s + (h_2s − h_s)/η_s；P_i = m_i·(h_dis − h_s)/η_mech
冷凝器：   Q_cond = N_fan_on/N_fan · UA_cond · (T_sat(p_HP) − T_wb)，再冷凝回气阀开度修正有效冷凝能力
节流阀：   m_valve = Kv · opening · sqrt(ρ_l · (p_HP − p_LP))
板换：     Q_hx = UA_hx · (T_sat,CO₂ − T_sat,NH₃)，两侧均按饱和处理
冷风机 j： Q_coil,j = min(fan_j · UA_coil · (T_room,j − T_sat,CO₂), m_pump,j · Δh_lv,CO₂ · x_max)
液泵：     m_pump = f(频率)，W_pump = m_pump·Δp/ρ/η
库房 j：   C_j · dT_j/dt = Q_leak,j + Q_load,j − Q_coil,j   （复用 A1 cold_room）
```

NH₃ 总量 `M_HP + M_LP` 恒定（冷凝器、板换、管道持液忽略，原文同样只给罐体），是天然的账本检查。液位适用区间 5%–95%，越界报诊断并停止，不夹值维持假平衡。

再冷凝回气阀（闭环 3）的物理方向在 B1 开环试验确认；若集总模型里该执行器不能按原文方向起作用，按原文的另一条动作（液位到下限时关小节流阀）实现，并在案例文档写明偏差。

### 2.3 控制

| 闭环 | 被控量 | 执行器 | 实现 |
| --- | --- | --- | --- |
| 1 | 低压循环桶压力（由目标蒸发压力换算） | 运行中压缩机载量 | PID |
| 2 | 高压贮液器压力（目标冷凝压力） | 电磁节流阀开度 | PID |
| 3 | 高压贮液器液位（上限 2/3、下限 1/2 + 20 cm） | 再冷凝回气阀；到下限关小节流阀 | Python 规则 |
| 4 | 库温 | 冷风机风量比 | PID（每库一个） |
| 5 | CO₂ 供液 | 液泵频率（按冷风机开机状态） | Python 规则或 PID |
| 上层 | 低压桶/高压罐液位、平均载量 | 压缩机台数、冷凝器风机组数 | Python 规则，带最小启停时间 |

外部接口与原文一致：输入目标蒸发压力、目标冷凝压力（运行时可写）；反馈能耗（压缩机 + 风机 + 泵累计 kWh）和需求满足度。原文没有定义需求满足度，本项目定义为库温落在设定带内的时间占比，文档注明是自定义口径。启停类执行器用 0/1 数值参数，不扩展布尔类型。

## 4. 验收

对应原文唯一的结果陈述“输入两个压力目标即可长时间稳定自运行”：

| # | 场景 | 通过条件 |
| --- | --- | --- |
| 1 | 额定负荷 24 h | 两库库温在设定 ±1 K 内；低压桶/贮液器压力跟踪目标，无持续振荡；两罐液位在上下限内 |
| 2 | 一库负荷阶跃（升/降） | 上层循环增/减开机台数；库温恢复；压缩机启停次数不超过最小启停时间允许的上限 |
| 3 | 运行中改目标蒸发/冷凝压力 | 平稳过渡到新目标；能耗与需求满足度随之变化且可解释 |
| 4 | 环境湿球温度变化 | 冷凝器风机组数调整，冷凝压力保持 |

每个场景同时检查 NH₃/CO₂ 质量守恒、能量账本 ≤0.1%、无越界诊断。产品验收：pytest 全量与覆盖率门禁、契约检查、新浏览器脚本（创建 → 运行 → 改目标压力 → 保存 → 重启读取 → 同帧复算）。

不做：B-S13 式的大场景矩阵、24 h 性能门槛以外的性能承诺、与倍思鹿的数值对比。

## 5. 数据

没有倍思鹿项目文件、参数和初态。全部参数用工程假设，沿用 A0 的 `value/unit/source_type/source` 登记；截图读数（如 0.12 MPa、载量 0.21）不作为设计点。需要的最少参数：压缩机排量/转速/效率、冷凝器 UA 与风机组数、三个容器容积与初始充注、节流阀 Kv、板换与冷风机 UA、泵曲线、库房围护与负荷（复用 A0 单库参数）。

## 6. 风险

| 风险 | 处理 |
| --- | --- |
| 容器 `(M,U,V)` 反求在近空/近满或近临界时失败 | 限定 5%–95% 液位与工作压力区间，越界诊断停止；B1 先做开环边界测试 |
| 原文闭环方向在集总模型中不成立（尤其闭环 3） | B1 开环逐个验证执行器方向，按物理改写并在文档写明与原文的差异 |
| 五个闭环相互干扰导致振荡 | 逐个接入；先单闭环整定，再加上层循环；最小启停时间与载量变化率限幅 |
| 集总模型被误读为工程精度 | 案例文档写明边界：无管路压降、无冷凝器/板换持液、饱和假设，结果只用于控制逻辑验证 |
