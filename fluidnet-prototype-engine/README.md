# FluidNet Prototype Engine

基于现有 FluidNet Studio 交互原型建立的独立项目。前端继承画布、模块库、型号、设备属性、草稿/应用和曲线工作流；后端重新定义模块合同、网络编译、水力算法和 HTTP 接口，并提供基于 Pydantic 的契约层、CoolProp 单相物性服务、版本化 Python 模块包和独立 Worker 生命周期。

本目录独立于原来的 `fluidnet/` 与 `web/`。原型来源为 `../output/visualizations/fluidnet-studio-prototype.html`。前端原型现拆分为 `frontend/index.html`(HTML/CSS 外壳与挂载点)与 `frontend/studio.js`(原内联 JavaScript),新增 `frontend/engine-client.js` 负责真实计算接口;新增 `frontend/project-services.js` 管理控制与工作区接口；`index.html` 按服务层、适配器、界面的顺序加载脚本,服务把 `frontend/` 目录以 `StaticFiles(html=True)` 挂载到 `/`,默认入口页即 `frontend/index.html`。

2026-10-28 已完成[1080p 基线与批量工况计划](docs/NEXT_DEVELOPMENT_1080P_PLAN.md)的六个工作包，唯一界面设计与验收基准为 **1920×1080（16:9）**。从左侧“批量”或建模工具栏“批量工况”进入；操作见[使用说明](docs/SCENARIO_BATCHES.md)，验证范围见[本轮验收](docs/FHD_BATCH_ACCEPTANCE.md)。

## 启动

Python 3.11 或更高版本，在本目录执行：

```powershell
.\start.ps1
```

脚本首次创建本目录下的 `.venv` 并安装依赖，随后打开浏览器。默认地址 `http://127.0.0.1:8798`，交互接口文档在 `/docs`。也可以手动运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m fn_engine serve --port 8798 --open
```

使用现有环境时可执行 `python -m pip install -r requirements.txt`，再执行 `python -m fn_engine serve --port 8798 --open`。本版本以源码/可编辑安装运行，不提供可独立分发的前端 wheel 包。

只启动计算服务可用 `python -m fn_engine serve --headless --data-dir .runtime/workspace`。第三方通过 `POST /api/v1/projects/{project_id}/runs` 启动已保存项目，支持固定修订与工况；完整启停、订阅和变量写入示例见 [Python / JavaScript 客户端](examples/external_clients/README.md)。

## 对外开放与访问令牌

运行项目和模块验证台会在 Worker 子进程中执行用户的 Python 代码。子进程不是操作系统级沙箱，所以服务默认只监听 127.0.0.1，本机访问不需要令牌。要让其他机器（三维界面、数字孪生、PLC 网关）调用，先创建令牌再开放监听：

```powershell
python -m fn_engine token create 三维看板 --scope read      # 只读：GET 接口与推送
python -m fn_engine token create 控制网关 --scope control   # 另可启动运行、发命令、写变量
python -m fn_engine serve --host 0.0.0.0 --port 8798 --cors-origin http://twin.local
```

- `--auth auto`（默认）：监听本机以外的地址时必须带令牌；没有令牌时拒绝启动。`--auth off` 在这种情况下也会被拒绝。服务放在反向代理后面（自己只监听 127.0.0.1）时请用 `--auth required`。
- 令牌只显示一次；`.runtime/tokens.json`（或 `FLUIDNET_TOKEN_FILE`）只保存 SHA-256 哈希。`token list` 查看、`token revoke <id>` 立即撤销。
- 请求头 `Authorization: Bearer <令牌>`；浏览器 WebSocket 不能设请求头时，用子协议 `fluidnet.bearer.<令牌>`。前端页面会弹窗要求输入令牌，只保存在当前标签页。
- 没有内置 HTTPS：跨网络使用时请放在 TLS 反向代理后面，否则令牌以明文传输。

## 已接通的工作流

1. 打开“泵阀并联管网”，点击“检查连接”。请求后端完成端口、参数、内部通路和压力参考校验。
2. 点击“运行”或“单步”。原型项目经归一化转换成新合同，后端返回真实水力与热力结果。
3. 修改 V1 的开度，点击“预览并应用”，再单步。草稿值不进入计算，已应用值进入下一次求解。
4. 画布、设备变量表和曲线读取同一运行帧。端口的温度、比焓、密度和干度来自热力层；设备“全部变量”另有黏度、比热和通路吸热量。
5. 点击“保存原型”将全部项目与编辑草稿事务写入本地 SQLite，服务端确认后显示已保存；跨标签页修改会检测修订冲突。服务重启后可恢复项目，并在“运行记录 → 服务端档案”查看历史与曲线。

初始算例的 A 路质量流量约为 **3.582677 kg/s**。A 路开度从 80% 改为 40% 后，A 路约为 **2.346313 kg/s**。这是内置参数下的回归算例，示例泵曲线不是厂家标定数据。默认 `property_coupling='reference'` 下热力层不改变水力结果，这两个值与接入热力层之前完全一致。

“双侧换热机组”示例（UA = 2000 W/K）中，热侧 65.002 → 62.741 °C，冷侧 25.002 → 27.307 °C，换热量约 75.4 kW。

项目页可创建“氨制冷站与二次液体回路”单盘管案例，或从“双盘管示例”选择同回路双支路、水与乙二醇独立回路。自己的项目可从建模页“建立热耦合”选择管段和容器，最多建立两条关联同一容器的关系；逐盘管及合计指标、曲线跟随实际配置，删除端点有影响提示并支持撤销。默认单盘管 30% 乙二醇设计点换热约 **16.05 kW**；操作、模型边界和变量见 [热耦合说明](docs/THERMAL_COUPLING.md)，小窗口编辑与重启复算的补充验收见 [完成情况核查](docs/DEVELOPMENT_COMPLETION_AUDIT.md)。

## Python 项目控制与可靠保存

在“控制”页编辑 `initialize(ctx)`、`step(ctx, dt_s)`、`finalize(ctx)`，声明输入/输出后点击“预览一个周期”。预览使用独立 Worker 真实执行，并返回拟写入值；启用脚本后新建动态运行，输出才会进入后续子步。内置示例将 V1 开度设为 0.65（65%）。旧 Lua 文本原样保留，手动迁移或载入 Python 示例后才能启用。

`ctx.read(key)` / `ctx.write(key,value)` 使用引擎单位（Pa、K、kg/s、开度 0–1），`ctx.state` 为受管理的 JSON 状态。脚本按仿真时间采样；失败子步重试复用提案，接受后提交状态。每个参数只允许一个控制者；脚本可以调整 PID 设定值，不能覆盖 PID 已绑定的设备参数。语法、异常、超时或非法写入会停止运行并保留已接受历史。

`serve` 默认启用 SQLite 工作区：本目录 `.runtime/workspace/`；可用 `--data-dir <目录>` 或 `FLUIDNET_DATA_DIR` 指定。兼容仅配置 `FLUIDNET_MODULE_STORE` 的启动方式时，工作区默认在其 `.workspace/` 子目录。一个目录同时只允许一个服务进程。

保存涵盖画布、草稿、型号、库值、曲线绑定、脚本文本和项目固定模块快照；最近 5 个工作区修订保存在数据库。浏览器继续保留草稿备份；保存失败显示原因并保持未保存状态。陈旧页面返回 409，先导出当前草稿，再点击“载入服务器”。载入前另外备份到浏览器键 `fluidnet-prototype-engine-v1-before-workspace`。

运行归档保留最近 20 次结束运行、最近 `history_window` 帧和约 2000 点的全程抽稀曲线；请求、脚本哈希、最新变量、事件及诊断一起保存，每次发布帧完成事务后更新最后落盘时间。重启时未结束的运行标为 `interrupted`，未确认命令标为拒绝；查看历史后需要新建运行继续计算。运行档案支持查看、导出和删除。

顶部“备份与恢复”支持在线下载完整 ZIP、校验并恢复到新目录、查看容量和恢复最近 5 个工作区修订。备份包含已保存项目、运行归档和模块版本；未保存草稿先保存或导出。恢复旧修订会生成新修订并保留运行档案。命令行也提供停服备份与恢复，详见 [备份与恢复说明](docs/WORKSPACE_BACKUP.md)。跨重启继续原仿真仍未实现。

项目页“管理”可单独保存、重命名、导入导出和恢复最近 5 个项目修订；“服务器项目”可载入已保存项目。每个项目独立检测修订冲突，保存或恢复一个项目会保留服务器上的其他项目。旧版数据库首次打开时自动迁移到版本 3，保留原有项目和运行档案，并增加独立批次存档。

工作台可新建、复制、编辑和选择工况，覆盖值使用参数面板的显示单位；运行快照记录所选工况和已保存项目修订。“模块版本”提供 Python 模块变更预览，兼容升级先保存旧修订，再统一更新全部实例；不兼容变更明确拒绝。曲线页可对照同一项目的两次已完成运行。使用方法、验证入口和交付范围见 [建模工作流验收说明](docs/MODELING_TRIAL_VALIDATION.md)。

“批量”页可一次生成参数工况或选择已有工况，固定项目、模块和控制脚本快照后顺序运行。每批最多 20 个工况、16 个观察变量；结果表、最多四条同变量曲线和 CSV 可重复查看。批次结果独立于普通运行的 20 条保留策略，支持取消剩余项和服务中断后重新运行未完成项，详见[批量工况说明](docs/SCENARIO_BATCHES.md)。

## 可编程模块验收入口

1. 打开「模块」，找到服务器清单加载的「可编程阀门 · Python · v1」。
2. 点击「独立验证」并运行：验证台显示实际流量、evaluate 变量/密度、网络关系、commit_step 状态和源码哈希。
3. 点击模块卡片的「管网算例」：创建「压力源 → 管道 → 可编程阀门 → 出口」，点击运行完成 1 秒、10 个成功时间步。
4. 在设备「全部变量」中查看累计通过质量和提交次数，并加入曲线。也可从模块库拖入新的实例，编辑参数后预览并应用。
5. Python 源码编辑形成浏览器草稿；独立验证执行草稿。项目执行插入时绑定的已保存版本，后续编辑和发布不会改变已有项目。

## 模块开发与版本保存

1. 在「模块库 → 新建模块」选择 Python 模板，填写唯一标识和名称。
2. 在「代码」编辑 `module.py` 的四阶段方法，以及可选的设计函数 `design.py`。在「变量属性」新增/编辑数值参数和输出，在「绘制模块 / 通路设置」编辑端口及内部连接。
   在「变量值」选择一组库值后点击「执行设计函数」，后端 Worker 由这组库值计算派生参数，确认差异后才写回该库值；随后可「保存为设备型号」供项目使用。
3. 「契约与版本」可以编辑完整 JSON，包括其他参数类型和单位换算。点击「校验并应用契约」完成 Pydantic、Python 语法、Worker 入口检查，并更新参数面板。
4. 「独立验证」配置边界并试算；“配置工况与预期值”可设置多工况及最终变量的预期值、绝对/相对容差，运行测试组合查看逐项误差，配置随工作区保存。回到编辑器填写版本备注，点击「保存新版本」。后端重新校验、用参数默认值试算并验证声明的输出后，才写入不可变版本。
5. 版本按模块 ID 从 v1 递增；内置示例 v1 的下一版本为 v2。「刷新版本」查看备注、哈希和验证状态，「载入为草稿」可以基于历史版本继续开发。
6. 拖入项目或创建管网算例时保存完整版本快照和引用。同一项目中同一模块 ID 使用同一版本；发布后新项目可以使用新版，已有项目继续使用原版，并可在项目内预览、升级到兼容版本或从项目修订回退。

模块版本默认保存在本项目 `.runtime/module-packages/module-<id>/v<N>/`，包含 `manifest.json`、`module.py`、可选的 `design.py`、`release.json`（备注、时间、试算条件与结果）。可用 `--module-dir` 或环境变量 `FLUIDNET_MODULE_STORE` 指定持久目录；从备份恢复的工作区默认使用其 `module-packages/`。服务重启不会丢失这些文件；该目录属于本地用户数据，Git 忽略它，完整 ZIP 备份会包含这些版本。`modules/` 中的示例包不被修改。「保存原型」保存整个工作区及编辑草稿到服务端，与模块「保存新版本」分开。

保存前试算会为每条启用通路各接一组独立压力边界，多通路模块（如两侧独立的换热结构）在同一个网络中一次求解；通路共用端口、端口未绑定通路或非流体端口会被拒绝，并在诊断中说明。数值、布尔、文本和曲线参数都可以在设备面板和验证台按类型编辑；数值参数显示单位换算，曲线参数使用 JSON 点对数组。设备面板的草稿仍通过“预览并应用”生效。

运行中一次应用多个设备参数时，参数统一换算后整批提交；全部校验通过才在同一帧边界生效，任何一项拒绝则保留全部已应用值和待修改草稿。

“项目控制逻辑”支持最多 16 个脚本，可分别选择、编辑、新增、删除、启用和预览，保留各自的输入输出、采样周期及超时。运行固定全部已启用脚本的快照；编辑一个脚本不会覆盖其他脚本。旧版单脚本自动迁入列表，旧 Lua 文本保留为禁用草稿，转换为 Python 后才能启用。

## 能力范围

| 能力 | 当前行为 |
| --- | --- |
| 压力边界、连接节点 | 支持；各连通子网络必须有压力参考 |
| 泵 | 流量—扬程曲线、转速相似律、轴功率估算；曲线外/反向/停泵工况报错 |
| 阀门 | Kv × 开度，正反流；0% 开度精确约束零流量 |
| 管道 | Darcy–Weisbach、层流关系、Haaland 湍流近似及过渡区插值；可选向环境散热（`heat_loss_ua_w_k`，默认 0 为绝热） |
| 热力层 | 端口压力 + 焓；按流向迎风传焓、节点按质量加权混合；内置泵与 Python 泵/压缩机关系的轴功计入流体；Python 模块可声明 `heat_w`；闭合回路无补水时取边界温度为参考并报告等效热量；全网能量残差校核 |
| 双侧换热器 | 两侧独立水力支路；ε–NTU 计算换热量与两侧出口温度（标称逆流，单侧反向时按顺流） |
| 物性耦合 | 默认 `reference`：水力用参考常数物性，结果与接入热力层前一致；可选 `node`：节点平均密度/黏度回到水力外迭代 |
| 动态选项 | 没有状态设备时每帧求解水力与热力并热启动，收敛后调用 Python commit_step；含水箱或管道热容时按隐式 Euler 推进（见下两行）；没有水锤 |
| 时间误差控制 | 理想热模型与冷库 B 可开启 Euler 误差接受控制（`SolverOptions.time_step`，默认关闭）：每步算整步与两个半步，按质量/能量/温度单位归一化局部误差，`error_norm ≤ 1` 才接受；内部步长在输出、控制采样、日程与启停边界截断；最小步长仍不满足时停止并保留已接受历史；帧指标和报告给出内部步长、拒绝/边界截断次数与 **局部** 误差范数，不称全局误差 |
| 开式水箱 | 液位、存水质量与水温为状态，和网络方程同步求解；一阶隐式 Euler，子步失败减半重试；排空或满箱时定位事件时刻并停止，保留已算历史；稳态把水箱当作液位不变的大容器 |
| 管道热容 | 管道 `thermal_cells` 分段（0–50，0 为无热惯性）加 `wall_heat_capacity_j_k` 管壁热容，各段完全混合；进水温度变化在管内延迟和平滑，停流管段按环境冷却；输出管内平均温度与储热功率 |
| 运行会话 | 动态项目在后端作为一个可控会话运行：可选“按真实时间”（含速度倍率）或“快速计算”；暂停/继续/停止在当前帧结束后生效；前端增量拉取新帧 |
| 持续运行 | 项目设置 → 运行设置勾选“持续运行”，不设时长，直到停止；后端保留最近 2001 帧和一条全程抽稀曲线，内存有上限；曲线页“时间范围”可切换最近窗口或全程；同步接口仍限 2001 帧 |
| 单步 | 在同一会话内推进一帧，Python 模块与水箱、管段、PID 状态连续，不重新初始化 |
| 运行中改参数 | 阀门开度、泵转速比、水箱加热功率及声明 `runtime` 的 Python 参数可在运行中“预览并应用”，下一子步生效，事件记录生效时刻；其他参数需停止后修改 |

### 时间误差控制（A0–A4）

`SolverOptions.time_step` 是显式开关和误差尺度（质量 kg、能量 J、温度 K 各自 atol，外加 rtol、最小/最大内部步长、safety、增长/收缩倍率），默认 `enabled=False`，旧项目与旧默认行为不变。首轮只接入理想热模型（执行域 `thermal`）与冷库 B 集总制冷站（`refrigeration`）；其他执行域开启时报 `TIMESTEP_DOMAIN_UNSUPPORTED`，不会静默忽略。算法、事务约定、默认值和 `RunFrame.metrics` 稳定键见 [算法设计与实现边界](docs/ALGORITHM.md)；实测精度/成本与四场景验收见 [A1](docs/numerics/results/A1.md)–[A4](docs/numerics/results/A4.md)。冷库报告新增“时间误差控制设置 / 内部步拒绝 / 边界截断 / 局部时间离散误差范数最大值”行；该范数只是 step-doubling 的局部估计，不是全程误差或模型准确度保证。


PID 示例：打开「控制」页，点击“液位示例”或“温控示例”生成项目，运行后在曲线中观察 `T1.state.level_m` / `T1.state.temperature_k` 与 `controller.*.output`。液位示例约 600 s 收敛到 1.5 m。

前端默认总览曲线仍绑定示例变量 `P1`、`V1`、`V2`。自定义实例与换热器第二侧可在“全部变量”中加入观察；未绑定的总览变量显示为空。

本轮专项测试 `test_controls_storage.py` 覆盖采样/失败重试、PID 设定值、整批写入校验、Worker 超时、工作区修订冲突、事务失败、归档恢复/保留和停服备份迁移；`browser-workspace.mjs` 覆盖真实控制预览、跨标签页冲突、保存重试、强制重启后在全新浏览器恢复项目及自定义曲线、旧脚本保留。冷库 A1 专项 `test_refrigeration_a1.py` 覆盖解析解对照与步长收敛、能量账本、契约拒绝、PID 控温方向、运行参数原子写入、失败回滚、保存/重启复算和 24 h 有界历史；冷库 A 专项 `test_refrigeration_cold_store.py` 覆盖循环对独立参考、库房/货物守恒、耦合关系、独立能量账本、步长敏感性、越界停止、最小开停机、温控方向、日程与融霜、重试不重复计数和报告/对照/重启复算；`browser-cold-storage.mjs` 覆盖项目页创建案例、选工况运行、单步中改参数并继续、编辑日程后重算、导出报告/CSV、策略对照、机组工作点、保存后服务重启读取与同帧复算；`scripts/verify_cold_storage.py` 在全新工作区跑完七组工况并输出案例包。时间误差控制专项 `test_timestep.py` 覆盖 A0 配置校验（单位、非正容差、最小/最大步长、不支持执行域）与理想热模型解析解、容差收敛和拒绝试算不入账本；`test_timestep_station.py` 覆盖固定步长路径对 v0.5.0 逐变量/逐计数一致、从任意 accepted vector 的无提交试算与缓存恢复、最小步停止、四场景对固定 1 s 参考、单步与 API 运行、报告措辞和接受步序列可复现。
