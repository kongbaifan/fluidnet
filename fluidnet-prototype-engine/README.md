# FluidNet Prototype Engine

基于现有 FluidNet Studio 交互原型建立的独立项目。前端继承画布、模块库、型号、设备属性、草稿/应用和曲线工作流；后端重新定义模块合同、网络编译、水力算法和 HTTP 接口，并提供基于 Pydantic 的契约层、CoolProp 单相物性服务、版本化 Python 模块包和独立 Worker 生命周期。

本目录独立于原来的 `fluidnet/` 与 `web/`。原型来源为 `../output/visualizations/fluidnet-studio-prototype.html`。前端原型现拆分为 `frontend/index.html`(HTML/CSS 外壳与挂载点)与 `frontend/studio.js`(原内联 JavaScript),新增 `frontend/engine-client.js` 负责真实计算接口;新增 `frontend/project-services.js` 管理控制与工作区接口；`index.html` 按服务层、适配器、界面的顺序加载脚本,服务把 `frontend/` 目录以 `StaticFiles(html=True)` 挂载到 `/`,默认入口页即 `frontend/index.html`。

## 启动

Python 3.11 或更高版本，在本目录执行：

```powershell
.\start.ps1
```

脚本首次创建本目录下的 `.venv` 并安装依赖，随后打开浏览器。默认地址 `http://127.0.0.1:8798`，交互接口文档在 `/docs`。也可以手动运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m fn_engine serve --port 8798 --open
```

使用现有环境时可执行 `python -m pip install -r requirements.txt`，再执行 `python -m fn_engine serve --port 8798 --open`。本版本以源码/可编辑安装运行，不提供可独立分发的前端 wheel 包。

## 对外开放与访问令牌

运行项目和模块验证台会在 Worker 子进程中执行用户的 Python 代码。子进程不是操作系统级沙箱，所以服务默认只监听 127.0.0.1，本机访问不需要令牌。要让其他机器（三维界面、数字孪生、PLC 网关）调用，先创建令牌再开放监听：

```powershell
python -m fn_engine token create 三维看板 --scope read      # 只读：GET 接口与推送
python -m fn_engine token create 控制网关 --scope control   # 另可启动运行、发命令、写变量
python -m fn_engine serve --host 0.0.0.0 --port 8798 --cors-origin http://twin.local
```

- `--auth auto`（默认）：监听本机以外的地址时必须带令牌；没有令牌时拒绝启动。`--auth off` 在这种情况下也会被拒绝。服务放在反向代理后面（自己只监听 127.0.0.1）时请用 `--auth required`。
- 令牌只显示一次；`.runtime/tokens.json`（或 `FLUIDNET_TOKEN_FILE`）只保存 SHA-256 哈希。`token list` 查看、`token revoke <id>` 立即撤销。
- 请求头 `Authorization: Bearer <令牌>`；浏览器 WebSocket 不能设请求头时，用子协议 `fluidnet.bearer.<令牌>`。前端页面会弹窗要求输入令牌，只保存在当前标签页。
- 没有内置 HTTPS：跨网络使用时请放在 TLS 反向代理后面，否则令牌以明文传输。

## 已接通的工作流

1. 打开“泵阀并联管网”，点击“检查连接”。请求后端完成端口、参数、内部通路和压力参考校验。
2. 点击“运行”或“单步”。原型项目经归一化转换成新合同，后端返回真实水力与热力结果。
3. 修改 V1 的开度，点击“预览并应用”，再单步。草稿值不进入计算，已应用值进入下一次求解。
4. 画布、设备变量表和曲线读取同一运行帧。端口的温度、比焓、密度和干度来自热力层；设备“全部变量”另有黏度、比热和通路吸热量。
5. 点击“保存原型”将全部项目与编辑草稿事务写入本地 SQLite，服务端确认后显示已保存；跨标签页修改会检测修订冲突。服务重启后可恢复项目，并在“运行记录 → 服务端档案”查看历史与曲线。

初始算例的 A 路质量流量约为 **3.582677 kg/s**。A 路开度从 80% 改为 40% 后，A 路约为 **2.346313 kg/s**。这是内置参数下的回归算例，示例泵曲线不是厂家标定数据。默认 `property_coupling='reference'` 下热力层不改变水力结果，这两个值与接入热力层之前完全一致。

“双侧换热机组”示例（UA = 2000 W/K）中，热侧 65.002 → 62.741 °C，冷侧 25.002 → 27.307 °C，换热量约 75.4 kW。

## Python 项目控制与可靠保存

在“控制”页编辑 `initialize(ctx)`、`step(ctx, dt_s)`、`finalize(ctx)`，声明输入/输出后点击“预览一个周期”。预览使用独立 Worker 真实执行，并返回拟写入值；启用脚本后新建动态运行，输出才会进入后续子步。内置示例将 V1 开度设为 0.65（65%）。旧 Lua 文本原样保留，手动迁移或载入 Python 示例后才能启用。

`ctx.read(key)` / `ctx.write(key,value)` 使用引擎单位（Pa、K、kg/s、开度 0–1），`ctx.state` 为受管理的 JSON 状态。脚本按仿真时间采样；失败子步重试复用提案，接受后提交状态。每个参数只允许一个控制者；脚本可以调整 PID 设定值，不能覆盖 PID 已绑定的设备参数。语法、异常、超时或非法写入会停止运行并保留已接受历史。

`serve` 默认启用 SQLite 工作区：本目录 `.runtime/workspace/`；可用 `--data-dir <目录>` 或 `FLUIDNET_DATA_DIR` 指定。兼容仅配置 `FLUIDNET_MODULE_STORE` 的启动方式时，工作区默认在其 `.workspace/` 子目录。一个目录同时只允许一个服务进程。

保存涵盖画布、草稿、型号、库值、曲线绑定、脚本文本和项目固定模块快照；最近 5 个工作区修订保存在数据库。浏览器继续保留草稿备份；保存失败显示原因并保持未保存状态。陈旧页面返回 409，先导出当前草稿，再点击“载入服务器”。载入前另外备份到浏览器键 `fluidnet-prototype-engine-v1-before-workspace`。

运行归档保留最近 20 次结束运行、最近 `history_window` 帧和约 2000 点的全程抽稀曲线；请求、脚本哈希、最新变量、事件及诊断一起保存，每次发布帧完成事务后更新最后落盘时间。重启时未结束的运行标为 `interrupted`，未确认命令标为拒绝；查看历史后需要新建运行继续计算。运行档案支持查看、导出和删除。

顶部“备份与恢复”支持在线下载完整 ZIP、校验并恢复到新目录、查看容量和恢复最近 5 个工作区修订。备份包含已保存项目、运行归档和模块版本；未保存草稿先保存或导出。恢复旧修订会生成新修订并保留运行档案。命令行也提供停服备份与恢复，详见 [备份与恢复说明](docs/WORKSPACE_BACKUP.md)。跨重启继续原仿真仍未实现。

项目页“管理”可单独保存、重命名、导入导出和恢复最近 5 个项目修订；“服务器项目”可载入已保存项目。每个项目独立检测修订冲突，保存或恢复一个项目会保留服务器上的其他项目。旧版数据库首次打开时自动迁移到版本 2，原有工作区和运行档案保留。

工作台可新建、复制、编辑和选择工况，覆盖值使用参数面板的显示单位；运行快照记录所选工况和已保存项目修订。“模块版本”提供 Python 模块变更预览，兼容升级先保存旧修订，再统一更新全部实例；不兼容变更明确拒绝。曲线页可对照同一项目的两次已完成运行。使用方法、验证入口和交付范围见 [建模工作流验收说明](docs/MODELING_TRIAL_VALIDATION.md)。

## 可编程模块验收入口

1. 打开「模块」，找到服务器清单加载的「可编程阀门 · Python · v1」。
2. 点击「独立验证」并运行：验证台显示实际流量、evaluate 变量/密度、网络关系、commit_step 状态和源码哈希。
3. 点击模块卡片的「管网算例」：创建「压力源 → 管道 → 可编程阀门 → 出口」，点击运行完成 1 秒、10 个成功时间步。
4. 在设备「全部变量」中查看累计通过质量和提交次数，并加入曲线。也可从模块库拖入新的实例，编辑参数后预览并应用。
5. Python 源码编辑形成浏览器草稿；独立验证执行草稿。项目执行插入时绑定的已保存版本，后续编辑和发布不会改变已有项目。

## 模块开发与版本保存

1. 在「模块库 → 新建模块」选择 Python 模板，填写唯一标识和名称。
2. 在「代码」编辑 `module.py` 的四阶段方法。在「变量属性」新增/编辑数值参数和输出，在「绘制模块 / 通路设置」编辑端口及内部连接。
3. 「契约与版本」可以编辑完整 JSON，包括其他参数类型和单位换算。点击「校验并应用契约」完成 Pydantic、Python 语法、Worker 入口检查，并更新参数面板。
4. 「独立验证」配置边界并试算；回到编辑器填写版本备注，点击「保存新版本」。后端重新校验、用参数默认值试算并验证声明的输出后，才写入不可变版本。
5. 版本按模块 ID 从 v1 递增；内置示例 v1 的下一版本为 v2。「刷新版本」查看备注、哈希和验证状态，「载入为草稿」可以基于历史版本继续开发。
6. 拖入项目或创建管网算例时保存完整版本快照和引用。同一项目中同一模块 ID 使用同一版本；发布后新项目可以使用新版，已有项目继续使用原版。暂未提供项目内的版本升级/迁移操作。

模块版本默认保存在本项目 `.runtime/module-packages/module-<id>/v<N>/`，包含 `manifest.json`、`module.py`、`release.json`（备注、时间、试算条件与结果）。可用 `--module-dir` 或环境变量 `FLUIDNET_MODULE_STORE` 指定持久目录；从备份恢复的工作区默认使用其 `module-packages/`。服务重启不会丢失这些文件；该目录属于本地用户数据，Git 忽略它，完整 ZIP 备份会包含这些版本。`modules/` 中的示例包不被修改。「保存原型」保存整个工作区及编辑草稿到服务端，与模块「保存新版本」分开。

保存前试算会为每条启用通路各接一组独立压力边界，多通路模块（如两侧独立的换热结构）在同一个网络中一次求解；通路共用端口、端口未绑定通路或非流体端口会被拒绝，并在诊断中说明。数值、布尔、文本和曲线参数都可以在设备面板和验证台按类型编辑；数值参数显示单位换算，曲线参数使用 JSON 点对数组。设备面板的草稿仍通过“预览并应用”生效。

默认 `reference` 模式下水力采用定密度、定黏度液态水近似，温度相关物性只在热力层和 `node` 耦合模式中使用；内置模型不计算汽蚀、相变或水锤；Python SDK 可显式传入物性及通路高差。非零节点标高会被参数校验拒绝。换热器原型没有水力内径输入时使用目录默认 40 mm；建议通过规范合同指定参数。

PID 示例：打开「控制」页，点击“液位示例”或“温控示例”生成项目，运行后在曲线中观察 `T1.state.level_m` / `T1.state.temperature_k` 与 `controller.*.output`。液位示例约 600 s 收敛到 1.5 m。

前端默认总览曲线仍绑定示例变量 `P1`、`V1`、`V2`。自定义实例与换热器第二侧可在“全部变量”中加入观察；未绑定的总览变量显示为空。
