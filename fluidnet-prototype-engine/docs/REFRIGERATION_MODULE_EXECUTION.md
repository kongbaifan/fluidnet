# RF-2 / RF-3：制冷作者模块运行与验证台

日期：2026-10-30。接续 [RF-1 合同与 SDK](REFRIGERATION_MODULE_CONTRACT.md)。**RF-2 / RF-3 已完成实现与定向验收**；RF-4 项目版本、报告与批量闭环现已完成，见[后续交付](REFRIGERATION_PROJECT_ACCEPTANCE.md)；PF-2 [全阶段验收](PLATFORM_EXTENSION_ACCEPTANCE.md)已通过。

## 已接通的入口

纯集总制冷站可通过正常 `StationSession` 和 `/api/v1/runs` 执行 schema 4 作者节流设备。编译器按 `refrigeration.isenthalpic_throttle.v1` 角色解析，不按模块名称或 ID 分支。作者算法在独立 Worker 中返回流量，平台将等焓流股加入原有容器质量与内能方程。

`/modules/test`、`/modules/test-suite` 和 `/modules/versions` 已接入制冷边界验证。模块库增加“制冷等焓节流阀”模板和 [isenthalpic_throttle](../modules/isenthalpic_throttle/README.md) 公共 SDK 包，可创建自定义标识、编辑源码、运行工况及发布不可变版本。普通流体的四类模板继续使用原验证流程。

纯制冷站仍只有动态积分；固定候选工作点求值不表示稳态收敛。A1 热节点、A 版冷库、流体/湿空气、热耦合及普通组合中的制冷作者设备仍在编译时拒绝。本次没有开放压缩机、换热器或带独立物理储量的 Python 制冷设备。

## 求值与接受

1. 输出、控制采样或日程边界之间形成一个接受段，冻结已接受状态和执行身份。
2. 每次牛顿迭代、差分探测或重试，都用同一候选物理状态的饱和液体压力、焓和密度调用 Worker。传入时间为当前试算终点；已接受时间和模块状态修订保持不变。
3. 固定步失败缩步；自适应步分别试算整步与两个半步，只有通过误差判据的两个半步进入候选积分账。作者 `evaluate` 的状态写入不提升。
4. 全段成功后调用一次 `commit_step`，收集所有作者模块候选，校验身份、版本、双哈希、状态、观察变量和结果帧。
5. 父进程在无 RPC 和用户回调的接受点，统一提升模块、容器、控制、事件、参数修订和时间。随后同步 Worker。

`state.transferred_mass_kg` 由平台按真正接受的隐式子步流量积分；自适应时累计两个被接受半步。它不是末端流量乘整个输出段时长，作者不得覆盖。作者自己的 `state.accepted_segments` 每段增加一次，不随牛顿迭代、差分或重试增加。

观察和发布读取缓存的同一设备结果，不为历史、报告或连续 `snapshot()` 再执行源码。模块只可返回已声明的派生观察字段；流量、端口、参数和平台累计量不能被 `ctx.var` 冒充。

求值异常、非法返回、Worker 超时/退出或准备失败时，回滚当前段的物理状态、控制、日程和累计账，关闭 Worker；已完成的较早段保留，即使它尚未到达原输出网格。接受后同步失败保留新状态及新帧，明确报 `MODULE_SYNC_FAILED` 并停止。关闭的会话不能再次推进；不提供跨服务重启续算或任意 Python 外部副作用回滚。

## 作者操作

1. 在“模块 → 新建模块”选择“制冷等焓节流阀”，填写自己的模块标识。源码仅使用 `fn_sdk` 和标准库；可在契约页检查角色、端口、参数和输出。
2. 默认制冷剂为 Ammonia，入口 1,350,000 Pa、出口 110,000 Pa；压力均为绝压。入口固定为该压力的饱和液体，温度由物性确定。验证台不显示独立温度输入，也不积分容器存量。
3. 在“配置工况与预期值”编辑压力、制冷剂、时长、步长和参数覆盖。选择 CO2 等其他工质时同时设置合法的压力点，例如 CO2 的入口 3,500,000 Pa、出口 2,500,000 Pa。默认工况包括正向、反向、零压差和全关断。
4. 用规范变量填写预期值，例如 `D1.in0.pressure_pa = 1350000`，或零开度时 `D1.mass_flow_kg_s = 0`。界面显示实际值、绝对误差、允许误差及失败原因；失败工况不阻断后续工况。源码异常可跳转实际错误行。
5. 保存版本会重新执行独立制冷验证，核对全部声明输出，记录实际边界及源码/定义哈希；运行失败不会生成新版本。“独立验证”页面可修改开度和特性、查看流量、流股、提交次数及曲线。测试配置和作者预期值随工作区保存。

新设备插入实际站内项目须连接合法的饱和容器液相出口及下游压力等级。该角色没有单相水力通路，因此模块卡片不生成通用水网算例；完整站内替换、升级/回退、导入/导出、报告与批量使用冻结版本的端到端验收属于 RF-4。

## 数值参考

额定 Kv 单位为 m³/h，开度 `a` 范围为 0–1，等百分比可调比 `R > 1`。作者模板使用：

```text
linear:           f(a) = a
equal_percentage: f(a) = (R^a − 1) / (R − 1)
Kv_effective = Kv_rated × f(a)
m = Kv_effective / 3600 × sqrt(1000 × rho_liquid × max(p_in − p_out, 0) / 100000)
h_out = h_in
```

此处等百分比曲线归一化到零开度严格关闭、全开度为额定 Kv。默认可调比 50；不模拟泄漏、壅塞、管内两相压降或过热度自调。相同默认边界和 50% 开度，线性流量为 0.2249392764 kg/s，等百分比为 0.0557396572 kg/s。

独立检查覆盖 Ammonia/CO2 两组合法压力、零/中间/全开度、两种特性、无正压差、等焓关系、累计质量、末尾不足一步以及浮点时长不重复接受；参考公式在测试中独立计算，不调用作者函数生成参考。

正式协议复用 [RF-0 冻结预算](platform-extension/rf0-performance-budget.json)，B 案例保持五个 PID、上层脚本、60 s 仿真和 10 s 输出，仅替换 EV1。内置/Python 各五个独立进程交替运行，候选求值预热两次、测七次，数值线程固定为 1。测量期间没有并行测试任务。
