# 模块开发与运行合同

SDK API 当前为 0.5.0。引擎保留 schema 1/2 的冻结解析和规范化；schema 3 增加适用范围、依赖声明、纯函数标记和组合定义。SDK、模块整数版本、合同版本独立编号。

## 作者流程

在模块库选择两端口阻力、泵／风机、双侧换热或受管理状态模板。向导生成契约和源码；参数、端口、通路及输出可继续编辑。参数默认值以引擎单位保存，界面显示值按 `canonical = (display − display_offset) × display_scale` 换算。因此百分比的倍率为 0.01；摄氏温度的偏移为 −273.15。

代码编辑后校验契约和同步生命周期入口，再运行测试组合。各项独立显示失败；取消和失败保留草稿。源码定位按钮选择实际错误行；错误重放导出包含源码、双哈希、参数、状态、工质、端口和执行上下文。

保存版本时服务重新执行独立网络试算并检查声明输出，不复用过期页面结果。整数版本递增，旧版本文件不覆盖。项目插入绑定精确版本与双哈希，导出和重载保留绑定。发布凭据和追加证据独立于定义哈希；旧包缺证据显示未登记，外部数据缺失显示待数据。

## 执行阶段

| 回调 | 输入 | 输出与状态 |
| --- | --- | --- |
| initialize | 初始参数、工质、JSON 状态 | 初始化受管理状态 |
| evaluate | 试算压力、物性、时间及已接受状态副本 | 注册水力关系；状态副本不提升 |
| thermal（thermal.v1） | 当前水力解、当前热迭代焓温 | `ctx.heat(channel, heat_w)`，每条启用通路一次 |
| observe（observe.v1） | 最终复核结果，包括 t=0 | 派生变量；不能修改关系、热流或状态 |
| jacobian（hydraulic.derivatives.v1） | 当前试算压力与流量 | 完整压降对流量及端口压力的导数；非光滑点声明 smooth=False |
| commit_step | 同一复核结果、实际 dt_s、已接受状态副本 | 返回候选状态与变量，由父进程统一接受 |
| finalize | 最后同步状态与协调者接受水位 | 清理；强制退出时可能不执行 |

压力单位为绝压 Pa，质量流量为 kg/s，热流为 W，正热流加入通路流体。热阶段把质量容差以下的流量视为零；零流量不得持续供热。停流储热使用引擎状态设备。声明新热回调的模块不能同时从水力关系返回非零 heat_w。

新热回调始终参与热迭代启用判断。候选温度收敛后，重算最终热流并复核固定点缺陷；热流采用 1e-6 W 绝对容差和 1e-6 相对容差，温度沿用项目 thermal_tolerance_k。失败继续迭代至上限或拒绝结果。node 模式继续独立物性外循环。观察及累计量读取同一最终结果，累计回调直接使用 `ctx.channel(...).heat_w`。

风机盘管、冷却塔和毛细管各有显式 SDK 新版本，旧目录和旧源码保留。前两者保持干空气显热假设；毛细管保持单相管道模型。它们使用实际通路流量，移除压差反解的重复代码。双侧模板使用各侧入口 cp、温度和流量，检查正负热流守恒。

## 全步接受和故障

父进程保存权威模块状态与修订。收集全部模块候选，校验状态、双哈希、基础修订、请求/子步身份、输出冲突和完整候选帧，再在无 RPC、无用户回调的接受点提升模块、PID、脚本调度、参数修订、物理状态、结果和时间。

接受前失败丢弃候选，并恢复 PID、脚本 pending/时钟/采样和候选参数。已经得到回执的边界参数命令属于事务基础，后续失败保留它。试算后参数修订改变时拒绝旧试算结果。重复候选和同步不会再次累计；过期候选和同身份不同输入拒绝。

接受后同步失败属于已接受子步后的执行故障：父进程保留新状态、时间和内部接受帧，停止执行，不重做累计回调。它不等同于数据库分布式事务或跨服务重启恢复。

JSON 状态上限为 64 KiB、32 层、16384 个值；只接受字符串键、JSON 容器与有限数值。计算及候选结果上限为 2 MiB。日志最多 128 条唯一诊断，每条消息最多 2000 字符；重复项记录次数与首次/最近时刻，溢出显式提示，错误不会静默丢弃。缓存最多 64 项，每项不超过 16 KiB。

恢复合同仅涵盖 ctx.state 与引擎受管理的控制/物理状态。self、全局、随机外部状态和 IO 副作用不能靠复制字典恢复。故障 Worker 关闭，不自动恢复任意用户程序；跨重启续算、OS 沙箱和通用两相模型属于其他专项。

## 性能和依赖

缺声明或 conservative 模式依赖全部端口；tracked 模式跟踪公开端口读取，越声明读取拒绝，保留保守默认。声明不是对任意 Python 全部分支的形式证明。

module_mixed_jacobian 与 module_cache 默认关闭。混合矩阵使用内置解析行与模块完整残差差分行；模块列按完整端口依赖或受检查的声明分组扰动，稀疏求解不创建完整稠密矩阵。可选声明导数仍与同工况差分验证，不符、非光滑或无声明时保留差分。

缓存仅用于明确的 pure_evaluate，不对浮点分桶。Worker 的精确键包含输入、时间、状态修订、参数、工质及双哈希；读取请求身份的回调不缓存。父进程只保存 Worker 已返回 `cache_hit=true` 的结果，后续相同请求可直接复用而省去 RPC；每次返回独立深拷贝，仍检查 Worker 存活。父进程缓存绑定初始化时的模块版本/双哈希及工质，重新初始化或更新参数时清空；时间、完整端口数据、运行/实例和接受状态修订改变时失效。每实例最多 64 项，单项输入键和结果各不超过 16 KiB。失败候选不改变接受修订，不会污染缓存。

性能验证可运行 `python scripts/profile_module_system.py --output artifacts/module-system/<新目录> --ablation`，分别记录默认、仅缓存、仅混合求导和两者开启；默认每组冷启动 5 次、热态预热后 7 次。`--hot-only` 只作热态诊断，不作为冷启动验收。`rpc.parent_cache_hits` 和实际请求计数分别报告，不能把父进程命中算作 Worker 调用。实测与边界见 [性能修复记录](results/PERFORMANCE_REPAIR.md)。工程案例开关对照用 `python scripts/engineering_acceptance.py --output artifacts/engineering/<新目录>`，结果见 [工程案例对照](results/ENGINEERING_ACCEPTANCE.md)。

验证目标工程后，可在编译前显式选择优化路径：

```python
project.solver.module_mixed_jacobian = True
project.solver.module_cache = True  # 仅对声明 pure_evaluate 的模块生效
```

hydraulic.signed_start.v1 是新 SDK 被动模块的可选能力：固定边界时按压差选择正、反、零流启动值。旧合同保留原启动路径。主动泵曲线保持自己的工作点和方向限制。

## 迁移和组合

升级预览可提供声明式参数、端口、通路和变量映射、默认值及标准单位转换。项目副本统一迁移连接、参数、草稿、库值、工况、PID、脚本声明和曲线绑定。歧义、重复目标、失效引用和非标准转换拒绝。脚本源码不自动替换字符串；需要作者显式提供新源码。历史运行保持原快照。

组合绑定子模块精确版本和双哈希，内嵌可重载的子定义。确定性递归展开不增加方程、连接或压力参考，保留内部路径、状态、公开变量和诊断源映射。首版深度上限 8、展开实例上限 1000，外端口和公开参数一对一映射；重复写目标与控制者冲突拒绝。画布封装生成新草稿，发布后插入，原设备组保留。多端口共享拓扑继续使用真实项目图；独立验证台保留普通模块每通路独立端口的限制。
