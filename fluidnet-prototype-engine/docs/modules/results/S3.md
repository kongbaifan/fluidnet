## 1. 交付与边界

SDK API 更新为 **0.3.0**，增加只读 `ctx.time_s`、`ctx.phase`、`ctx.execution` 及对应公共类型别名/Protocol。四个生命周期回调签名保持；新能力声明为 `context.execution.v1`，SDK 0.1/0.2 的支持范围不扩大。模块 schema 1/2、定义哈希算法及历史默认值保持。

阶段、仿真时间、会话/实例/请求/子步身份、迭代/dt、数据来源和接受时间的精确语义见[执行上下文](../EXECUTION_CONTEXT.md)。`ModuleExecutionInfo` 为宿主只读模型；请求增加可选 context，旧 JSON 缺省不补该字段。新增两个独立生成协议模型，共 55 份生成合同。

`module_execution.py` 管理宿主身份；solver 的一次求解尝试为所有残差、分片和物性外循环设置同一 step_id，NetworkResult 记住该 ID。采用先前保存的试算结果时，提交恢复其身份。单/批 Worker 传递实际实例 ID，finalize 按实例携带接受时间，未增加 RPC 次数。

SimulationSession 在原有接受点后更新水位时间，台架在帧检查/入历史后更新；没有移动物理求解、状态提交或控制采样顺序。回调的候选提交时间与协调者上一次接受时间分开记录。新 `timed_valve.py` 是未发布的类型示例，演示纯时间相关关系和仅在提交累计状态；正式模块版本发布留到 S4。

## 5. 保持的限制与后续项

`accepted_time_s` 是协调者水位，不是状态快照或提交确认。第二个模块提交失败时，第一个模块状态仍可能已按旧路径推进；专项测试明确验证本地提交时间 0.5、接受时间 0 的差异。S3 没有原子回滚、修订检查、幂等去重或跨重启续算。finalize 仍可能因超时/强制终止而不执行。

API 运行档案 ID 与模块执行会话 ID 不混用；旧直接调用缺少协调者时允许未知子步/接受时间。旧通路缺省零对象不被标成已收敛零流。原始 RPC 错误协议和新结构化诊断仍按后续 D/T 工作包推进。

本轮不修复 S0 记录的反向冷启动/等压数值问题，不改变容差，也不作性能提速承诺。远端 required CI 和全套浏览器清单未运行；下一依赖为 S4 的新 SDK 示例模块正式发布，状态事务按 T0–T4 推进。
