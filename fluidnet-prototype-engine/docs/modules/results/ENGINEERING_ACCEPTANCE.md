# 工程案例优化开关对照（2026-10-25）

基线 `70e5a8b`，代码与模块包未改。对 6 个仓库案例比较四种组合：默认（两开关关）、仅缓存、仅混合求导、两者开启。案例均为仓库参考配置，未经现场标定，不能代替 ROADMAP M4 的现场项目验收。

```powershell
python scripts/engineering_acceptance.py --output artifacts/engineering/<新目录>
python scripts/engineering_acceptance.py --project <项目.json> --duration 60 --dt 1 --output artifacts/engineering/<新目录>
```

每次运行都在新进程中执行（冷启动、独立 Worker、BLAS 单线程），4 种组合交替运行，各重复 3 次。逐帧对照的参考是默认组合的第 1 次运行，容差按变量单位设定（压力 1 Pa，流量 1e-8 kg/s，温度 1e-4 K）。独立校核包括：Kv 阀方程，ε-NTU 风机盘管/换热器，节点质量守恒，能量残差 ≤ 0.01 W，以及逐个已接受子步核对水箱和模块的质量/能量台账。案例定义见 `scripts/engineering_cases.py`，校核方程见 `scripts/engineering_checks.py`。

## 结果

原始记录：`artifacts/engineering/20261025-r1/report.json`。24 组全部通过独立校核，与默认结果一致，关闭后没有残留 Worker。

| 案例 | 默认 run (s) | 仅混合求导 | 两者开启 | 评估 RPC 默认 → 混合 | 帧间最大差 |
| --- | --- | --- | --- | --- | --- |
| 24 支路泵阀配水（稳态） | 1.10 | 0.22（−80%） | 0.28（−75%） | 245 → 38 | 1.2e-10 |
| 96 支路泵阀配水（稳态） | 21.27 | 1.10（−95%） | 1.12（−95%） | 1091 → 46 | 1.2e-10 |
| 8 支路风机盘管动态 20 s | 5.46 | 2.36（−57%） | 2.67（−51%） | 1007 → 161 | 6.7e-8 |
| 水/乙二醇双侧换热 20 s | 0.72 | 0.45（−37%） | 0.39（−46%） | 527 → 131 | 7.5e-8 |
| PID 水箱 + Python 出口阀 30 s | 0.88 | 0.93（+6%） | 1.08（+23%） | 1035 → 1035 | 2.7e-9 |
| NH₃/CO₂ 制冷站 60 s | 0.025 | 不适用 | 不适用 | 0 | 0 |

run 指模型初始化之后的求解时间（3 次中位数），Worker 冷启动在 0.45–2.0 s 之间，各组合相当。峰值进程树内存 157–176 MB，开启混合求导后 96 支路由 174 MB 降到 166 MB。每个案例只启动 1 个模块或控制脚本 Worker。

- 缓存在这 6 个案例中都没有命中（`parent_cache_hits = 0`）：现有模块包都没有声明 `pure_evaluate`，缓存路径不会启用。仅缓存组合的耗时与默认相同，PID 水箱和 24 支路各补跑 7 次，差 0.2%–1.5%，3 次重复时看到的 +44% 属于噪声。性能修复记录中的缓存收益只适用于声明了 `pure_evaluate` 的模块。
- 混合求导的收益随 Python 模块实例数增长。PID 水箱只有 1 个 Python 实例，分组扰动减少不了调用（RPC 前后都是 1035），所以没有收益；+6%/+23% 在本组噪声范围内，未补测。
- 制冷站使用 `refrigeration` 执行域，不走通用水力求解（0 次求解），两个开关对它不起作用。这一行只用于确认开关不改变结果。
- 开关仍默认关闭。混合求导在多模块网络中收益明显，数值差远小于容差，可以考虑改为默认开启，或在新项目中默认开启，由评审决定。
