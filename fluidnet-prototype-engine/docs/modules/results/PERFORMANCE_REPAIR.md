# 类型门禁与模块性能修复（2026-10-25）

基线为 `ab85fb6` 加本次工作区修改。修复全局 mypy 的 37 个错误，以及可选混合 Jacobian 随网络规模增加而产生大量重复 RPC 的问题。项目和 SDK 版本号不变，旧模块契约、数值容差和两个优化开关的默认值不变。

## 类型检查

当前 `mypy.ini` 范围从 37 个错误 / 11 个文件清零。修改包括容器元素类型、列表/元组变量分离、数值边界及热力结果的非空约束、公开 SDK Literal 类型、Pydantic 显式输入校验，以及使用已归一化的源码和已序列化的历史列表。

主 CI 与 `scripts/check_module_system.py` 已将后端 mypy 改为阻塞门禁。`check_untyped_defs=False` 仍保留，因此零错误仅代表当前检查范围；无注解函数体仍需逐步纳入。独立 SDK 严格类型门保持启用。

## 性能实现

- 混合求导按模块残差的稀疏依赖分组扰动；缺少受检查声明时仍保守包含该模块全部端口。每组只提取相应模块方程的导数，内置设备及连续性方程继续使用解析导数。
- 声明导数仍用同一工况的完整残差差分校验，错误或非光滑导数回退；只展开单行进行校验，替换行也以稀疏形式保存，不再展开整个矩阵。
- 父进程缓存只接受 Worker 已确认命中的结果，绑定初始化实例、模块版本/双哈希和工质；参数更新或重新初始化清空缓存，时间、端口值和接受状态修订属于精确键。每次命中返回深拷贝并检查 Worker 存活，故障继续携带模块、实例和阶段诊断。
- 内部 `model_copy(update=...)` 可能绕过 Pydantic 校验。缓存键使用禁止非有限值的 JSON 编码；非法输入绕过父进程缓存，由原 Worker 路径校验，避免 NaN/Infinity 被编码为 `null` 后误命中。
- 每实例最多 64 项；输入键和结果分别限制为 16 KiB。批处理只发送有未命中实例的分片，全部命中时没有 evaluate RPC。
- `rpc_batches` 统计实际非空分片 RPC，`rpc_instances` 统计其中的实例数；`parent_cache_hits` 单独记录父进程命中。`worker_requests` 仍是 Worker 生命周期累计值，跨帧应取差值。

性能采用同一固定关系模块、单线程 BLAS、规模 4/16/40 和单/双分片。每组冷启动用 5 个新进程，热态排除预热后取 7 次中位数。性能测量与测试串行执行；完整原始项目、模块双哈希、残差、请求计数和核心实现源码哈希随结果保存。

```powershell
python scripts/profile_module_system.py --output artifacts/module-system/repair-20261025-full-r2

```

`--ablation` 可分别测默认、仅缓存、仅混合求导、两者开启；`--hot-only` 只作热态诊断。两个优化开关继续默认关闭：本次性能场景是固定关系重复求解，不能代表全部昂贵模块、动态工况或大规模生产网络的收益。
