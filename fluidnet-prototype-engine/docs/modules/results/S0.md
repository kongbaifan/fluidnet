## 1. 交付及接口决策

新增 `backend/fn_sdk/`，SDK API 预览版本 0.1.0，完全由标准库构成。公开 `ModuleContext`、`NetworkBuilder`、物性/端口/通路/关系/诊断/结果类型、JSON/标量别名及四阶段 `DeviceModule` 生命周期。它们是结构化 Protocol，宿主继续提供现有对象；不是新的上下文构造器、Pydantic 模型或 Worker 实现。

签名、单位、阶段可用量及公开/内部清单见 [SDK API](../SDK_API.md)。没有修改生产模型字段、源码加载、Worker 协议、物性初始化或求解器，也没有修改种子模块源码/版本。S1 的 resistance 和公共阻力工具、S2 的合同/版本协商、S3 的时间/阶段身份仍待实施。

新增 `examples/module_sdk/valve.py`，只引用 SDK 和标准库；使用现有阀合同做测试，不作为已发布新模块版本。参数读取需明确检查数值/有限值，状态累计仅放提交回调。`typed_module() -> DeviceModule` 让 mypy 对四个回调签名进行一致性检查。

打包继续沿用现有工程，增加 `py.typed` 的 package-data。整个项目 wheel 保留原引擎依赖；SDK 可独立导入不等于已有单独轻依赖发行包。

## 5. 扩展工况中发现的存量数值现象

首次接入测试曾尝试三个完整网络工况，出现两项失败。已使用**未修改的 programmable_valve v1** 单独复现，源码及定义双哈希与 M0 相同；不是 SDK 引入的新数值行为。原始输入、哈希与结果见 `known-baseline-issues.json`。

| 压力边界 / 默认配置 | 旧版模块实测 | 影响及处理 |
| --- | --- | --- |
| 入口 120000 Pa、出口 250000 Pa | 冷启动 `HydraulicNotConverged`；压力残差 130000 Pa，质量残差 0 | Python 阀反向冷启动的存量问题；需数值专项独立修复，不将其登记为 S0 网络验证通过 |
| 两端均 120000 Pa | 流量 0.0003906324209545599 kg/s，压力残差 0.0012091253606824458 Pa | 原压力容差允许的近零解，不能套用严格零流量等价门；没有把该流量改记为零 |

S0 的完整网络接入只登记正向工况。负/零/正流的提交行为通过直接 Worker 回调单独验证，范围在测试名和本记录中明确区分。后续 S1/数值工作若声称完整反向冷启动或严格零流能力，应重新对这些输入建立独立验收。
