## 1. 交付与决策

新增模块合同 schema 2，可声明精确 SDK API 版本、所需能力及状态合同版本。支持 SDK 0.1.0、0.2.0 与状态合同 1；不支持的声明在源码执行前拒绝。具体字段、默认值、能力支持表和诊断代码见[合同版本与协商](../CONTRACT_VERSIONING.md)。公共 Python SDK 仍为 0.2.0，工程仍为 0.5.0，模块整数版本机制保持。

原模块模型及嵌套端口、单位、参数、通路和变量类型提取为 `_module_schema_v1.py` 的冻结字段布局/解析器，`models.py` 继续导出历史类型名。schema 2 使用独立冻结解析器；当前入口按 schema 分派，不把 SDK 默认字段写入 v1 JSON。生成物增加 `module-v1.schema.json`、`module-v2.schema.json`，现有入口及 OpenAPI/项目请求响应同步更新，共 53 份合同。

`module_contracts.py` 按冻结字段投影与原数字/JSON 规则计算定义哈希；SDK 声明参与 schema 2 定义哈希，不参与源码哈希。旧源码、种子模块整数版本和既有项目 schema 没有改写。能力集合排序，缺省能力与显式空集合一致；不重复声明。未知 SDK/能力/状态合同可严格解析和导出，但不能执行；未知 schema 直接拒绝解析。

兼容检查覆盖项目编译、作者验证、宿主单 Worker、批量全部实例预检、子进程每份定义的运行/验证/设计入口及保存流程。新能力仅声明现有行为，没有实现状态事务、热回调、依赖自动安装或新状态限制。
