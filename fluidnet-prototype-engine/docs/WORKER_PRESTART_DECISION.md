# 当前 Worker 启动与预启动决策

2026-11-07，代码基线 `1a2ffe5`；运行路径仍采用独立 Worker，没有启用生产进程池。原始证据位于 `artifacts/architecture-completion/worker-startup.json` 和 `worker-prestart.json`；后者包含源码哈希、环境、12次独立生命周期、每步数值与状态、采样RSS。

## 当前测量

旧 `profile_worker_startup.py --repeats 3` 重新执行，四种 Worker 和两种整网首步全部零失败。控制、普通模块、批量 Worker 首个成功调用中位数分别0.598 / 0.575 / 0.580 s；需物性模块首个成功步1.603 s，其中首次物性约1.016 s。普通水网新进程compile→solve墙钟2.917 s，含25% Python模块的对应网络3.608 s；进程内compile+solve分别0.061 / 0.739 s。这不是API已启动情况下的用户点击延迟，也不与2026-10-23的旧机器负载直接计算改善百分比。

新实验 `python scripts/profile_worker_prestart.py --repeats 3` 交替比较“按需新建”和“提前发startup_report的新进程”。每次运行都新建并关闭一个进程，不跨运行回收，也不注入已执行用户代码的旧进程。

| 类别 | 按需首个成功步 | 预启动后请求首步 | 预启动+首步总时间 | 首次物性后/普通步采样最大RSS |
| --- | ---: | ---: | ---: | ---: |
| 普通模块 | 0.576 s | 0.017 s | 0.586 s | 约35 MiB |
| 需物性模块 | 1.614 s | 1.040 s | 1.602 s | 约72 MiB |

预启动本身分别消耗约0.569 / 0.566 s。后续evaluate约0.43–0.48 ms。独立初始化状态、三步结果与状态在冷热实验中一致，全部进程退出，无新增子进程残留。RSS是固定时点采样，不宣称操作系统级峰值；每组仅3样本，未测并发吞吐。

## 决策与适用范围

**本轮不启用生产池化。** 证据支持“空闲期间提前启动可以缩短下一次请求等待”，没有证明连续跑批总工作量减少；首次物性成本仍在。跨运行回收已加载用户模块的进程还必须证明用户类/self、全局、原生物性缓存和超时异常隔离，当前实验没有这样的证据。

若产品以后提出明确的点击响应预算，优先选择小容量、内存有界、租用后不归还的预启动进程，另测空闲命中率、取消、后台补充与并发吞吐；不把0.017 s当作无需付出预热成本的加速承诺。当前发布继续按需新建，避免没有端到端收益证明的生命周期复杂度。测量工具和这份决策即本次AC-5交付，Worker生命周期、接受事务和公开合同未修改。
