## 1. 场景清单与检查

| 场景 | 类型 | 参考/守恒检查 |
| --- | --- | --- |
| `valve-open` | 静态 | 流量等于独立 Kv 解析解 `q_m3_h = sqrt(Δp·kv_eff²/(100000·ρ/1000))`；压力/质量残差过门 |
| `valve-closed` | 静态 | 关闭阀流量精确为 0；压力/质量残差过门 |
| `reverse-flow` | 静态 | 反向负流量、幅值与正向对称（管道为被动对称支路）；压力残差过门 |
| `tank-valve-switch` | 动态 | 关阀阶段无进流、开阀阶段进流为正、液位先降后升；水箱质量账本 ΔM = Σ net_inflow·dt |
| `pipe-wall-capacity` | 动态 | 有/无壁面热容 A/B：壁面充电时出水温度滞后且 `stored_power_w`>0；能量残差过门；两跑水箱温度轨迹一致 |
| `pid-level` | 动态 | 液位跟踪设定值 ±0.15 m、PID 实际移动阀门、质量残差过门、液位在物理边界内 |
| `module-state` | 动态 | Python 模块 `commit_count` == 接受步数、`throughput_kg` == Σ|q|·dt（1e-9 相对）、状态变量可读 |
| `cold-store-a` / `cold-store-b` | 计时 | 冷库 A（理想冷源单库房）/ B（集总制冷站）各自单独计时，全部子进程运行成功 |

动态场景都用 `SimulationSession`/`create_session` 逐步 `advance` 推进，参数切换在帧边界
通过 `set_parameter` 执行；`pipe-wall-capacity` 用同一水箱加热阶跃下“壁面热容 0 与 20000 J/K”
两跑对照，滞后来自管道壁面而不是水箱轨迹差异。

## 3. 结果比较器

```powershell
python scripts/compare_numerics_results.py <基线.json> <新结果.json> \
    [--max-regression 0.10] [--timing-floor-s 0.005] [--json-out report.json]
```

发现码（任一出现即退出码 1）：

- `WRONG_RESULT`：场景状态非 passed、基线检查项在新结果中未通过。
- `MISSING_FIELD`：缺场景、缺顶层字段、缺检查项、缺稳定指标、缺计时字段。
- `RESULT_DRIFT`：基线声明的稳定指标（`stable_metrics`，排除计时类）相对漂移超过 1e-6
  （绝对下限 1e-9）。
- `PERF_REGRESSION`：计时中位数回退 >10% 且绝对增量 >5 ms；计数类指标（迭代/调用/启动数等）
  增加 >10%。

先正确性后性能，符合计划 §3.2；性能门带噪声下限，单次抖动不阻塞共享 CI。

比较器自检：`python scripts/compare_numerics_results.py <同一文件> <同一文件>` 输出
`{"ok": true, "findings": 0}`；单元测试覆盖错误结果、缺字段、结果漂移、2 倍变慢、2% 噪声、
计数回退与 CLI 退出码。

## 5. 偏差与限制

- **阀门反向流不收敛（现状限制，如实记录）**：阀门压降为 `q·|q|`，在 q=0 处导数为 0；
  当前 dense 求解从零初值出发时，反向阀门工况会停在零流量并报“水力求解未收敛：压力残差
  130000 Pa”。v0.5.0 快照同样复现。因此 `reverse-flow` 用被动对称管道（层流项在零流量处
  导数非零）做反向流验收，并把该限制留待 V/L 专项评估。未为了让场景通过而修改求解器。
- `dead` 场景未加入：关/开阀用 `tank-valve-switch` 的动态阶段检查覆盖；更复杂的多阀联动
  留给 V 专项。
- 冷库 A 的 `initialize` 中位 1.784 s 明显高于冷库 B，是本环境实测，不做因果断言；W0/W1
  只优化 Worker 首次可用时间，不宣称冷库模型本身提速。
- 本包未改任何求解器/模型默认值；`property_coupling`、步长、容差均用项目默认。
