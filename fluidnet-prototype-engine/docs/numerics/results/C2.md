## 1. 架构说明（与任务描述的偏差，如实登记）

任务建议“内部调用 `solve_hydraulics(约化子网络)`”。实现时确认无法直接这样做：复合链不是一个注册过的
内置支路模型（`hydraulic_derivatives.branch_drop_value` 只支持 valve/pipe/pump_curve/resistance），
把约化网络交给 `solve_hydraulics` 会在第一个链支路上抛“未注册的支路模型”。因此本模块**只接管约化后的
代数系统**：自己组装残差/Jacobian（复合压降解析导数），但严格复用常规求解路径的数值约定：

- 残差缩放：支路行 `/PRESSURE_SCALE`，质量平衡行不缩放；未知压力列 = `p/PRESSURE_SCALE`；
- 冷启动：固定压力均值（未知锚点）+ C1 §2 的流量初值（常规路径为 0.1）；
- warm start 失败回退 cold；`xtol=ftol=gtol=1e-12`、`x_scale='jac'`、`max_nfev=options.max_iterations`；
- dense/sparse 选择复用 `choose_hydraulic_method`（CSR 解析 Jacobian + `lsmr`）；
- 收敛门用**原网络**逐支路压降与原节点质量平衡重新计算（不是约化残差），并检查正压力/有限性/泵曲线范围；
- 泵转速 ≤ 0、未注册模型等错误由同一 `branch_drop_value` 抛出，保持原有错误文本。

因此 `counters` 记录的是**约化求解自身的计数**（不是“子求解汇总”）；`rpc_*` 恒为 0（C 路径不调用模块）。

## 2. 回算内容

| 字段 | 回算方式 |
| --- | --- |
| `pressures` | 锚点：固定压力或约化解；内部节点：沿链逐段 `p_next = p − s·drop(s·q)`；环链不覆盖锚点 |
| `flows` | 链成员：`s_i·q`；单支路：约化流量 |
| `branch_density` / `branch_viscosity` | 原支路数组（无 node 耦合时取参考物性，有耦合时用调用方传入的原支路数组） |
| `solution` | **原网络**布局：`[未定压节点压力/PS, (水箱净流入：本版无), 原支路流量]` |
| `pressure_residual` / `mass_residual` | 用**原网络**重算（逐支路压降、逐节点质量平衡） |
| `storage_rates` | `{}`（storage_step 非空时不压缩） |
| `relations` / `module_variables` / `module_diagnostics` | 空（无 Python 模块） |
| `counters` | `nfev`、`njev`、`residual_calls`、`solver_attempts`、`problem_size`（约化）、`jacobian_nnz`（约化）以及附加键 `series_compression/original_problem_size/reduced_problem_size/compression_chains/compressed_branches/unknowns_saved` |
| 方法字段 | `requested_method`=项目配置，`effective_method`=实际用（dense/sparse），`method_reason` 追加“压缩：N 条链、原 X → 约化 Y 未知量（节省 Z）”，`matrix_size=Y`、`matrix_nnz` 为约化矩阵规模，`jacobian_mode='analytic'` |

## 3. `solution` 布局与 warm start（实测）

`test_solution_layout_is_original_network_and_warm_start_reuses_it`（6 串联）：

- `solution` 长度 = 未压缩布局长度（11）；`solution[:未知压节点数]·PS` 与 `pressures[未知节点]` 逐点
  一致（atol 1e-9 Pa），`solution[未知压节点数:]` 与原支路流量逐点一致（atol 1e-15 kg/s）。
- 把压缩解作为 `initial` 喂回压缩路径：**nfev 4（冷）→ 1（热）**，压力/质量残差与冷启动解相同。
- 把压缩解作为 `initial` 喂给**未压缩**路径：正常收敛且解与未压缩冷启动一致 → 两种布局可互换。
- 把未压缩解作为 `initial` 喂给压缩路径：同样收敛（`_map_initial` 按原布局映射）。

`test_dynamic_frames_match_with_and_without_compression`：`solve_dynamic(..., 0.6 s, dt=0.1 s)`
共 7 帧，压缩/未压缩两路的全部帧变量（原支路流量、节点压力、端口压力/流量）都在 3.1 差值门内，
状态均为 `converged`。动态帧间 warm start 直接使用上一帧 `NetworkResult.hydraulic.solution`，
因此本项同时验证“动态 warm start 不污染”。
