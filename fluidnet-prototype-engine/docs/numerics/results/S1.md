# S1 证据：显式 `auto`、选择记录与一次可诊断回退

- 日期：2026-10-23；基线 v0.5.0 `a986ca3`。
- 测试：`python -m pytest -q tests/test_numerics_auto.py` → **6 passed**（选择器单测 + 集成 + 回退）。
- 交叉引用：阈值实测见 [S0](S0.md) §1；新项目默认与契约见 [S2](S2.md)。

## 1. 选择记录（始终写入结果）

`HydraulicResult` 新增：`requested_method` / `effective_method` / `method_reason` / `matrix_size` / `matrix_nnz`；
`RunFrame.metrics` 增加 `matrix_size` / `matrix_nnz`，`RunFrame.solve_summary` 汇总这五项与 Jacobian 模式。
前端运行事件会显示“求解：自动→稀疏，未知量 N，Jacobian 解析”。

三种典型原因串（实测）：
- `auto：未知量 199 ≥ 64 且稀疏度 0.005 ≤ 0.45`
- `auto：未知量 5 < 64，稠密矩阵的固定开销更小`
- `auto：稀疏度 1.000 > 0.45（多端口模块依赖密集，稀疏分组扰动接近稠密）`

## 2. 显式请求不被覆盖

- `hydraulic_method='dense'` / `'sparse'` 时 `choose_hydraulic_method` 直接返回原值，原因串为“显式请求 …”；
  单测覆盖 `dense` + 大尺寸、`dense` + 小尺寸、`sparse` + 小尺寸三种组合。
- `auto` 与显式 `sparse` 在同一大网络（100 阀串联，size 199）上 `pressures`/`flows` 一致（rel/abs 1e-9）。

## 3. 一次可诊断回退

构造：monkeypatch `least_squares`，让 `tr_solver='lsmr'`（稀疏）的调用返回 `success=False`；
`auto` 先选 sparse 失败后：

| 观测 | 实测 |
| --- | --- |
| 尝试次数 | sparse 1 次 + dense 1 次 = 2 |
| `effective_method` | `dense` |
| `method_reason` | 含“稀疏求解未收敛，已回退 dense（容差未放宽）” |
| `counters['method_fallback']` | `dense` |
| 最终残差 | 仍过 `pressure_tolerance_pa` / `mass_tolerance_kg_s` 同一道门 |

不放宽容差、不做无限重试、回退后可诊断。

## 4. 未覆盖

- `auto` 在动态水箱步下的回退计数未单独统计（动态用例走 dense，`counters` 在 B0 口径下可查）。
- 大规模 auto 收益由 B3 报告给出（见 `B3.md`）。
