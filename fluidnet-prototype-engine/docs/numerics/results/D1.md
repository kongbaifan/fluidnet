## 1. 求解流程（`solve_hydraulics_hook`）

1. `resolve_plan(network)`：按结构签名取缓存计划；`degraded` 或可求解块 ≤ 1 → 返回 `None`
   （常规全网路径，不递归）。`runners is None` 时也返回 `None`，不接管 Worker 创建。
2. 逐块构造 `CompiledNetwork` 子视图（`dataclasses.replace`，不复制 Worker）：
   - `branches`：块内**未关闭**支路，起止节点改成本地索引；
   - `node_keys` / `fixed_pressures` / `fixed_temperatures` / `port_nodes` / `storage`：同一本地映射；
   - 关闭支路不进入子网络，合并时按定义写 `0.0`；
   - 单工质项目 `mixed=False`；多工质项目按该块回路取 `circuit_fluids=[该回路工质]`、`mixed=True`，
     避免跨工质混算；
   - `hooks` 收窄为 `hooks - {'blocks'}`（默认 `{'compression'}`）；若 `fn_engine.hydraulic_plan`
     暂不存在，用 `try/except ImportError` 与导入探测回退到 `frozenset()`，并在 `method_reason` 记录回退。
3. 子求解：`solve_hydraulics(子网络, runners=块内 Python 实例子集, hooks=子钩子, ...)`；
   传入的 `branch_density/branch_viscosity/port_base/initial/storage_step` 全部按块切片。
4. 合并回原索引：压力、支路流量、水箱净流入、`module_variables`、`relations`、残差；
   `solution` 按**原网络**未知量排布重建：
   `[未知节点压力/1e5（升序）, 水箱净流入（升序）, 各支路流量]`。
5. 所有块成功后返回 `HydraulicResult`；任一块失败抛异常（见 §4），不返回部分结果。

### 与 A0/事务的集成边界

- `_local_network` 用 `dataclasses.replace(CompiledNetwork, ...)` 构造：`execution_domain` 不是
  `CompiledNetwork` 的字段，不会被带入子网络（子网络上 `getattr(network, 'execution_domain', None)`
  为 `None`）；`timestep.ensure_supported` 只在 `simulation.run_dynamic` 入口对**原网络**调用
  （`simulation.py:36`），不会检查子网络，因此 A0 的 domain 拒绝逻辑不受分块影响。
- 同理，子网络不携带 `trapped` 等非字段状态；Lead 侧已把 `SimulationSession` 改为
  `getattr(self.network, 'trapped', {})`，子网络缺该属性也不会失败（本包未修改 `simulation.py`）。
- 分块只改变 `_solve_hydraulics` 内部的求解路径；`ensure_supported`、子步接受/提交、PID/日程
  仍在原网络与原事务链上执行。

## 2. 正确性：3.1 差值门实测

门限：流量 `1e-8 + 1e-6×|q_ref|`，压力 `1 Pa + 1e-8×|p_ref|`。实测是
`solve_hydraulics(network)` 与 `solve_hydraulics(network, hooks=frozenset({'blocks'}))` 的最大绝对差：

| 场景 | 压力差 (Pa) | 流量差 (kg/s) | `solution` 差 | 块最大残差 (Pa, kg/s) |
| --- | --- | --- | --- | --- |
| 两个独立水网（2 块） | 0.000e+00 | 5.418e-14 | 5.418e-14 | (5.38e-10, 0) |
| 独立管道 + 独立泵阀（2 块） | 5.821e-11 | 1.155e-14 | 1.155e-14 | (5.38e-10, 0) |
| 换热器双回路（2 块 + 热力边） | 0.000e+00 | 4.441e-16 | 4.441e-16 | (9.09e-13, 0) |
| 4 端口 Python 实例 + 管线（2 块） | 0.000e+00 | 1.066e-14 | 1.066e-14 | (8.88e-10, 0)；`module_variables` 逐项相等 |
| 12 条独立链（12 块） | ≤ 门限 | ≤ 门限 | ≤ 门限 | 见测试 |
| 关闭阀支路（4 块/2 可解） | ≤ 门限 | ≤ 门限 | ≤ 门限 | 关闭支路 `q=0.0` |
| 分块 + C 串联压缩（2 块） | 0.000e+00 | ≤ 5.42e-14 | — | C 钩子返回后仍过门 |

结论：所有实测差值远小于 3.1 门限；关闭支路的「精确 0 vs 常规数值零」差异也在门内。

## 3. 调用计数：块之间互不重复迭代

`SolverOptions.hydraulic_diagnostics=True` 时的实测（tests/test_hydraulic_blocks.py::test_easy_block_iteration_count_unchanged_by_other_block）：

| 量 | 独立管道块单独求解 | 独立泵阀块单独求解 | 两块分块求解 | 常规全网求解 |
| --- | --- | --- | --- | --- |
| `residual_calls` | 13 | 7 | 13 + 7 = 20 | 11 |
| `solver_attempts` | 1 | 1 | 2 | 1 |
| `problem_size` | — | — | 1 + 3 = 4 | 4 |

- 每个块的 `residual_calls` **精确等于它单独求解时的计数**：另一个块的存在、难度、
  迭代次数都不会让本块重新迭代。
- `solver_attempts == 块数`（冷启动每块一次 `least_squares` 尝试），没有隐藏重试。
- `residual_calls` 是各块之和；常规全网路径一次残差调用覆盖所有方程，所以「块数 × 每块调用」
  在极小模型上会比全网总调用多（见 §5 性能结论）。
- 每块明细写入 `counters['blocks']`（`block`/`nodes`/`branches`/`size`/`nfev`/`residual_calls`/
  `wall_s`/`pressure_residual`/`mass_residual`）；`counters['blocks_wall_s']` 是分块求解总墙钟。

## 4. 失败定位

块内失败不再吞掉，而是抛出带块号与原设备的异常，且保留原语义：

- 收敛失败 → `HydraulicBlockFailure(HydraulicNotConverged)`，`code='HYDRAULIC_NOT_CONVERGED'`，
  `_retryable(...) == True`（仍可按既有缩步语义重试）。实测消息：

  ```text
  水力分块 1/2 求解未收敛（V1）：合成的不收敛块
  ```

- 非收敛类失败（泵曲线越界、模块运行错误等）→ `BlockSolveError(ValueError)`，`code` 沿用原异常
  （无则 `BLOCK_SOLVE_FAILED`），`_retryable(...) == False`（终止语义不变）。实测（下游 600 kPa
  迫使泵反向流）：

  ```text
  水力分块 1/2 求解失败（P1）：P1 工作点 -145.155 m³/h 超出泵曲线范围；反向流和曲线外工况尚未支持
  ```

## 5. 性能实测

环境：Windows、CPython 3.11.0、numpy 2.3.2、scipy 1.17.1；同机 A/B；BLAS 原生线程未固定
（默认值），因此只作为**同机相对比较**，不作为绝对基线。冷/热：预热 1 次后取中位数；
静态/小模型 7 次，规模扫描 5 次，动态 3 次。`hydraulic_blocks` 默认仍为 `False`。

### 5.1 小模型（median [min, max] ms）

| 场景 | 常规 | 分块 | 比值 |
| --- | --- | --- | --- |
| 两个独立水网（静态） | 6.01 [4.43, 7.39] | 12.69 [10.43, 13.16] | 2.11× |
| 换热器双回路（静态） | 5.48 [3.98, 6.27] | 12.01 [9.19, 12.96] | 2.19× |
| 4 端口 Python 实例 + 管线（静态，含 Worker 启动） | 2359.05 [2251.87, 2435.28] | 2287.18 [2236.56, 2805.01] | 0.97× |
| `heat-loop` 动态 0.2 s / 0.1 s（3 帧） | 10.96 [9.44, 12.34] | 17.61 [13.89, 20.68] | 1.61× |
| `tank-control` 动态 0.2 s / 0.1 s（3 帧） | 12.91 [10.49, 14.58] | 14.15 [10.10, 14.50] | 1.10× |
| 双水箱独立网络 动态 0.3 s / 0.1 s（4 帧） | 17.70 [14.28, 21.13] | 31.27 [21.29, 32.09] | 1.77× |

小模型分块反而更慢：每块都要构造子网络、调用一次 `least_squares`，Python/scipy 固定开销
（约 2–3 ms/块）远大于求解本身。这是预期行为，D 的收益需要足够大的独立分量规模。

### 5.2 规模扫描：N 条完全独立回路（每块 3 未知量）

| N（块数） | 未知量 | 常规 median (ms) | 分块 median (ms) | 比值 | 分块 `residual_calls` |
| --- | --- | --- | --- | --- | --- |
| 10 | 30 | 7.63 | 30.73 | 4.03× | 63 |
| 20 | 60 | 25.08 | 61.00 | 2.43× | 133 |
| 40 | 120 | 69.76 | 123.78 | 1.77× | 273 |
| 80 | 240 | 144.15 | 305.81 | 2.12× | 535 |
| 120 | 360 | 349.37 | 336.90 | 0.964× | 775 |
| 200 | 600 | 954.83 | 659.10 | **0.690×** | 1230 |
| 240 | 720 | 1936.27 | 813.52 | **0.420×** | 1550 |

- 常规路径是单个 dense 非线性系统，规模越大 Jacobian/线性代数越贵；分块把 1 个 720 未知量
  问题换成 240 个 3 未知量小问题，**N=200/240 实测提速 1.45×/2.38×**。
- N=200/240 另有独立一轮复测：`0.626×` / `0.452×`（方向一致，绝对比值受机器噪声影响）。
- 交叉点约在 N≈120（360 未知量）；小于该规模时固定开销占优，不应默认开启。
- 分块 `residual_calls` 随块线性增长（N=240 为 1550），但每块 nl 迭代只有 5–7 次；
  常规路径调用少（9–10 次）但单次稠密 Jacobian 更贵。

### 5.3 动态规模扫描（0.3 s / 0.1 s，4 帧；thermal 默认开启）

| N（块数） | 常规 median (ms) | 分块 median (ms) | 比值 |
| --- | --- | --- | --- |
| 10 | 29.99 | 70.51 | 2.35× |
| 40 | 142.75 | 312.81 | 2.19× |
| 120 | 639.01 | 977.37 | 1.53× |
| 240 | 2480.51 | 2396.13 | 0.966× |

动态端到端在 N=240 仍未见收益：每帧除水力分块外还有快照/热力/提交等共享开销，
稀释了水力部分的提速。**D 是否默认开启留给 R 里程碑按目标规模决定**（本包不打开默认）。

### 5.4 每块耗时（`counters['blocks']`）

- 2 块小模型（独立管道 + 独立泵阀）：块 0 = 6.56 ms，块 1 = 3.66 ms，`blocks_wall = 10.39 ms`。
- 换热器双回路：块 0 = 5.87 ms，块 1 = 6.89 ms，`blocks_wall = 12.94 ms`。
- N=40：40 块，块耗时 min/median/max = 1.97 / 2.60 / 4.48 ms，`blocks_wall = 112.5 ms`。
- N=200：200 块，块耗时 min/median/max = 1.62 / 2.41 / 4.67 ms，`blocks_wall = 533.2 ms`，
  `problem_size=600`、`jacobian_nnz=1800`。

## 6. 批量 Worker 与「不额外创建 Worker」

- `test_blocked_solver_uses_passed_runners_without_new_workers`：把 `fn_engine.solver._python_runners`
  替换为抛 `AssertionError` 的桩后，传入现成 `runners` 的分块求解仍成功；`evaluate` 计数增加、
  Worker 状态不变。
- `test_batch_runner_subset_keeps_workers_and_matches`：两个 Python 实例、`batch_modules=True`
  （`module_parallelism` 1/2）时，分块路径用 `_RunnerSubset` 只为**有请求的分片**发批量 RPC，
  不新建/关闭 Worker；求解前后 `runners.workers` 对象 id 列表相同，结果与常规路径一致。
- `_RunnerSubset.request_count` 只统计本块发出的 RPC，块级 `worker_requests` 相加即总 RPC 数，
  不会因复用父 `BatchRunners` 而重复计数。
- `test_solve_steady_two_blocks_matches_regular`：`solve_steady` 端到端（帧变量 + `solve_summary`）
  在 2 块网络上与常规路径逐变量过门，`method_reason` 含「分块求解」，残差过项目容差。

## 8. 未达标 / 未运行

- 小模型（< 120 独立块 / < 360 未知量）分块无提速，实测 1.03×–4.03× 回退；这是固定开销，不是缺陷，
  但**不满足「小模型不回退」**，因此本包不改变默认开关。
- 动态端到端 N=240 实测 0.966×，**未看到端到端收益**；只验证了水力部分的吞吐。
- 未接入线程池/多进程（X0 之前不做），块严格串行。
- 未在 API/前端入口跑端到端基准；未固定 BLAS 线程数、未记录进程树峰值 RSS。
- 分块 `iterations` 字段是各块 `nfev` 之和，与常规路径的单个 `nfev` 不可直接比较（已按新语义记录）。
- 多工质拆分只覆盖「块内单回路」；跨工质 Python 实例会降级整网（未构造真实多工质 D 场景基准）。
