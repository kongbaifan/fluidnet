## 1. 限定场景与“关阀捕获”

本阶段唯一支持的运行场景（编译期强制）：一条两端阀门在 t=0 全关的被动段，内含单一
`closed_volume`；`B1 → L1 → V1(关) → CV1 → V2(关) → L2 → B2`。

- 编译期把初态 p/T 作为该子网络唯一压力参考，并据此算出 M、U（`trapped.py::build_spec`）。
- 动态会话初始化时把 `(M, U)` 捕获为 **accepted 初态**（`TrappedState`），此后 M 不参与积分、
  U 只按热量收支推进；每步子步开始前用 accepted 状态经 `state_du(M/V,U/M)` 重算边界 p/T
  （`simulation.py::_view`），并写入求解视图的 `fixed_pressures/fixed_temperatures`。
- 相邻支路必须保持关闭；`step_network` 每次还校验相邻支路流量为 0（`TRAPPED_BOUNDARY_FLOW` 防御）。

- 两个端阀关闭，容积节点不在任何开放管道支路上：管道热容/节点焓流不会给该节点重复计能，
  同温管壁储能只记在困液账本（trapped 账本的 wall_energy_j）。本阶段没有改 thermal.py：困液节点通过
  求解视图的 fixed_pressures/fixed_temperatures 接入，热力层把它当作停滞的定温边界。
- 加热 20 kW、60 s、C_wall=2000 J/K 的实测帧（V=0.01 m³，初态 101325 Pa / 293.15 K）：

行内 `cumQ` 与 `U` 的差即同温管壁储能；每帧变量/指标见 [I1.md](I1.md) §1。

## 2. 运行时热流参数

`heat_input_w / heat_loss_ua_w_k / ambient_temperature_k` 与水箱一样是运行时参数：写入后立即进入
下一步的 `TrappedSpec`，不改 accepted 的 `M/U`。实测 `test_setting_trapped_heat_input_at_runtime_is_applied`：
把 `heat_input_w` 从 0 改成 50000 W 后推进 1 s，累计热量增加且 `CV1.state.temperature_k > 293.15 K`。

## 3. 拒绝/失败子步不提交（实测）

| 场景 | 实测行为 |
| --- | --- |
| 运行时把 `V1.opening_ratio` 改成 0.5 | 在生效前抛 `CompilationError(TRAPPED_OPEN_UNSUPPORTED)`；accepted `(M,U)` 与账本逐位不变，`V1` 仍为关闭。消息带释放账本（只报告、不写入相邻节点）：当前 `M=9.9820715 kg、U=847093.718 J、p=205654.786 Pa、T=293.38 K`，总储能 `847553.634 J`，管壁储能 `459.916053 J`；明确写“完整开闭周期（I5–I9）未实现” |
| 定容冷却闪发两相（`heat_input_w=-20000`，初态 500 kPa / 373.00 K） | 第一步 trial 抛 `TRAPPED_PHASE_UNSUPPORTED` → `SolveFailed`；`frames=1`，只保留 t=0 accepted 帧（p=500000.0000067 Pa，T=373.0000000000017 K，残差 0，漂移 0）；两相子步没有进帧 |
| 定容加热超压（初态 9.9e8 Pa / 500 K，加热 1e5 W） | 第二个子步 trial 抛 `TRAPPED_PRESSURE_LIMIT`（p=1.00598e9 Pa > 1e9 Pa）→ `SolveFailed`；`frames=2`（t=0、1.0），最后 accepted 帧 p=9.97984e8 Pa、T=502.72021 K、残差 −1.97e-7 J、漂移 0 |
| 邻接支路在运行中被打开（防御路径） | `TRAPPED_OPEN_UNSUPPORTED`；不会先推进再失败 |

实现：`advance` 捕获 `CompilationError` 中 `TRAPPED_*` 前缀的失败，转成 `SolveFailed(code, message,
instance_id, frames=已接受帧)`；`_trial` 中任何异常都不会调用 `_accept`，因此困液状态、账本与
`self.time` 都不会半提交。普通 `HYDRAULIC_NOT_CONVERGED` 等仍走既有的减半重试，不影响旧行为。

## 4. 帧输出与稳态边界

- 每帧 `RunFrame.variables` 增加 `CV1.state.*`（p/T/ρ/M/V/u/U/管壁储能/总储能/累计热量/热流/质量漂移）；
  `RunFrame.metrics` 增加 §I1 所列 `trapped_*` 稳定键。账本超门限时追加 `TRAPPED_LEDGER_VIOLATION`（error）。
- 每帧附带编译期 `TRAPPED_PROTOTYPE_ONLY`（info），文案明确“单容积封闭定容原型（I0–I4）……
  完整开闭周期与任意阀门隔离网络仍未实现”。
- `solve_steady` 不积分困液状态：稳态把该节点当初始压力参考（端口压力 = 初压），不输出
  `CV1.state.*`。这是刻意的降级，避免把稳态值冒充动态定容结果。

## 5. 未实现/阶段边界（必须如实说明）

- **完整开闭周期未实现**（I5–I9）：没有“运行中关阀捕获”（open→closed）与“重开释放/保守重连”。
  本阶段只支持**初始即关闭**的捕获；开阀请求在生效前拒绝并给出释放账本，不做压力强赋值。
- 不支持多容积串联、气垫、两相、弹性管壁、泄漏、水锤。
- 没有实现开放阶段的质量账本（见 [I2.md](I2.md) §4）。
- I0–I4 不计为“完整隔离段功能完成”；只标“单容积封闭原型”。
