交叉点分别落在 size ≈ 30（串联）、16–24（并联）、63–94（多环）。取 **MIN_SIZE = 64**：
最差的小模型（多环 38–63，稀疏慢 2.7×）仍走稠密，守住“小模型端到端回退 ≤10%”门。

阈值（`solver.py`）：

```text
AUTO_SPARSE_MIN_SIZE   = 64      # 未知量低于此值一律 dense
AUTO_SPARSE_MAX_DENSITY = 0.45   # 稀疏度高于此值（多端口模块依赖密集）一律 dense
AUTO_DENSE_MAX_SIZE    = 3000    # 超过此规模即使密度高也强制 sparse（稠密内存 O(size²)）
```

## 2. S1 选择与记录

- `hydraulic_method` 增加 `'auto'`（`Literal['dense','sparse','auto']`）。
- `HydraulicResult` 新增 `requested_method` / `effective_method` / `method_reason` / `matrix_size` / `matrix_nnz`；
  `RunFrame.metrics` 增加 `matrix_size` / `matrix_nnz`。选择原因示例：
  - `auto：未知量 199 ≥ 64 且稀疏度 0.005 ≤ 0.45`
  - `auto：未知量 5 < 64，稠密矩阵的固定开销更小`
  - `auto：稀疏度 1.000 > 0.45（多端口模块依赖密集，稀疏分组扰动接近稠密）`
- 显式 `dense` / `sparse` 永不被覆盖（单测）。
- auto 选 sparse 但稀疏求解未收敛时：**只回退一次到 dense**，容差不放宽，回退记录写入
  `counters['method_fallback']` 与 `method_reason`；回退后仍走同一个收敛门。单测用 monkeypatch
  让 `tr_solver='lsmr'` 的调用返回 `success=False`，观测到 `sparse:1, dense:1` 两次尝试。

## 3. 数值一致性

同一 100 阀串联网络（size 199）：

- `auto` 与显式 `sparse` 的 `pressures` / `flows` 一致（rel/abs 1e-9）。
- `auto` 未回退时 `counters['method_fallback'] == ''`。

## 4. 未覆盖

- 大规模（1000 实例）auto 与 sparse 的墙钟收益由 B1/B3 报告给出，本包只给交叉点与选择正确性。
- `property_coupling` 未改；API 缺字段仍按 dense（S2）。
