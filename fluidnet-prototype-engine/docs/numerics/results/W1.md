- 工作包：W1（依赖 W0）。
- 实施日期：2026-10-23。
- A/B 方式：同一 v0.5.0 快照 `a986ca3` 建两个 detached worktree：
  `artifacts/numerics/baseline-tree`（只改脚本）与 `artifacts/numerics/w1-tree`（额外替换成本包的
  `backend/fn_engine/worker.py`）。两棵树 solver/models/runtime 完全一致，只差 Worker 入口，
  因此差异只来自 W1；两轮 A/B 交错执行（A→B→A→B），每类 Worker 6 个样本取中位数，抵消共享机负载漂移。
- 改动文件：`backend/fn_engine/worker.py`（唯一行为改动）、`scripts/profile_worker_startup.py`（新增剖析）、
  `tests/test_worker_startup.py`（新增生命周期/诊断测试）。

## 1. 改动内容

1. **顶层导入瘦身**：`worker.py` 不再在模块导入时 `from . import properties`、不再 eager
   `from .runtime import ...`。顶层只保留标准库与 `.models`（协议模型必需，pydantic 无法避免）。
2. **惰性物性**：控制 Worker / 普通模块 Worker 在第一次真正访问 `ctx.fluid`、`ctx.fluid_at` 或
   `design` 上下文物性之前，不导入 CoolProp。实现方式是在 Worker 进程内包装
   `runtime._LazyPropertyService._get`：首次访问时才 `from . import properties` 并设置
   `properties.PROBE_REFPROP = False`。REFPROP 预探测语义不变（API 进程已探测，Worker 跳过），
   API 进程的运行时不受影响。
3. **启动诊断**：
   - 新动作 `startup_report`：返回 `module_import_s`、`first_request_uptime_s`、
     `properties_imported`、`probe_refprop`、`python`、`pid`；
   - `python -m fn_engine.worker --startup-report`：在 stderr 打一行 `FN_STARTUP {json}`，
     stdout 协议不变（仍只有 JSON RPC 响应）。
4. **行为保持**：控制 Worker 的 action 分支、`validate/design/initialize/parameters/evaluate/
   commit_step/finalize` 的顺序与错误消息不变；dispatch 异常仍回 `{"error": str}`；
   未知操作仍报“未知 Worker 操作：<action>”。

## 3. 启动报告示例

```
$ python -m fn_engine.worker --startup-report < /dev/null
FN_STARTUP {"module_import_s": 0.62, "first_request_uptime_s": null, "properties_imported": false,
            "probe_refprop": null, "python": "3.11.0", "pid": 1234}
```

控制 Worker 的 `properties_imported` 在完成 `control_initialize` + `control_step` 后仍为 `false`；
普通模块 Worker 在第一次读取 `ctx.fluid` 后才变 `true`，且此时 `probe_refprop` 为 `false`。

## 4. 适用/拒绝条件与回退

- 适用：控制脚本 Worker、只做内置关系/纯代数计算的 Python 模块 Worker、批量 Worker。
- 需物性任务：成本后移到首次物性访问，总首个成功步基本不变（实测 +3.3%，在门内）。
- 若模块**自己直接** `import fn_engine.properties`（而不是经 `ctx.fluid`），Worker 的
  `PROBE_REFPROP=False` 可能尚未设置，会退化为在 Worker 内做一次 REFPROP 预探测：结果正确但更慢，
  属于可诊断的退化，不改变数值行为。
- 回退：只改 `backend/fn_engine/worker.py` 一个文件；`git checkout -- backend/fn_engine/worker.py`
  即回到 v0.5.0 的启动语义。
