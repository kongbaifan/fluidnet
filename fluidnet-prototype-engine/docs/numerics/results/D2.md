## 1. 动态一致性（`solve_dynamic`，开/关 `hydraulic_blocks`）

逐帧、逐数值变量比较（门限：流量 `1e-8+1e-6|q|`、压力 `1 Pa+1e-8|p|`、温度 `1e-5 K`，
其余量 `1e-9` 相对）。实测最大数值差：

| 场景 | 帧数 | 最大数值变量差 | 说明 |
| --- | --- | --- | --- |
| `prototype('heat-loop')` 0.2 s / 0.1 s（2 块 + 换热器热耦合） | 3 | **0.000e+00** | 逐变量完全一致（含温度、热流、压力、流量） |
| `prototype('tank-control')` 0.2 s / 0.1 s（1 块） | 3 | **0.000e+00** | 计划只有 1 块，钩子返回 `None`，路径不变 |
| 双水箱独立网络 0.3 s / 0.1 s（2 块，动态水箱） | 4 | 1.510e-09 | 质量流量量级 ~2.6 kg/s，门限 ~2.6e-06；温度/液位/压力均过门 |
| 4 端口 Python 实例 + 管线 0.2 s / 0.1 s（2 块，含 Worker） | 3 | 2.910e-11 | `M1.state.commit_count` 两条路径均为 2 |

结构性指标会不同，这是分块语义的一部分，不参与物理一致性断言：

- `metrics.iterations`：分块是各块 `nfev` 之和（`heat-loop` 第 0 帧 16 vs 常规 8；第 1/2 帧 2 vs 1）。
- `metrics.matrix_size` / `matrix_nnz`：分块是单块最大规模（3 / 18），常规是全网（6 / 36）。
- `pressure_residual_pa` / `mass_residual_kg_s` / `energy_residual_w` 两条路径一致（如
  `heat-loop` 三帧均为 `3.64e-11 Pa` / `0.0 kg/s` / `7.94e-10 W`）。

对应测试：`test_dynamic_heat_loop_blocked_matches_regular`、`test_dynamic_two_tank_state_split_merge_matches_regular`、
`test_dynamic_multiport_module_commits_once_per_frame`。

## 2. 拆分 → 合并：初值/`solution` 不丢、不污染

未知量布局固定为 `[未知节点压力/1e5（升序）, 水箱净流入（升序）, 各支路流量]`：

- `test_blocked_solution_rebuilds_original_unknown_layout`：逐项断言
  `solution[:len(unknown)] * 1e5 ≈ pressures[unknown]`（`rtol=0, atol=1e-9` 的缩放单位，
  即 1e-4 Pa）与 `solution[flows_offset:] == flows`（`rtol=0, atol=0` 全等），并在换热器双回路
  场景与常规解过 3.1 门。
- `test_blocked_warm_start_slices_initial_per_block`：给分块求解传入常规解作为 `initial`，
  用探针截获每块实际收到的初值向量，与「按原布局切出的期望值」逐元素全等。实测换热器双回路
  （4 个节点全部为固定边界，每块只有 1 个流量未知量）：

  ```text
  solution = [q(HX.ch0)=2.12508402, q(HX.ch1)=2.06687042]
  块 0（节点 0,3；支路 HX.ch1）收到 [2.06687042]
  块 1（节点 1,2；支路 HX.ch0）收到 [2.12508402]
  分块带 warm start 与常规解：压力差 0.000e+00，流量差 0.000e+00，solution 差 0.000e+00
  ```

  含未知压力节点的块会收到额外 `p/1e5` 分量（`test_blocked_solution_rebuilds_original_unknown_layout`
  与 D1 的 2 块静态场景覆盖该排布）。

- 形状不匹配/非有限的 `initial` 直接回退冷启动（不抛错、不误用错位初值），实测与常规解
  流量差 `5.42e-14 kg/s`。
- 动态：水箱状态（`TK*.state.mass_kg` / `level_m` / `net_inflow_kg_s` / `temperature_k`）
  与常规解逐帧过门（见 §1 双水箱 1.51e-09）。

## 3. 失败与提交边界

- `test_failed_block_does_not_commit_module_state`：先让块真实求解（`evaluate` 计数增加），
  再人为抛 `HydraulicNotConverged`。结果是 `HydraulicBlockFailure`，且
  `runners['M1'].state`（含 `commit_count`）与失败前**逐项相等**：
  **分块 hook 在失败路径上不调用 `commit_step`、不修改模块状态**。
- 分块求解只在全部块成功后才返回合并结果；任一块失败直接抛出，不会产生「部分块成功」的
  `HydraulicResult`。
- `_commit_modules` 仍由 `simulation._step_network` 在子步接受后统一执行；D 不改变该事务点。
- **未运行**：本包没有新增端到端「失败子步 Worker/PID/能量均未提交」的集成测试（PID 场景也未
  构造）。该语义由既有 `tests/test_run_control.py` / `tests/test_pid.py` 覆盖，D 的分块路径在失败时
  不会先提交任何东西（见上一条单测），但完整事务链未在 D 包内重复验收。

## 4. 同一多通路模块的生命周期

- 分块不会把同一 Python 实例拆到两个块（D0 保守同块），也不会为不同块重复创建 Worker。
- `test_dynamic_multiport_module_commits_once_per_frame`：3 帧动态运行，两条路径的
  `M1.state.commit_count` 都恰好为 `2`（= 接受帧数），每条通道关系各由一次 evaluate 提供；
  与常规路径逐变量差 `2.91e-11`。
- 批量 Worker：`test_batch_runner_subset_keeps_workers_and_matches`（见 `D1.md` §6）证明
  分块只复用父 `BatchRunners` 的 Worker（对象 id 列表求解前后相同），没有额外生命周期。
- 子网络由 `dataclasses.replace` 重建为同类型 `CompiledNetwork`：`execution_domain` / `trapped`
  不是 `CompiledNetwork` 的 dataclass 字段，重建时不会带入；这些属性只存在于 thermal/制冷
  执行域的其他网络类型，而那些网络不会进入本钩子。A0 的 `ensure_supported` 只在
  `simulation.run_dynamic` 入口检查**原网络**（`simulation.py:36`），不会作用于子网络；Lead 侧
  已把 `SimulationSession` 改成 `getattr(self.network, 'trapped', {})`，因此子网络缺该属性也不会
  失败。本包未修改 `simulation.py` / `timestep.py`。

## 5. 依赖缓存失效（结构 + 闭合状态 + Python 关系）

- `plan_signature(network)` 包含：节点数、编译期 `node_component`、`node_circuit` 与回路工质、
  `mixed`、每条支路的 `(instance, channel, start, end, closed, solver_model)`、
  每个 Python 实例的 `(runtime, [(port, node)])`。**不含**压力/温度数值，因此：
  - 同一步内热力外迭代、动态时间推进只改边界/物性 → 签名不变 → 计划缓存复用；
  - 阀门静态闭合状态、Python 实例端口映射/回路结构变化 → 签名变化 → 重新划分。
- 实测：同一网络两次 `plan_signature` 相同且 `resolve_plan` 返回同一对象；把一条支路改为
  `closed=True` 后签名不同，重算块数从 2 变 3，`solvable_blocks` 只剩 1，钩子返回 `None`
  （`test_plan_cache_keyed_by_structure_and_closed_state`）。
- 运行期 Python 关系变化（阀关/压缩机强制流量）只会**减少**耦合：静态上已同块的节点仍同块，
  不会让新节点耦合，所以缓存无需按运行期关系失效；代价是块可能比理论最小划分大。
- 缓存上限 64 条，超出整表清空；只存索引，不持有 `CompiledNetwork`。

## 6. 单块与总耗时（实测）

来自 `SolverOptions.hydraulic_diagnostics=True` 的分块结果，详见 `D1.md` §5.4：

| 场景 | 每块墙钟 | `blocks_wall_s` |
| --- | --- | --- |
| 独立管道 + 独立泵阀（2 块） | 6.56 / 3.66 ms | 10.39 ms |
| 换热器双回路（2 块） | 5.87 / 6.89 ms | 12.94 ms |
| N=40 独立链 | min/median/max 1.97 / 2.60 / 4.48 ms | 112.5 ms |
| N=200 独立链 | min/median/max 1.62 / 2.41 / 4.67 ms | 533.2 ms |

动态端到端（median，3 次）：`heat-loop` 10.96 → 17.61 ms；`tank-control` 12.91 → 14.15 ms；
双水箱 17.70 → 31.27 ms；Python 多端口 2359.05 → 2287.18 ms（Worker 启动占主导）。
N=240 独立链动态 4 帧：2480.51 → 2396.13 ms（0.966×，端到端无收益）。
**结论：小模型/动态端到端未达提速目标；静态大规模（N≥200）才出现收益。默认开关保持 `False`。**
