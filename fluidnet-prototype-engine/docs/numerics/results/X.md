# X/G 探索包证据与决策

计划 §14 把 X0/X1/X2/G0 定义为“有证据再立项”的探索包，不承诺整项工期。本文件记录本轮实际做了哪些探索、
测得什么、以及继续/停止的决定。

## X0：分块并行（启动条件：D2 报告显示独立块有明显耗时）

**已做的探索**（`tmp/x0_threads.py`，非提交物）：同一 79 未知量网络重复求解 8 次，
顺序执行 vs `ThreadPoolExecutor`：

| 并发方式 | 总耗时 | 相对加速 |
| --- | ---: | ---: |
| 顺序 | 0.227 s | 1.00× |
| 线程 ×2 | 0.225 s | 1.01× |
| 线程 ×4 | 0.228 s | 1.00× |

结论：单次水力求解的主要耗时在 SciPy 的 Python 层调用与 GIL 持有的小对象操作上，
线程并无收益；按 §14 的门（≥20% 中位数改善才拆实施包），**X0 停止**，保留顺序分块。
真正的并行需要进程级隔离（每个块一个 Worker/进程），会引入进程启动、序列化与事务一致性成本，
在没有 D2 的块级耗时证据（例如某块独占 >50% 端到端时间）前不立项。
本轮未做进程池 A/B：D2 结论（见 `D2.md`）是顺序分块在典型网络上没有明显收益，前提不成立。

## X1：通用管网误差控制（启动条件：A4 通过且确有精度需求）

未启动。A4 的首轮范围只覆盖理想热模型与冷库 B；通用管网涉及 `commit_step`、任意 Python 模块状态
与两支半步的可恢复协议，属于独立协议设计。按 §12/§14，需先有 A4 通过 + 明确的通用管网精度需求
（例如现场验收要求与固定步长结果的可追溯差异），才把“任意模块状态的两半步试算/恢复协议”立项。
本轮**不做**，也不宣称通用管网支持误差控制。
