## 1. 结论摘要

1. **默认无迟滞**（`hysteresis_pa = 0`）：`evaluate` 只依赖试算 Δp，与 accepted state 无关，
   天生幂等，且不需要求解器改动。
2. **迟滞是可选的**，状态只在 accepted 步（`commit_step`）更新；`Δp ≤ 0` 恒关，所以迟滞不会带来
   任何反向泄漏。实测表明动态按步推进即可自洽，**不需要**外层活动集（见 §2.3）。
3. 动态扫压差在 `dt = 0.1 / 0.05 / 0.02` 三种步长下累计**反向通过质量均为 0.0**，正向通过质量严格
   正比于 dt（时间轴被重放，不是被压缩）。
4. 版本：`check_valve` 同时可查 `2.0.0`（`tested=true`）与 `1.0.0`（旧包原样）；升级只能显式预览，
   v1→v2 预览 `compatible=true` 且列出变化；拒绝/失败时项目文档逐字段不变（回滚 = 不写入）。
5. 剩余限制：Python 模块运行期关断若造成无参考子网，仍会报“缺少压力参考”，见 §5。

## 2. 迟滞设计（默认关闭）

### 2.1 冻结的状态机（纯函数，`backend/fn_engine/check_valve.py`）

```python
is_open(delta_p, p_crack, hysteresis_pa, was_open) -> bool
# Δp ≤ 0                                  -> False（反向/零压差恒关）
# hysteresis_pa == 0                      -> Δp > p_crack（与 accepted state 无关）
# hysteresis_pa > 0 且 was_open == False  -> Δp > p_crack + h        （开阈值）
# hysteresis_pa > 0 且 was_open == True   -> Δp > max(0, p_crack - h)（关阈值）
```

保持开启且 `0 < Δp ≤ p_crack` 时开度取 `opening_max`（阀瓣已抬起），这是**正向亚阈值流量**，
是迟滞的固有代价；反向依然被第一条挡住。状态转移 `next_open_state(...)` 只在 `commit_step`
调用；`evaluate` 只读 `ctx.state`（深拷贝），不写回。

### 2.2 实测

- `test_v2_evaluate_idempotent_under_same_accepted_state`：同一 trial 输入、同一 accepted state
  下连续两次 `evaluate` 的 `model_dump()` 完全相等，且 `runner.state` 不被污染；`Δp=−1000` 恒返回
  精确 `0.0`，`Δp=4900` 在“已开启”时保持 `opening=1.0`，`Δp=5100` 在“已关闭”时保持 `0.0`
  （要 `5600 > 5000+500` 才开）。
- `test_v2_hysteresis_disabled_does_not_change_results`：显式传 `hysteresis_pa=0.0` 与不传该参数
  的整网解与 `nfev` 完全相同（“未启用时不改变结果”回归）。
- `test_v2_hysteresis_band_is_path_dependent_and_never_leaks_reverse`：
  - 冷启动（accepted=关）在 `Δp=5200`（落在 `(5000, 5500]`）时保持关闭、流量 0；无迟滞对照则
    `5200 > 5000` 立即开启 —— 路径相关是迟滞的预期语义；
  - 序列 `20000 → 4800 → 4800 → −1000`：前 3 步开启（第 2/3 步为正向亚阈值保持，`Δp=4800`
    在关阈值 4500 之上），第 4 步关断；累计反向质量 `0.0`，`state.reverse_throughput_kg=0.0`。

### 2.3 为什么默认路径/动态路径都不需要求解器改动，以及可选的集成提案

模块 `evaluate` 拿到的是**试算压差 + accepted state**，同一子步内状态不变，因此给定活动集后残差
关于压力的函数是确定的；`commit_step` 用收敛压差推进状态机。动态运行每个 accepted 步推进一次，
语义自洽。只有在“同一步内需要把活动集反复重解到自洽”（例如将来要把迟滞状态允许在步内翻转、
或稳态求解在已有 accepted state 上重解）时，才需要外层活动集。**本包未接入、未实测。**

给 Lead 的精确提案（仅在需要时接入；默认路径与本次验收都不依赖它）：

| 项 | 内容 |
| --- | --- |
| 纯函数 | 已在 `backend/fn_engine/check_valve.py`：`is_open`、`required_opening`、`next_open_state`、`opening_slack_pa`、`complementarity_residual`、`ValveParameters` |
| 插入点 | `solver.py::_solve_hydraulics` 中 `attempt(...)` 成功之后、构造 `HydraulicResult` 之前，加“活动集重解”循环（只对 `hysteresis_pa > 0` 的 Python `valve` 关系生效） |
| 试算状态注入 | 新增可选参数 `activity_state: dict[str, dict] | None`；在 `attempt` 前把 `runner.state` 的 `is_open` 临时覆盖为候选活动集，`attempt` 后恢复（不提交、不影响 `_commit_modules`） |
| 翻转判据 | 对每条止回阀支路：`Δp = p[start]−p[end]`、`q = flows[idx]`、`λ = opening_slack_pa(Δp, p_crack)`；违例 = `(λ ≥ 0 且 |q| > mass_tolerance)` 或 `q < −mass_tolerance`；新活动集 = `next_open_state(was_open, Δp, p_crack, h)` |
| 收敛/上限 | 活动集不再变化即收敛；上限 8 次重解，超限报可诊断错误（或回退到 `h=0` 路径保留已接受历史），不放宽容差 |
| 压力邻接 | 关闭支路本就不进入压差方程（`physical_residual` 的 `constraints` 已排除），无需新增图约束；`_solve_hydraulics` 末尾的“每块需要压力参考”检查仍会触发，失败模式与 §5 一致 |
| 预期数值 | 单阀单次求解实测 2–18 nfev（V1 §4–§6）；若活动集需要 2–3 次重解，预计总 nfev ≈ 1.5–3× 单次、RPC 同比例增加。**这是估计，未实测** |

## 3. 动态扫压差验收（步长变化不产生虚假反向质量）

序列（每个 Δp 一个时间步，`p_crack=5000`，`Kv=50`）：
`20000, 10000, 5001, 5000.01, 5000, 1000, −1, −1000, −20000, −1000, 20000`。

| dt (s) | 正向通过质量 (kg) | 反向通过质量 (kg) | `state.open_steps` / `closed_steps` |
| ---: | ---: | ---: | --- |
| 0.1 | 1.3900246837 | **0.0** | 5 / 6 |
| 0.05 | 0.6950123419 | **0.0** | 5 / 6 |
| 0.02 | 0.2780049367 | **0.0** | 5 / 6 |

- 反向质量在三种步长下都精确为 `0.0`（不是“小于容差”），且 `state.reverse_throughput_kg == 0.0`。
- 正向质量严格 ∝ dt（`1.3900 × 0.5 = 0.6950`、`× 0.2 = 0.2780`，相对误差 < 1e-12），说明时间轴被
  重放而不是被压缩；开/关步数在三种步长下完全一致（步长不改变活动集序列）。
- 序列中的 `5000.01 Pa` 与 `5000 Pa` 分别落在开关点两侧：前者开启（q≈0.00439 kg/s），后者精确 0。
- 验收不通过减小 dt 修复稳态：稳态/阈值侧收敛在默认容差（1 Pa、1e-8 kg/s）下完成（V1 §5），
  本节只比较不同 dt 的积分结果。

- 升级后 `package.version == '2.0.0'`，实例参数、参数库与包绑定一起更新。

## 5. 剩余限制

- **Python 关闭产生无参考段**：关闭的 Python 止回阀若把下游隔成无压力参考子网，运行报
  `RuntimeErrorBase: 模块通路关系产生了缺少压力参考的子网络`（实测复现，见
  `test_v2_dead_end_after_close_reports_missing_reference`）。动态时间步的“被动段保压近似”
  只覆盖内置被动支路，运行期由 Python 模块决定的关断不在其内。缓解：关闭后仍与压力参考相连的
  一侧保留边界/泵/其它支路；根治需要运行时依赖重建（计划 I5+ / D2 范围）。
- `evaluate` 契约拿不到流量，开关判据只能基于压差；病态工况（压差正、流量被其它支路逼负）不会在
  `evaluate` 内发现，只能由收敛结果事后检查。
- `hysteresis_pa > 0` 的“步内活动集自洽”未接入（§2.3 提案）；当前动态按 accepted 步推进，
  稳态从 `initialize` 的关闭初态出发也能得到正确活动集，但同一步内不重解。
- 关闭支路的热语义沿用既有零流量约束（`NO_FLOW_HEAT` 前提），v2 不输出 `heat_w`。
- `state.closed_steps` 只统计接受步；稳态不提交，恒为 0。
- 冷/热启动在跨阈值时热启动可能更差（V1 §7），本包不宣称 warm 一定更优。
