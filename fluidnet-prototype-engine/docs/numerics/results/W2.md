## 3. 旧行为与错误码

- `RuntimeErrorBase.code`（`MODULE_RUNTIME_ERROR`）与 `ModuleRuntimeTimeout.code`
  （`MODULE_RUNTIME_TIMEOUT`）未改；Worker 异常响应仍是 `{"error": str(error)}` 单行 JSON。
- 控制预览走既有 `create_session → initialize → _control()` 路径，返回 `writes/state/diagnostics/
  content_hash/time_s/applied`，本包没有改控制协议。
- 成功与失败路径都不额外启动 Worker：`WorkerProcess` 仍按实例创建、`close()` 后进程退出；
  `wait_for_no_children()` 在每条用例后验证。

## 4. 偏差

- 启动报告的时间戳来自 Worker 进程自身（模块导入完成、首个请求到达），不含解释器启动；
  解释器启动成本由 W0/W1 的进程层测量单独登记。
- 未实现“Worker 池/预派生”：那会改变 Worker 生命周期与失败隔离语义，超出 W2 范围；
  本包只提供可诊断的启动报告与生命周期回归。
