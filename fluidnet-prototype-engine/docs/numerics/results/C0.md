## 1. 识别规则（冻结）

`plan_compression(network)` 返回可导出的计划（`:class:`CompressionPlan``，`as_dict()` 可直接进报告）：

| 项 | 规则 |
| --- | --- |
| 可压缩支路 | `solver_model ∈ {valve, pipe, pump_curve, resistance}` 且 `branch.closed == False` 且实例不是 Python 模块 |
| 锚点（保留节点） | 固定压力节点、水箱/储量节点、**紧邻不可压缩支路**（关闭阀、未注册模型、Python 支路）的节点、可压缩子图度数 ≠ 2 的节点 |
| 内部节点 | 可压缩子图度数 = 2 且不是锚点 → 从约化网络移除，压力由链回算 |
| 链 | 从锚点沿可压缩支路走到下一个锚点；成员数 ≥ 2 才压缩；回到起点的链记为 `loop=True`（保留锚点，约化为自环） |
| 无压力参考的纯环/分量 | 整条成员全部标记为不可压缩（原因“无压力参考的纯环/分量”），交回常规路径报原有错误 |
| 单支路 | 不压缩（无收益），按单支路保留在约化网络 |

`CompressionPlan` 导出：`chains`（每条链的成员 `(原支路下标, 遍历符号 ±1)`、起止锚点、是否环）、
`standalone`、`anchors`、`unknown_anchors`、`excluded`（`(原支路下标, 原因)`）、
`original_size`、`reduced_size`、`reduced_nnz`。未压缩原因只有三类：`关闭支路`、`未支持模型 <model>`、
`Python 支路`，另有无压力参考分量（见上）。

## 3. 关闭状态与参数变化（C3 的计划失效）

计划缓存签名 = 节点数 + 每支路 `(start, end, closed, solver_model)` + 固定压力节点集合 + 储量节点集合。
参数**值**不进入签名（复合压降每次求解现读参数），关闭阀会把 `closed` 置 True → 签名变化 → 重建。
`test_closed_valve_and_open_change_are_consistent` 实测：先算开启链（压缩链数 1、`matrix_size==1`），
再把参数改为 `opening_ratio=0` 且 `branch.closed=True` 后重算，计划重建为 2 条链、矩阵从 1 变 5，
结果与未压缩路径在 3.1 差值门内一致。

## 4. 缓存与一次性开销（实测）

- `plan_compression` 1000 支路首次构建：**36.9 ms**（一次性）。
- 同结构重复求解命中缓存：签名重建是 O(m)（1000 支路约 0.3 ms），1000 支路压缩求解中位数 **96.6 ms**，
  见 C2/C3。
- 缓存上限 16 条，超出整体清空；缓存只是性能优化，失效不影响正确性。

## 5. 未覆盖 / 已知限制

- 有 Python runner、`storage_step` 非空、`port_base` 非空、多工质（`network.mixed`）时**不压缩**，
  直接返回 `None` 走常规路径（C2 §1 列了实测断言）。
- `heat_exchanger` 等非四类模型不进入链（保持原支路）。
- 同时开启 D（`hydraulic_blocks`）时的“先分块再压缩”组合**未实测**（D 端实现不在本包）；单开 C 已验。
- 未实现“多条平行链合并”“链内解析闭式聚合”，每次残差对链成员是 O(m)，见 C1 §5。
