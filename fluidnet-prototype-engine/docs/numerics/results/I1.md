## 1. 内置模块契约

`catalog.py::builtin_catalog()` 新注册（catalog 条目数 23）：

- `id=closed_volume`，名称“封闭定容液腔（原型）”，`solver_model='closed_volume'`，`state_model='closed_volume'`。
- 端口：`in0`/`out0`（两端都要求连接，两个端口在节点上合并为一个均匀容积节点，与 junction/tank 同规则）。
- 参数（默认值只保证“旧项目无该模块时完全不受影响”，不会自动激活）：

| 参数 | 默认 | 语义 |
| --- | ---: | --- |
| `volume_m3` | 0 | 有效液体容积；**0 或缺失在编译期拒绝**（`TRAPPED_VOLUME_REQUIRED`） |
| `wall_heat_capacity_j_k` | 0 | 集总管壁热容（与流体同温） |
| `initial_temperature_k` | 293.15 | 显式初温 |
| `initial_pressure_pa` | 101325 | 显式初压（该子网络唯一压力参考） |
| `heat_input_w` | 0 | 加热功率（负值为冷却），运行时可写 |
| `heat_loss_ua_w_k` | 0 | 环境散热 UA |
| `ambient_temperature_k` | 293.15 | 环境温度 |

帧变量（`RunFrame.variables`）：`<id>.state.pressure_pa / temperature_k / density_kg_m3 / mass_kg / volume_m3 /
specific_internal_energy_j_kg / internal_energy_j / wall_energy_j / total_energy_j / cumulative_heat_j /

trapped_pressure_pa / trapped_temperature_k / trapped_density_kg_m3 / trapped_internal_energy_j /
trapped_total_energy_j / trapped_cumulative_heat_j / trapped_energy_scale_j / trapped_energy_residual_j /

## 2. 激活与注册（实测）

`compile_project` 在标准单流体分支（非 thermal/refrigeration/cold_store 执行域）识别该模块：

- 节点合并后，把该节点登记进 `fixed_pressures` / `fixed_temperatures`（初态 p/T），即该子网络的压力参考；
- 生成 `network.trapped = {node: TrappedSpec}`，`TrappedSpec` 内含 V、C_wall、T_ref=初温、初态 M/U、p₀/T₀；
- 追加信息诊断 `TRAPPED_PROTOTYPE_ONLY`（每帧可见），明确“单容积封闭原型，完整开闭周期未实现”。

实测（V=0.01 m³、初态 101325 Pa / 293.15 K、C_wall=2000 J/K）：
`M=9.982071504679 kg`、`U₀=837553.634006 J`；`fixed_pressures[node]=101325.0`、
`fixed_temperatures[node]=293.15`；诊断列表 `[('TRAPPED_PROTOTYPE_ONLY','info')]`。
稳态求解把该节点当作初态压力参考（`CV1.in0.pressure_pa = 101325.0`），**不产生** `CV1.state.*`
动态状态变量（稳态不积分困液状态，避免伪装成动态结果；定容状态只在动态步里推进）。

## 3. 初态合法性（编译期，复用 `state_du`）

`trapped.build_spec` 用 `state_pt(p₀,T₀)` 取密度/比内能，构造 `M=ρV`、`U=M·u`，再用
`state_du(M/V,U/M)` 做**往返一致性**检查：

- p 往返差 `−3.76e-5 Pa`（门限 max(10 Pa, 1e-5·p₀)≈10.13 Pa）；T 往返差 `2.13e-11 K`；
- 初态必须是 `liquid`（`supercritical_liquid` 也按含 liquid 的单相压缩液接受；`twophase`/`gas` 拒绝）；
- T 必须在物性上下限内，p 必须在 `(0, p_max]`；初态不一致返回 `TRAPPED_INITIAL_STATE_INCONSISTENT`。

## 4. 拒绝矩阵（实测诊断码与触发条件）

| 配置 | 诊断码 | 说明 |
| --- | --- | --- |
| 任一相邻支路初始未关（`opening_ratio>0`） | `TRAPPED_NOT_CLOSED` | 消息点名仍打开的支路（如 `V1`）；不会启动后才失败 |
| `volume_m3=0` / 缺失 | `TRAPPED_VOLUME_REQUIRED` | 未建模阀腔不得按零容积默认通过 |
| 工质 `HEOS::R134a` | `TRAPPED_FLUID_UNSUPPORTED` | 只用 HEOS 纯水；消息说明“尚未通过压缩性/相态能力检查” |
| 工质 `IF97::Water` | `TRAPPED_FLUID_UNSUPPORTED` | 纯水但非 HEOS 后端也拒绝（不借用 IF97 压缩性） |
| 初态 50000 Pa / 400 K（气相） | `TRAPPED_PHASE_UNSUPPORTED` | 初态必须单相液体 |
| 初压 > Water `p_max` | `TRAPPED_INITIAL_STATE_INVALID` | 不截断到上限 |
| 两个 `closed_volume` | `TRAPPED_MULTIVOLUME_UNSUPPORTED` | 第一阶段只支持单一均匀容积；多容积串联属 I5–I9 |
| 与开式水箱同项目 | `TRAPPED_TANK_MIXED` | 不把定容语义与水箱定压储量混用 |
| 压力边界与容积同节点 | `TRAPPED_PRESSURE_REFERENCE_CONFLICT` | 不跨压力参考 |
| INCOMP / 其他后端 | `TRAPPED_FLUID_UNSUPPORTED` 或更早的 `PROPERTY_BACKEND_UNSUPPORTED` | 由物性服务给出稳定错误，不静默降级 |

## 5. 与既有模型/默认值的关系

- 未使用 `closed_volume` 的项目完全不受影响：`trapped` 为空，`s.has_state` 与动态/稳态路径不变。
- 没有复用开式水箱的 `TankState`/`StorageSpec`（定压、静压液位语义），也没有复用两相 `vessel_state`。
- 编译器没有为困液容积生成任何“定压等效”的替代结果：识别的只是显式容积与初态参考。

## 6. 未达标/未实现项（如实记录）

- 不支持多容积串联（即使显式给了每段 V）；这是第一阶段硬边界。
- 不支持 INCOMP、气垫、两相、弹性管壁、泄漏、水锤。
- 支持范围只在“标准单流体分支”：`thermal`/`refrigeration`/`cold_store` 执行域里的 `closed_volume`
  会因各自编译器不认识而报既有诊断，不会静默当作已支持。
