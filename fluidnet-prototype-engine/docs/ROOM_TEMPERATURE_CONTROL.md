# 房间自动温控与三回路联算

本案例在已有空气、冷冻水和冷却水三回路上，使用房间温度反馈自动调节盘管水阀。机组持续运行，风机保持固定转速；风量仍由风机与空气管网工作点求得。房间有真实热湿储量，两个水回路仍为无储量网络。

## 创建并运行

1. 打开“风系统 → 创建风侧示例”，选择“房间自动温控 · 初始降温”“负荷阶跃”或“设定变化”。
2. 默认动态运行 **2400 s（40 min）**，输出及控制采样周期 **30 s**。点击“运行计算”，等待完成。
3. “反馈控制”同时显示反馈、目标、阀门输出和运行模式，并绘制反馈/目标与输出两张曲线。数值来自该次运行的已接受帧；PID 反馈为上一采样时刻的测量，当前房间状态见“设备与水耗”。
4. “调整设定”使用 **°C**，保存及计算采用 **K**。例如输入 25，规范项目保存为 298.15 K。改变目标会令当前结果过期，新运行使用新目标；历史来源继续显示原目标。
5. “控制逻辑”可编辑 PID、手自动模式及 Python 工况脚本。通用 PID 编辑器标注并使用规范单位，温度设定填 K，阀位填 0–1。
6. “设备与水耗”查看房间温湿度、盘管冷量、机组负荷比/COP/功率/累计耗电。“风量与状态”保留全部空气与水端口。CSV/HTML 报告包含 PID 目标、测量和输出。
7. 保存项目后可重载；“管理项目”的单项目导出保留运行时长、控制及模块快照。也可从[案例目录](../examples/room-control/README.md)导入规范 Project 文件。规范格式没有运行时长，导入后请将动态时长改为 2400 s、输出步长改为 30 s。

## 三个工况

| 示例/API 名称 | 初始条件 | 600 s 时的变化 | 目标 |
| --- | --- | --- | --- |
| `room-temperature-control` | 室温 30°C、显热负荷 5 kW | 无 | 降温并维持 26°C |
| `room-control-load-step` | 同上 | 显热负荷由 5 kW 增至 8 kW | 恢复到 26°C 附近 |
| `room-control-setpoint-step` | 同上 | 室温目标由 26°C 改为 25°C | 跟踪新的目标 |

变化由真实 Python 控制脚本 `room-scenario` 执行。脚本在 600 s 帧之后的控制边界写入，因此 **600 s 帧保留变化前值，630 s 帧包含变化后值**。它只写一次，已接受状态记录 `applied=true`；没有新增风侧日程执行器。脚本可编辑 `CHANGE_TIME_S`、`TARGET` 和 `VALUE`，输出声明须和目标一致。

设定变化案例中，脚本拥有 `controller.room-temperature.setpoint`：运行期间不能同时手动写这个目标。停止后“调整设定”改的是初始目标，600 s 时仍由脚本设置为其源码中的值。若要全程手动改目标，先停用该脚本。负荷阶跃案例的脚本只拥有室内显热负荷，温度目标仍可调。

## 控制及模型假设

- PI 控制器 `room-temperature` 读取 `Room.state.temperature_k`，写 `WaterValve.opening_ratio`。此编号只是示例绑定，平台及结果页按实际项目引用工作。
- `error = setpoint − measurement`，水阀开大使房间降温，因此采用 `Kp = −0.1 K⁻¹`、`Ki = −0.00006 (K·s)⁻¹`、`Kd = 0`。初始阀位 40%，初始化保持初始输出，后续按采样推进；现有积分限幅避免输出饱和时继续积累。
- 阀位限制 **2%–100%**，保证案例水回路保留正流量。该下限是此教学模型的边界选择，模型没有厂家规定的最小水量；案例不包含旁通阀或机组最小负荷启停。
- 默认机组冷冻水出水目标 7°C、额定制冷量 35 kW。房间有效体积 100 m³，围护/家具附加热容 1 MJ/K，显热负荷和围护传热按原三回路模型计算。
- 湿量迭代收敛精度为 `1e-10 kg/kg_da`，比原短示例更严格，水分/能量守恒验收阈值不变。
- 机组 `capacity_limited=true` 表示满载仍未达到冷冻水出水目标；阀位已到上限但室温偏高，表示当前系统或控制能力不足，不能把设定值当作实际室温。
- 房间湿度随盘管冷凝和房间散湿共同变化。本例只有温度闭环；水侧储热、机组启停、独立湿度控制及设备厂家性能标定不属于此案例。

## 对比与复算

“运行对比”可对同一变量叠加最多四次运行，单位与变量合同须一致。建议依次对比室温、控制输出、机组累计耗电和室内负荷；比较能耗时采用相同时长，并同时检查舒适温度偏差。

“批量方案”沿用现有保存修订和固定快照，可扫描房间显热负荷或初温。观察量包含 `Room.state.temperature_k`、`controller.room-temperature.setpoint`、`controller.room-temperature.output`、`Chiller.state.electric_energy_j`。PID 增益不是设备参数，调整增益后保存新修订并运行，再从“运行对比”比较。
