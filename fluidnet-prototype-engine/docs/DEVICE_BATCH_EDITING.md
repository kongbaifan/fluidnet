# 多设备批量编辑

2026-11-05。建模工具栏的“批量编辑设备”提供按模块筛选、跨画布设备选择、共同参数/型号编辑、逐设备预览和一次整批应用。它使用现有项目参数写入协议，和“批量工况运行”是独立入口。

## 使用

1. 在建模页点击“批量编辑设备”，选择模块。
2. 勾选当前项目各画布中要编辑的设备。设备必须有兼容的冻结模块版本、参数合同和显示键映射。
3. 勾选要修改的字段，输入统一显示值；支持数值、布尔、文本和曲线。没有勾选的参数及其待应用草稿保留。
4. 也可以选择统一型号。完整采用型号时保留型号来源；在型号基础上另改字段时，预览明确标注“自定义参数，基于型号”，应用后不继续声称与原型号一致。
5. 预览逐台显示“已应用、已有草稿、本次应用、单位”，确认后整批提交。取消不修改任何实例。

运行中，预检查可写权限、runtime权限，以及该次运行冻结的PID/脚本控制归属。任一选中设备的改动不合法就拒绝整批。后端仍负责最终校验；暂停/运行期间通过一个`write`命令提交所有实例参数，等同一命令应用回执后才提升本地状态。

如果命令已接收但回执超时，界面保留草稿并提示检查运行事件，不将未知结果宣称为后端已回滚。

停止时使用同一参数合同校验，再一次提升本地对象。型号必须属于相同模块及版本；选型型号额外校验冻结双哈希。预览期间项目、实例、参数、草稿、运行或型号变化时拒绝过期预览。等待回执期间若产生新的草稿输入，由事务层保留，不以旧草稿覆盖。

当前每批针对同一模块的兼容设备；不同模块或版本应分别操作。批量编辑不升级模块版本，不修改控制器设定，不复制库房/容器物理状态。

## 实现与验证

UI为`frontend/device-batch.js`；工作台只加入工具栏入口和动作依赖。事务由`engine.applyParameterBatch`及`frontend/parameter-batch.js`处理，UI不会循环调用单设备应用接口。

- `node --test tests/device-batch.test.mjs`：5项通过，涵盖旧显示键映射、参数类型和单位范围、冻结控制归属、异版拒绝、过期预览与只读构造。
- `node tests/browser-device-batch.mjs`：真实浏览器1920×1080、DPR=1通过。双阀跨页选择；取消保持原值；未选Kv草稿保留；暂停时只有一次write包含两个实例参数并确认同一ACK；下一帧两值同步；控制冲突整批拒绝且没有write；整批型号应用、型号叠加转自定义；保存重载一致，页面错误为空。
- `artifacts/device-batch-preview-1080p.png`已检查，逐设备预览表与确认按钮可见。
