# 热耦合作者设备与房间自动温控实施记录

日期：2026-10-30。起始提交：`ec3edf3`。用户已要求同时实施两条主线，并按可验证的小阶段多次提交。

## 目标与分工

| 主线 | 交付目标 | 范围 |
| --- | --- | --- |
| C：热耦合液体侧 Python 设备 | 自写水力设备可在制冷站与二次液体网络联算中使用，具有完整生命周期和可复用项目 | 从无独立储量的阻力/阀门设备开始；采用公共 SDK、独立 Worker、全局接受与失败回滚 |
| R：房间自动温控 | 在现有空气/冷冻水/冷却水三回路中反馈室温、调节水阀，并交付完整控制案例 | 固定风量、机组连续运行；初始降温、负荷变化、设定变化，校核最小流量和所需旁通 |

两个实现代理分别负责 C 与 R，主代理负责共享文件、提交、检查整合和最终验收。两项不互为物理前置。执行范围沿用 [平台能力表](PLATFORM_CAPABILITIES.md) 和 [三回路说明](CHILLER_AIR_LOOP.md)，本阶段只更新实际验证通过的能力。

## 分阶段交付

1. C1：定义支持条件，接入嵌套求值与液体模块事务；验证真实 Worker、成功接受、失败回滚和重复试算不重复累计。
2. R1：构建有物理依据的温控案例，绑定真实变量与执行器，验证控制方向、设定量纲、容量边界及典型扰动。
3. C2：提供可编辑模块和完整项目，检查控制、保存重载、模块版本、导入导出、冻结历史及实际浏览器流程。
4. R2：接入创建/导入入口和结果，提供可修改控制参数、完整运行时长、温度/设定/阀位/冷量/耗电及场景比较。
5. I：整合测试入口与生成合同，执行定向物理与工作流检查、后端全量及覆盖率、完整浏览器链、静态和类型检查。
6. D：登记实际结果与限制，同步能力表、路线图和使用入口，提交最终验收。

每个可独立审阅的实现阶段分别提交。实现代理只修改约定文件，主代理串行暂存和提交，避免共享工作区中包含其他主线未完成的文件。

## 验收重点

- C：同一候选物理状态用于 Worker 求值；全局成功前不提升模块状态或累计量；失败重试、停止、同步失败和构造失败具有明确生命周期；非法模块在计算前拒绝。
- C：独立公式或内置等价设备给出数值参考，既有纯内置热耦合和制冷站行为保持可复现；模块标识不参与物理选择。
- R：在容量足够的工况下显示明确的室温调节过程，记录温差、超调/稳定过程、执行器限制和耗电；超出能力时如实显示结果。
- R：用户修改设定、保存重载、导入导出及历史比较采用正确的项目和控制快照，不绑定示例固定编号。
- 界面使用 1920×1080、DPR=1 验证。后端全量与完整浏览器回归顺序执行，避免进程清理检查受并行任务干扰。
- 测试参考采用工程假设和独立公式，结果不登记为厂家或现场标定。

水侧储热、机组启停、独立湿度控制、第二类制冷作者角色、DX 过热度控制不属于本次两条主线；既有取消项保持此前决定。
