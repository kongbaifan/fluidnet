# FluidNet 与倍思鹿的当前差异

> 本文比较的是本轮开发前的 v0.4.6 基线。Python 控制与可靠保存随后已接通，当前行为见 README 和 ROADMAP。

核对日期：2026-10-15。FluidNet 基线：`fluidnet-prototype-engine` v0.4.6，提交 `5c05c79`。近期架构和路线图修改属于文档，Python 项目控制脚本、运行持久化等计划项尚未作为已实现能力计入。

本次重新读取倍思鹿官网 12 篇公开教程，正文与仓库 10 月 9 日缓存一致；阅读并逐页查看了本地 V1.1 说明的全部 8 页。官网安装教程当前列出 6.29 下载，其他文章涉及多个版本，因此下表比较的是公开材料明确描述的能力，不将全部材料视为同一发行版的完整验收结果。未运行倍思鹿软件，未取得 NET 内核源码或双方同工况的性能对测。

## 判断

FluidNet 已具备真实建模、管网求解、Python 模块开发、动态控制与外部变量接口的主要链路。相较早期原型，REFPROP、多工质、模块实际执行、后台运行和变量读写已补上。

倍思鹿公开资料呈现的覆盖面更广，主要体现在工业设备模型、项目控制脚本、设计函数与断点调试、外部设备/程序接入，以及 Windows 发布部署流程。FluidNet 当前侧重单相管网、明确的数据合同、可追溯模块版本和可验证的计算边界。

## 计算架构的具体差别

**倍思鹿参考架构**：主控 EXE 解析拓扑；不同模块 EXE 并行计算，主控检测模块完成后调用 NET DLL，再进入下一轮。数据 DLL 提供模块变量和控制指令的统一读写入口。说明允许轻量模块合并、重型模块单独执行。[P，第 1、3–4 页]

**FluidNet 当前架构**：FastAPI 接入，RunManager 调度动态会话，SimulationSession 管理状态/PID，SciPy 求解全网水力与热力。自定义 Python 模块通过行式 JSON RPC 提供设备关系，成功子步再提交状态。内置设备在主服务中计算。

| 具体项 | 当前差别 |
| --- | --- |
| 全网数值方法 | 我方可确认是 SciPy least_squares，默认 dense、可选 sparse Jacobian；参考资料没有足够信息还原 NET 的内部算法 |
| 支路定义 | 参考说明将多个串联设备通路组成一条计算支路；我方每条启用的设备通路形成一个 CompiledBranch，尚未做串联压缩与连通分块调度 |
| 并行粒度 | 参考架构按模块程序分工；我方有 2 个后台计算线程，Python 模块可按 1–16 个 Worker 分片批量求值，默认 1 片。每实例状态独立 |
| 数据交换 | 参考走原生 DLL/PIPE 等接口；我方内部 Worker 采用 JSON 管道，对外使用 HTTP/WS；调用频率、数据体积和一致性语义都不同 |
| 状态提交 | 我方显式区分重复 evaluate 与成功子步 commit_step；公开材料不足以确认参考系统在失败重试中的完整状态提交规则 |
| 模块追溯 | 我方项目绑定完整模块快照与双哈希，后续发布不影响旧项目；参考教程没有足够版本策略细节支持同级比较 |

## 三处需要避免混淆的比较

### 两相物性与两相流网络

倍思鹿入门文章明确写着“目前还没做到两相流计算的底层支持”。冷库案例可以在设备模块里描述气液状态、罐体和制冷循环；这些内容不能单独证明具备通用两相管网求解器。该案例也列有模型简化，AI 训练与效果检验仍在进行中。[B00][BC]

FluidNet 可查询两相物性，但网络流动只支持与所在回路边界一致的单相。当前计划明确排除管网两相流、水锤和完整可压缩流动；若目标转为覆盖复杂制冷或燃气案例，需要另设物理模型项目。

### 容量、读写速度与求解速度

| 资料或实现中的数字 | 正确含义 |
| --- | --- |
| 倍思鹿 V1.1 的 10 个项目、1110 支路槽位、每支路 55 个单元、单项目 40000 模块槽位 | 该说明中的接口数组配置，不能当作同规模实时性能验收 [P，第 5–7 页] |
| 倍思鹿的小项目约 200 次迭代/秒、大项目 30 次以上/秒 | 作者报告，缺少本次可复现的统一算例、精度和硬件条件 [P，第 1 页] |
| 倍思鹿数据 DLL 的 800 万次读写/秒、曲线文章的高频刷新数字 | 变量访问或曲线通道指标，与一次全网物理求解不是同一测量对象 [P，第 7–8 页][B07] |
| FluidNet 后端最多 1000 实例、最多 20 个活动后台运行 | 当前模型及运行管理配置；不表示 20 个复杂项目能同时满足实时节奏 |
| FluidNet 画布每页最多 64 个设备、每项目最多 8 页 | 当前前端限制，需要与后端容量分别说明 |
| FluidNet 文档记录 1000 实例串联网络 sparse 约 2.33 秒 | 特定机器上简单管网的既有基准；本次未重跑，不能推广至复杂环网/自定义模块，更不能与上述参考指标直接相除 |

如需比较速度和精度，应先统一拓扑、设备曲线、工质、初值、边界、状态模型、容差、输出频率与硬件，分别测量求解时间、RPC、历史记录和界面开销。

### 界面重连、历史保存与跨重启续算

倍思鹿部署教程描述了关闭界面不影响后台、重新打开界面恢复显示；型号教程明确描述磁盘 JSON 保存。V1.1 PDF 第 8 页同时写明其调用说明尚未涉及工况保存设计。现有材料不足以确认所有变量历史的磁盘保留策略或任意时刻的跨进程重启续算。[B05][B09][P]

FluidNet 已有页面关闭后后台继续运行、浏览器项目/结果保存和磁盘模块版本。服务运行记录仍在内存，服务重启清空；[后续计划](ROADMAP.md) 中的持久历史和检查点必须分别实施。不能仅根据双方都使用“数据库”“恢复”字样推断行为等价。

## 目前值得保留的基础与下一步

我方已经形成的基础包括：Pydantic 严格合同与自动生成接口说明、显式单位、草稿/应用语义、模块版本快照与双哈希、受限参数写入和可关联命令回执，以及成功子步提交状态的约定。这些是本项目可验证的工程特性；不据此推断参考软件没有相应机制。

同一代码基线在本会话此前完成度评估中通过 276 项 Python 测试和 8 组浏览器验收，包含 REFPROP、动态状态、模块版本和访问接口。本次比较复用该验证记录，没有重复执行，也没有把它作为双方精度对测。

下一步按使用目标推进：

1. **本地单相管网工具**：落实既定的数据保存、发行包和试用验收，形成稳定交付。
2. **可编程控制与数字孪生**：落地已选定的 Python 项目控制脚本，完成变量映射，再针对一个确定协议接真实设备。
3. **工程模型复用**：补设计函数、源码调试工作流及有真实算例支撑的止回阀/压缩机等模型。
4. **复杂制冷或燃气应用**：把闭式容器、可压缩管道、动态组分及必要瞬态物理分别立项，重新确认范围、公式与验收数据。
