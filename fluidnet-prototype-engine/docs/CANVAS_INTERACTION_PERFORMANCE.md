# 工程画布交互性能记录

2026-11-06。本轮扩充已有 [30/100/300容量记录](LARGE_PROJECT_EDITING.md)，单独测量实际拖动、平移、缩放及撤销重做。未改变前端每页64台、每项目8页的容量合同，没有运行1000台同屏测试。

## 测量方法

`node tests/browser-canvas-performance.mjs` 启动隔离服务和 Edge 无头浏览器，1920×1080、DPR1。输入是两端压力边界与双口水管组成的简单串联项目：30/64实例单页，100/300实例分为2/5页，每页最多64台。全部通过界面导入，不直接写应用状态；测量期间没有运行仿真。

每规模三轮：分别拖动两台设备（每次24个鼠标移动步骤）、空白平移、放大/缩小、撤销/重做和保存。鼠标松开前检查被拖节点及其子元素仍是原DOM对象，其他节点不移动，关联路径端点跟随；松开后检查全部已绘制边端点与实际端口一致。

浏览器 `requestAnimationFrame` 记录交互期间帧间隔，`PerformanceObserver`记录长任务。统计包含自动化、断言及鼠标松开后的页面重绘开销，不是纯算法耗时或持续拖动帧率。最后一轮本任务没有其他浏览器测试或后台求解并行；其他系统负载未控制。

环境：Windows，AMD Ryzen 7 5800H，16逻辑处理器；Node v24.15.0；Edge 158.0.4370.1。基础提交 `4a521e3` 加本轮未提交画布改动，原始记录同时保存具体源码SHA256与dirty路径，不能把结果当作未经修改的HEAD性能。

## 最终观测

| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 30 | 1 | 30 | 29 | 7.0 ms | 7.4 ms | 34.9 ms | 0 |
| 64 | 1 | 64 | 63 | 7.0 ms | 7.4 ms | 55.4 ms | 3 |
| 100 | 2 | 64 | 63 | 7.0 ms | 7.4 ms | 48.8 ms | 2 |
| 300 | 5 | 64 | 63 | 7.0 ms | 7.4 ms | 55.0 ms | 1 |

全部交互与端点/DOM身份断言通过，页面异常为空。仍存在长帧及长任务，因此不宣称所有操作无卡顿。与此前容量记录的“组操作2202ms”测量对象不同，不直接计算优化倍数。

本轮实际优化是拖动过程中按绘制帧合并更新、只移动当前节点并重路由关联边；松开后完整重算避障，结果刷新只更新观察图层。图形渲染仍使用SVG/DOM。

未覆盖：单页超过64台、复杂Python/制冷模块规模、运行中大量动画与曲线叠加、多种GPU/机器、人工操作体验统计、长时间稳定性。后续有具体场景时再补该场景，不由这些数据推断支持任意规模。

原始产物：`artifacts/canvas-performance-metrics.json`（每轮原始帧间隔、操作耗时、长任务、环境和源码哈希）、`artifacts/canvas-performance-1080p.png` 及视口证据，均为本地生成物。源码入口加入 `npm run test:browser:canvas`，不加入本轮全量执行承诺。
