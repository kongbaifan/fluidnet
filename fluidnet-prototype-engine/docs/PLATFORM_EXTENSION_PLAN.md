## 1. 本阶段目标

让工程师通过现有界面和公共 Python SDK，自行编写设备算法、验证设备、保存版本、组建项目并复算。平台继续负责网络协调、状态推进、物性、控制、数据存储和结果展示。

主线顺序为：**核对并补齐现有自主建模流程 → 开放一类制冷站 Python 设备 → 完成作者验证、版本复用和项目运行。**

完成时交付两条可重复操作的作者流程：

1. **单相网络流程**：从模块模板创建自定义阻力设备，配置参数和预期结果，发布版本并插入自建项目；封装包含该模块的组合，保存、导出、重载、升级和回退后仍能计算。使用不同于内置示例的实例 ID，结果与控制引用随实际项目绑定。
2. **制冷站流程**：工程师用公共 SDK 编写两端口等焓节流设备，在现有 NH₃/CO₂ 制冷站中替换一台内置节流阀；修改开度特性、发布新版本、比较运行结果。新增这个作者模块不需要修改引擎目录、求解器分支、前端设备 ID 清单或专用结果页面。

第二条首批限定为无独立物理储量的等焓节流设备。完成它表示制冷站具备一类受支持的设备扩展接口；其他制冷设备的扩展范围另行列明。

## 4. 首类制冷扩展设备的约定

以下为设计要求；RF-0 已验证运行与事务可行性，建议 schema 4 / SDK 0.7.0 的正式角色合同，详见[设计记录](REFRIGERATION_EXTENSION_DESIGN.md)。RF-1 已实现正式合同、SDK 与独立 Worker 调用；正式项目运行、验证台与发布的当前状态见[RF-2/RF-3 交付](REFRIGERATION_MODULE_EXECUTION.md)。

### 4.1 设备职责与物理范围

- 选择现有制冷站 `expansion_valve` 对应的两端口角色：上游为饱和容器液相取液，下游为合法的另一压力等级。继续沿用现有制冷剂回路与容器约束。
- 作者可定义开度与有效 Kv 的关系。首个模块保留现有单向流动、零开度关断和等焓节流假设；不增加出口过热度控制、闪发管道或流动壅塞模型。
- 由平台提供同一次候选求值的上/下游压力、上游液体比焓/密度、工质、参数和执行身份；数值单位固定为 Pa、K、kg/s、J/kg，显示单位由现有合同转换。
- 作者返回受约束的流量及派生量。等焓流股使用平台给定的上游比焓，平台统一向两个容器写入相反的质量与能量通量，防止作者重复记账或更改容器状态。
- 容器质量/内能、库房温度及积分仍由原制冷站执行器负责。首批设备不新增独立物理状态、压力未知量或时间积分器。累计通过量等观察状态沿用受管理接受机制。

### 4.2 生命周期与故障边界

- 用户代码只通过独立 Worker 执行；公共作者模块使用 `fn_sdk`，不能通过导入 `fn_engine.refrigeration.devices` 包装内置函数来充当扩展验收。
- 牛顿迭代、有限差分探测和步长重试只能生成候选值；不得推进累计量、控制时钟或已接受模块状态。
- 接受时将设备状态、容器状态、控制输出、参数修订、运行时间和结果帧一并提升。错误或超时保留最后已接受状态并按既有故障策略结束运行；恢复范围必须在文档中明确。
- 观察字段读取同一已接受设备结果，报告和历史目录不得重新运行当前模块源码。
- 首次目标为纯 `refrigeration` 项目；`thermal`、`coupled` 及湿空气项目的适用性须显式判定。未验收的组合在编译阶段拒绝，旧内置项目保持可用。
- 复用既有 Worker/RPC、版本、诊断和模块发布机制；新增的是制冷设备角色与适配，不另建一套模块仓库或发布系统。

### 4.3 作者界面

- 模块模板说明支持的物理设备和工况，参数、端口与输出沿用现有编辑器。
- 制冷设备独立验证采用物理合法的制冷边界，不能直接套用水力验证台后显示通过。
- 用户能看到实际值、预期值、误差、失败原因和源码定位。超出支持范围时指出具体设备及不满足的工况。
- 项目插入、参数编辑、控制绑定、变量选择和报告均由合同驱动；新模块标识不得触发专门的前端分支。
- 所有新增界面沿用 **1920×1080、16:9、DPR=1** 的验收基准。

## 5. 必须通过的验收场景

| 场景 | 验收要点 |
| --- | --- |
| 原作者流程 | 使用自定义模块/实例 ID 从创建到保存、复算和复用；确认没有依赖示例名称、固定曲线或隐藏参数 |
| 独立数值参考 | 节流流量与独立 Kv 方程、等焓关系一致；至少覆盖零/中间/全开度、无正向压差和多个合法压力点；参考结果不得由被测模块调用生成 |
| 完整站替换 | 在同一冻结项目中对比内置节流阀和等价 Python 版本，检查关键流量、压力、液位、库温及全站质量/能量账；沿用现有相应容差，不因新接口放宽 |
| 作者修改算法 | 切换开度特性后结果按独立公式变化；相同模块用于第二个项目时无需修改引擎代码 |
| 动态与控制 | 控制输出调节已声明的运行参数，设定/负荷变化后接受状态连续；设备限幅和能力限制真实反映到结果 |
| 失败与重试 | 非有限值、非法单位/类型、不支持的角色、越界输出、源码异常、超时、过期候选和重复消息均有明确结果；失败步不重复累计、不提升时间或容器状态 |
| 版本与持久化 | 编辑草稿不改变已有运行；新版本由项目显式采用；旧运行、报告、批次及重载结果仍使用旧快照；回退同时核对控制和变量引用 |
| 不支持的组合 | 把新制冷模块放入未支持执行域或热耦合项目时，在求解前给出可定位诊断；不产生“部分执行成功”的误导结果 |
| 性能与资源 | 固定同机环境测内置版/Python 版的典型 B 案例，分别记录初始化、固定候选工作点求值、动态耗时、真实 RPC 次数、迭代次数和峰值内存；检查 Worker 结束回收。RF-0 冻结测量配置与可接受预算，超预算先修复再交付 |

性能测试复用现有计数与基准工具，记录预热和重复次数；不以一次运行宣称加速，也不恢复 24 小时稳定性专项。
