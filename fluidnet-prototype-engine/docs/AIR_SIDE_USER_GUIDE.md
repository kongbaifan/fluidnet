# 风系统使用说明

适用于风侧合同 1、SDK 0.6.0。以源码服务运行，页面验收基准为 1920×1080。

## 从示例开始

1. 启动 `python -m fn_engine serve --host 127.0.0.1 --port 8798`，打开 `http://127.0.0.1:8798/#air`。
2. 选择“创建风侧示例”，可创建盘管、混合箱、完整 AHU、房间、并联系统或冷却塔。
3. 在“编辑拓扑”中双击设备，修改草稿参数并应用；回到“风系统”运行计算。
4. 查看风量与状态、湿空气状态图、设备与水耗。CSV/HTML 按所选运行的冻结目录导出。
5. “保存项目”保存参数、模块快照和页面配置；“批量方案”可扫描机器露点、BF、加湿量、过滤器污堵或房间负荷。

文件入口见[六个规范及原型示例](../examples/air-side/README.md)。每次运行绑定已应用参数；尚未应用的设备草稿不参与计算。

## 状态、流量与单位

湿空气项目必须同时设置 `moist_air=true`、`moist_air_options.contract_version=1`、`thermal=true`、`property_coupling=node`，工质为 `Air/gas`。普通水系统继续使用原设置；湿空气冷却塔的项目工质是液态 Water，塔内部另查湿空气。

| 变量 | 规范单位与含义 | 页面显示 |
| --- | --- | --- |
| `humidity_ratio_kg_kg` | kg 水/kg 干空气 | g/kg_da |
| `relative_humidity` | 0–1 | % |
| `mass_flow_kg_s` | 当地湿空气总质量流量 | kg/s |
| `dry_air_mass_flow_kg_s` | 干空气质量流量 | kg_da/s |
| `enthalpy_j_kg` | 每 kg 当地混合物的比焓 | kJ/kg |
| `enthalpy_j_kg_dry_air` | 每 kg 干空气的比焓 | kJ/kg_da |
| `volume_flow_m3_h` | 实际入口体积流量，已经是 m³/h | m³/h，勿再乘 3600 |
| `dew_point_k` | 露点；无水蒸气时为空 | °C 或“—” |

端口流量以流入设备为正，通路流量以声明的入口→出口为正。加湿和除湿会改变湿空气总质量，干空气质量流量保持一致。混合箱的入口显示实际入流流股，出口显示混合状态。

“相对湿度换算”按边界当前已应用的温度与压力生成含湿量草稿。存档只保留含湿量，不保存互相矛盾的 RH/w 双重输入；修改温度而保持 w 时，RH 随状态变化。

## 设备与模型边界

- 表冷器：规定机器露点和 BF，干区只降温，湿区在 h/w 空间混合。`total_heat_w = cooling_load_w + condensate_enthalpy_flow_w`。无冷却时 SHR 为空；不支持结霜和反流，不包含真实冷水侧/制冷剂侧工作点。
- 加湿器：`adiabatic` 为零参考焓注水的教学等焓模型；`isothermal` 输出维持温度所需补热。`saturation_action=limit` 输出实际加水量及限幅标志，`error` 拒绝超限。普通风管节点不自动消除过饱和水分。
- 风机：新版默认按入口真实密度和实际体积流量计算工作点。参考密度模式会提示假设。进入空气的水力功、轴功和电功分别记账。
- 房间：固定有效干空气存量、完全混合，温湿度和附加热容按隐式 Euler 更新。围护显热、人员/货物散湿、平衡渗透分别入账；真实新风已由风管进入时不要重复填写同一渗透量。持续散湿且无排湿的封闭房间没有稳态解。
- 冷却塔：新的 `cooling_tower_moist`，保留原 `cooling_tower`。空气为规定流股，当前没有风管空气端口。输出蒸发、飘水、排污、补水、实际浓缩倍数和独立残差；无法排热时明确失败。接触效能不是厂家 KaV/L，不能用于填料或厂家选型。

物性产品包络为 60–120 kPa、−20–60°C、0–0.05 kg/kg_da，且必须未过饱和。盘管和房间另有较窄温度边界。局部风速超过 30 m/s 警告，超过 100 m/s 拒绝。串联压缩、分块、混合解析 Jacobian 和迭代加速在湿空气模式下明确拒绝；普通干工况保持原实现。

## 动态、历史与对比

凝水、加水、能量、房间散湿和冷却塔水耗只在接受的子步累计，失败或缩步重试不重复计数。历史抽稀不会用曲线积分替换累计量。失败运行保留最后有效帧并标注运行未完整完成。

修改参数、拓扑或模块后，原结果显示过期。切换运行时会取消旧请求；结果页和报告依据所选运行的项目快照、物性版本和变量目录。最多叠加四次运行的同一变量，质量基准和单位必须兼容。

批量工况沿用 20 工况、16 观察变量上限，每个子运行固定同一修订、模块和控制脚本。不会把扫描值回写到原项目参数。

## 旧项目迁移

旧 Phase 2a 项目缺少 `moist_air_options`，启动新运行时会返回 `AIR_CONTRACT_VERSION_REQUIRED`。在风系统页使用“升级旧项目”先预览，再下载原项目备份并应用新草稿，随后保存新修订、重新计算。

迁移只自动升级哈希与已知历史包一致的官方模块。自定义源码或不同哈希的模块保留原样，需作者明确适配湿空气能力。四个官方模块的旧包在各自 `history/v1/`，旧干项目仍可用原始源码复算。历史运行不乘系数、不重写旧数值；缺少元数据的旧档案明确显示不可用的新目录能力。
