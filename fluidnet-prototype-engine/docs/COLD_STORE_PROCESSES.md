# 冷库热湿、货物、霜层与油路参考模型

日期：2026-11-08。入口为 `fn_engine.refrigeration.process_examples.process_example(hotgas=True, oil=True)`。
该工程由公开设备合同组装，采用 R134a 两库参考拓扑。几何、UA、货物、油和融霜参数为可编辑的自定义输入，不是厂家标定数据。

## 已接入的物理状态

- `logistics_cold_room`：空气/围护总能量、水蒸气质量、独立货物焓；门口内外密度差确定中性面，两侧干空气质量相等。输入、输出的水蒸气及焓分别入账。
- 货物采用集中焓法：未冻结显热、冻结潜热平台、冻结后显热三段；冻结温度、比热、潜热、质量及与库房 UA 均可配置。
- `frost_hotgas_cooler`：金属与霜/水的共同能量、霜水总质量、累计排水及排水焓。冻结水在 273.15 K 上存在显式熔化潜热平台；空气侧 UA 随霜层热阻降低。
- 热气进口与凝液出口须成对连接。热气侧实际压力、流量和出口焓参加图式网络，放出的热量进入盘管能量；不使用无来源的融霜热负荷。辅助电加热单独计入外部能量。
- `compressor_oil_system`：油槽、油分离器、贮液侧携油和每台冷风机的独立油质量/能量；携油、分离、回油、油冷却和冷媒传热分别计入对应库存。油积聚降低冷风机换热能力。

所有坐标通过 `PhysicalStateSpace` 声明单位、尺度和范围，进入 StationSession 的同一隐式向量；其非温度坐标以 `设备ID::状态名` 保存，不会作为普通库温重复计算热容。坐标量纲也参与步加倍误差接受。质量账同时给出制冷剂、水和油残差。

## 融霜与接受边界

融霜顺序为 0 正常冷却 → 1 预排液 → 2 热气/辅助电加热 → 3 滴水 → 4 再冷却 → 0。
请求采用上升沿锁存；一次持续请求只触发一轮。各阶段时长是明确积分边界，停供液和停风在相应阶段生效；其他库房支路继续求解。
固定步模式对“霜已融化且达到结束温度”的事件进一步缩短步长并重算，以 1e-5 J 的事件能量判别容差定位；再使用新阶段推进剩余时间。自适应模式的温度提前结束目前在外部分段的已接受端点判断，定位分辨率受分段长度控制，应按工况设置 `time_step.max_internal_step_s`。

过程模式在接受事务内复制并更新。失败试算不会提交库存、计数或模式；会话快照保存物理坐标、融霜锁存、阶段与时钟，运行时模型由冻结项目重建。CSV 与 HTML 报告从归档帧读取声明的过程变量，生成报告不再次运行过程模型。

## 方程和适用边界

货物与房间间的热交换、湿空气凝结到霜层、霜融化与水排出、油和冷媒间的换热均在两侧取相反符号。外部能量包括围护/外加热、门焓流、设备电功、冷凝器散热、油冷却和排水焓。

管网仍使用均相平衡 HEM，无气液滑移和流型关联。热气通道使用明确 Kv 参考关系及有限 UA，不包含可压缩临界流/声速限制；实际阀组选型需另外标定。油系统为集中库存与一阶输运，不计算油溶解性、润滑膜或真实油滴粒径。油路所在回路的冷风机须使用图式供回液，其他冷风机组合明确拒绝。

货物以单一等效冻结温度表达；不解析货物内部空间温度和冻结曲线。门交换假设准静态双向浮力流，不含人员/叉车扰动的细节；机械交换可作为显式附加参数。水分凝结当前由冷风机霜层接收，不另设墙面凝露库存。

## 验收

`python -m pytest tests/test_cold_processes.py -q`

覆盖：货物潜热平台、霜融化能量、关门/完全保护零交换、热气路径完整性、实际热气流量和热量、油/水/制冷剂质量和总能量账、重启续算、失败回滚、固定步内融霜终止定位，以及归档 CSV/HTML 保留过程数据。
完整油路工况 0.1 s 隐式步的质量残差约 2e-13 kg、能量残差约 8e-9 J（本机一次运行值）；这些是数值守恒证据，不是工程准确度或实测误差。
