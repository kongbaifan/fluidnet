# 倍思鹿借鉴：选型、通路追踪与失败复现

日期：2026-11-05。本轮按用户确认的三个优先项实施，将现有设备模块、设计函数、型号库、画布和独立验证台衔接起来。

## 已实现的操作

| 入口 | 用户可以完成的任务 | 行为边界 |
| --- | --- | --- |
| 设备参数面板 → 设备选型 | 按显示单位填写设计条件、选择工质、计算并预览；保存为型号并填入设备草稿，再明确应用 | 使用项目绑定的设计函数版本；计算/取消不改实例；无设计函数的模块给出说明。新增`design_valve`液体流量/压差选型示例，不宣称全部设备已有选型算法 |
| 画布端口悬停或键盘聚焦 | 查看设备内部通路、高亮相邻外连线和远端口，点击目标跳到另一画布 | 使用真实声明通路，换热器两侧隔离；范围为当前设备内部及外部一跳，不表示瞬时流向 |
| 作者错误/独立验证失败 → 带入验证台复现；失败运行档案 → 查看模块失败输入 | 查看当时的参数、状态、端口/通路、阶段/时刻、冻结源码与错误行，独立执行捕获回调 | 不重算原网络，不替换模块库草稿，不推进原运行；没有完整回调快照时明确说明无法精确复现 |

分别见[设备选型](EQUIPMENT_SELECTION.md)、[通路追踪](CANVAS_PATH_TRACE.md)、[失败回调复现](MODULE_FAILURE_REPLAY.md)。本轮没有扩展此前暂缓的外部设备联调或打包发布。

## 失败复现的来源与接口

`POST /api/v1/modules/replay`接收`{replay: snapshot}`；`GET /api/v1/runs/{id}/module-failure`读取归档中的单份失败快照。普通运行状态与历史帧不重复附带整份模块源码。

快照在回调执行前复制，包含冻结模块与双哈希、参数、受管理状态、各端口工质、试算端口/通路和执行上下文。支持`initialize/evaluate/thermal/observe/jacobian/commit_step`；原执行阶段、迭代编号、实际时间及步长由捕获上下文提供，不能用最后接受帧代替失败试点。复现前校验格式、体积、状态和哈希。

在新Worker内只执行对应回调，后续阶段不重新初始化；回调返回的状态只作为本次结果展示。错误代码、消息、源文件/行号和阶段匹配才标为“复现同一错误”；回调成功不表示原网络已修复。`self`、全局变量、随机数和外部IO状态不在此受管理状态恢复合同内。源码加载失败、超时、平台求解失败或旧格式快照不能冒称已取得完整回调输入。

前端复现视图保留独立副本；模块库或编辑器后续变化不会覆盖它。切换失败快照后，旧请求不覆盖新视图；离开档案页后迟到响应不抢回验证台；归档读取失败也不会将既有复现按钮永久锁住。
