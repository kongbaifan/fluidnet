# 模型入口、算法说明、保存回执与六库首屏修复

日期：2026-11-13。分支：`codex/desktop-ui-refinement`。范围来自[桌面与 EXE 全面检查](COMPREHENSIVE_DESKTOP_REVIEW_2026_11_13.md)中的 D01、D02、D03、D04，界面只按 1920×1080、DPR 1 验证。

## 实际行为

### 模型入口

可计算状态由当前计算目录的注册模型标识决定，Python 模块还需有已发布版本或已冻结的项目定义。不按显示名称猜测模型，也不维护第二份可计算设备名单。

- 旧 `check`、`sensor`、`pid`、`refprop` 保留为参考对象，模块卡片显示限制和替代入口。
- 设备库中的参考行打开说明，不进入放置模式，不提供设备拖动数据。
- 实际插入计划仍检查注册状态，直接插入、画布点击及拖放不能绕过检查；已有项目和参考内容不自动改写。
- 止回阀替代入口按当前画布的端口类型提供水网止回阀或制冷剂止回阀。测点与 PID 转到控制页，物性参考转到介质与单位设置。
- 未发布的 Python 模块继续引导校验与保存，已冻结项目定义仍可按原版本复用。

主要实现：`frontend/project-model.js`、`frontend/module-service.js`、`frontend/studio.js`。目录状态只影响入口与插入，不改变已冻结模块的方程或物理参数。

### 算法编辑表达

内置设备的“算法”页改为“算法说明”，主位置明确“内置算法说明 · 只读”，说明文本不参与真实运行。运行关系、公共声明和设计函数参考都可以阅读、选择及复制，但不能通过输入、Tab 缩进或变量插入改写。

移除该页用于插入变量、检查/调用文本的编辑操作；保存按钮明确为“保存工作区”。“新建 Python 模块”提供真实算法作者路径。Python 模块保留可编辑源代码、校验和版本发布，原有内置说明文本与草稿不被重写。

主要实现：`frontend/module-editor-view.js`、`frontend/studio.js`、`frontend/desktop-workspace.css`。

### 保存与载入回执

服务层对工作区身份和载入代次建立票据。工作区或项目对象被替换后，旧响应不能写入当前对象的 `workspaceRevision`、`projectRevisions`、`projectSavedKeys`，也不能将新对象标记为已保存。排队中的旧保存在发送之前被拒绝，后续新工作区保存不会被旧队列卡住。

覆盖工作区保存/载入、项目保存/恢复/删除，以及修改修订信息的项目读取。最新载入请求拥有呈现权，过期载入的失败也不会影响新的成功连接；当前对象的正常保存仍更新回执元信息，保存期间的新编辑继续保留，其结果不被错误登记为已保存参数。

真实浏览器验证在延迟发送已提交保存的回执期间，通过界面恢复内置示例。旧回执到达后，替换后的工作区仍显示未保存。再次保存按替换后已知修订发送，服务器修订冲突明确失败，草稿保留；不会用过期回执自动授权整份覆盖。

主要实现：`frontend/project-services.js`。服务器原有修订冲突检查、工作区草稿保存和恢复合同继续保留。

### 六库首次画布

六库自动温控与持续仿真示例在首次保存及 `openProject()` 渲染之前，完成新工程所有页面的 `fitNetwork()`。因此首屏 SVG 使用实际设备边界，页面的 viewBounds、zoom、pan 与保存数据一致。

1920×1080 实际首屏结果：

| 示例 | 当前页设备 | 首次完整显示 | 保存重开 |
| --- | ---: | ---: | --- |
| 六库自动温控 | 21 | 21 | 保留拟合视图 |
| 六库持续仿真 | 42 | 42 | 保留拟合视图 |

这是当前页的显示数量，不是完整工程设备总数。本轮没有修改设备位置、连接、求解设置或算法。

主要实现：`frontend/cold-storage.js`。
