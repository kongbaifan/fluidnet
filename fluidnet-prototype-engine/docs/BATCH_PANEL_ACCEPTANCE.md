# 多设备编辑与面板配置验收

2026-11-05。按用户确认实施多设备批量编辑、按模块配置设备面板两项。继续使用已发布模块合同、显示单位、项目冻结快照和参数应用回执；未运行全量测试。

## 使用入口

- 建模工具栏“批量编辑设备”：按模块选择跨画布的多台兼容设备，勾选共同修改字段或选择统一型号，逐台核对已应用值/草稿/拟应用值后确认。
- 模块编辑器“配置设备面板”：配置该版本以后插入的默认布局。
- 设备参数页“配置此项目面板”：配置当前项目中该模块的常用参数、控件、结果顺序及分组。

详细操作见[批量编辑](DEVICE_BATCH_EDITING.md)、[面板配置](CONFIGURABLE_DEVICE_PANEL.md)。每批要求同模块兼容版本；没有选择的参数、设备自定义变量和三组库值保持原值。型号参数另行修改时明确转为自定义配置。面板字段最多12个常用参数和12个结果，完整参数页仍可访问其余字段。

## 原子应用与兼容性

前端在任何写入前校验全部设备、类型/范围、单位、模块/型号版本、控制接管和运行可写权限。旧显示键与规范参数键若映射到同一个参数则拒绝歧义，不允许后端只收到一值而本地留下两值。活动运行使用一次`write`命令；同一应用回执后才一次提升本地参数。批量与单设备应用共用设备锁。等待期间新输入的草稿保留，过期项目/运行/设备对象不得接受迟到响应。

后端补齐了原批量路径的RPC故障回滚：先同步全部Worker，全部成功后才提升网络参数、物理副作用和控制器配置；中途失败恢复此前及失败设备的旧参数，保持修订号和接受状态。恢复无法确认时终止运行，保留最后接受帧及其非零修订号，命令仍记为拒绝，不能继续用部分更新的执行器求解。网络回执超时仍属未知结果，前端提示查询事件，不把超时宣称为已回滚。

面板配置位于UI模块包装对象`panelLayout`，按模块版本、双哈希及字段结构绑定，不进入物理manifest或其哈希。已有项目保留原布局；字段/版本不匹配时回默认并提示。工作区及单项目封装保存展示配置；规范计算Project保持计算合同，导入后使用默认显示。

验收还复现并修复了同内容刷新时的重复备份配额问题：已有约3.2MB工作区与服务端内容相同，仅保存回执字段不同，重复写第二份会超过浏览器默认配额。现在在同一恢复事务中规范化后比较，只有完整内容相等才跳过重复备份，比较仅忽略顶层`savedAt/workspaceRevision/projectRevisions/projectSavedKeys`；所有参数、草稿、布局、代码、运行内容与dirty标记继续严格比较。实际差异仍走原备份保护，既有备份不删除。

## 实际验证

- 前端批量事务、批量UI、面板配置及已有单设备事务/面板回归合计27项通过。覆盖新草稿保留、拒绝不变、迟到响应、互斥、单位、只读和控制接管、型号版本、参数别名冲突。
- 工作区等价判断、原草稿缓存与连接/修订冲突定向12项通过，确认不以相同修订号或dirty标记替代内容比较，备份失败恢复旧state和参数定义。
- 后端故障注入与原批量拒绝路径合计15项通过；最终新增故障文件8项单独复验通过（13.32s）。包括独立/共享/分片Worker、丢回执、恢复失败停机、组合映射及物理副作用恢复。这两组有重叠，不累加为唯一用例总数。
- `browser-device-batch.mjs`真实UI通过：双阀跨页、取消、未选草稿保留、暂停单次write及同ACK、下一帧双值同步、控制接管整批拒绝、统一型号/自定义覆盖和重载，页面错误为空。
- `browser-panel-layout.mjs`真实UI通过：库默认、新实例继承、旧项目隔离、项目覆盖、真实运行权限、保存重载和单项目封装导出导入，页面错误为空；最终复验确认同内容刷新不再出现重复备份配额告警。
- 相关JS语法、ruff、mypy126个源码文件及94份生成合同检查通过。截图使用1920×1080、DPR=1。

专项入口：`npm run test:browser:batch-and-panels`。本轮两个脚本分别执行，未执行全量浏览器链或全量pytest。当前代码仍保留在本地工作树。
