## 数据来源与流程

通过“导入单项目”上传规范 Project：压力边界 → 调节阀 → 压力边界。所有物理读数来自实际后台动态会话及已接受帧，没有向前端 state 注入结果。前端检查依赖已有 `/runs`、暂停/继续/停止和工作区保存接口。

| 检查 | 实际结果 |
| --- | --- |
| 未运行 | 连接值未知，无流向箭头或流动动画 |
| 正向连接顺序 | 质量流量约 3.54415207957 kg/s；两条边方向均为 +1 |
| 反转连接的 source/target 存储顺序 | 同一物理状态与流量；两条边方向均为 −1，说明方向不由连线编辑顺序决定 |
| 阀门关闭 | 质量流量 0；方向为 0，无箭头 |
| 温度与压力 | 标签读取真实端口，温度换为 °C、绝压换为 kPa(abs)；更改色标只截取颜色，不改读数 |
| 显示配置 | 切换物理量、数值标签和色标前后，模块快照、参数、拓扑、工质和求解设置完全一致 |
| 动画 | 实际运行时出现；取消动画或暂停后停止 |
| 结果过期 | 停止运行后修改已应用阀位，旧结果不再提供方向和动画，显示结果已过期 |
| 保存重载 | 三个项目分别保存并刷新，物理参数与连接不变 |
| 真实设备警告 | 使用冻结的 `capillary_tube` v1、长度 0 的原有数值下限警告；Worker 发出 `CAP_LENGTH_CLAMPED` 后设备变为警告色，可由告警列表定位并打开实例 |
| 初始化失败 | 使用下述已知边界触发 `HYDRAULIC_NOT_CONVERGED`；无物理帧时保持未知和无动画，系统诊断没有实例归属时不伪造定位目标 |

## 观测适配边界

`canvas-observations.js` 的 13 项定向单测覆盖真实带符号端口流量、零流、缺失/非有限值、明确通道回退、多通路隔离、制冷聚合值不当作逐口流股、热连接不臆测方向、端点不一致、规范单位、真实上游端点、失效帧、图例范围及状态来源。

设备运行状态只读取模块声明的实际输出或关联诊断；`running` 等参数设定不是实际运行状态。静态边界和未提供运行标记的设备显示未知，不按流量或图形猜测启停。热连接暂未建立统一逐口热流符号合同，保持未知。

## 发现的既有数值边界

最初用左右边界 120000/250000 Pa、20/40°C、阀开度 0.7、Kv=16 的三设备工程验证负流；动态初始化在 `reference` 和 `node` 耦合下均出现 `HYDRAULIC_NOT_CONVERGED`（压力残差 130000 Pa、质量残差 0、gtol）。本轮未更改求解器，也未将该工况计为反向物理求解通过。

可视化逆向浏览器测试改为反转连接存储顺序；适配器单元测试另验证负端口流量。原始失败输入和观察记录保存在 `artifacts/canvas-existing-boundary.json`，供独立数值排查。初始化失败分支同时用于验证画布不能在求解失败时展示伪流向。
