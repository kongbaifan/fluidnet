# 设备组网与运行仿真：使用步骤

更新日期：2026-11-12。三个代表场景的技术验收基线为 `edb8c2d`，见[核心流程与源码交付记录](CORE_WORKFLOW_ACCEPTANCE.md)；其后的工作区包含[界面说明清理](INTERFACE_COPY_CLEANUP.md)，以下操作使用清理后的名称。实际使用反馈另行登记。

## 启动

在 `fluidnet-prototype-engine` 目录打开 PowerShell。首次使用需要 Python 3.11 或更高版本；Windows 安装了 Python Launcher 时，可以明确选择已验证的 3.11 环境：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start.ps1
```

之后直接运行 `start.ps1`。脚本使用本目录的 `.venv`，默认打开 `http://127.0.0.1:8798`。如果没有 `py` 命令，使用 Python 3.11 或更高版本的完整路径创建环境；先检查版本，避免系统中的旧 `python` 被选中。只有 Node.js 开发检查需要 Node 24.9 或更高版本；正常启动服务不需要运行 npm。

希望先试用而不编辑已有工作区时，在依赖安装完成后执行：

```powershell
.\.venv\Scripts\python.exe -m fn_engine serve --port 8799 --data-dir .runtime/trial-workspace --module-dir .runtime/trial-modules --open
```

这个命令使用独立数据目录。以后用同一个命令重新打开，才能看到这份试用数据。默认工作区仍在 `.runtime/workspace`；不同目录的项目不会自动合并。

## 选择一个代表工程

| 场景 | 界面入口 | 先观察什么 |
| --- | --- | --- |
| A：基础泵阀管网 | 项目 → 打开“泵阀并联管网”；或新建项目，将“起始内容”选为同名示例 | 阀门开度、两支路流量、阀压降和泵轴功率 |
| B：单库房 | 项目 → “−18°C 冷库案例” | 库温、温控目标、机组状态、制冷量和电功率 |
| C：多页六库工程 | 项目 → “六库自动温控” | 六个库的目标和当前温度、控制状态、全站功率 |

B 自带库房、冷风机、机组三台设备及温控脚本；C 是 51 设备、72 连接、4 张画布和 19 个 PID 的自动温控版。两者都可以直接创建副本使用。另一个“六库持续仿真”是 126 设备专项，完整运行日尚待验证，第一次试用先使用表中的三个场景。

## 打开或搭建，检查连接

已有示例打开后，双击设备可以查看“总览”“参数与型号”和“连接”。设备太密集时，用工作台的全项目查找输入设备标识，例如 `V1`、`ROOM1` 或 `F01`，定位到设备及所在画布。

从空白搭建 A 时，可按下面的最小结构练习：

1. 新建项目，起始内容选择“空白画布”。从设备库插入两个压力边界、一个泵、一个阀和一段管。
2. 将入口压力边界接到泵 `in0`，泵 `out0` 接阀 `in0`，阀 `out0` 接管 `in0`，管 `out0` 接出口压力边界。压力边界的连接口是 `out0`。
3. 在设备“连接”页选择目标端口，或点击“连接端口”后点选两端。使用界面实际生成的设备标识。
4. 在两个压力边界的“参数与型号”中，把入口设为 201.325 kPa、出口设为 120 kPa，均为绝对压力，分别预览并应用；其余设备先保留默认值。这是该空白案例原验收采用的配置。
5. 点击“检查连接”，处理错误后重新检查，再返回工作台。检查通过说明配置可进入求解；实际运行仍可能报告工况或收敛问题。

空白单库房的连接是“机组 `cold` → 冷风机 `supply`”“冷风机 `heat` → 库房 `heat`”。只设置库房目标不会自动启停机组；初次使用 B 的现成温控模板即可。需要自行组装时，见[常用设备说明](COMMON_DEVICE_GUIDE.md)。

## 运行

工作台画布右侧点击“运行设置”，进入求解设置。短程试用可选择动态、关闭持续运行、计算节奏选“快速计算”：

| 场景 | 试用时长 | 输出间隔 | 说明 |
| --- | ---: | ---: | --- |
| A | 2 s | 0.1 s | 便于快速比较水力工作点 |
| B | 600 s | 30 s | 在工况下拉框选“基础模型”，先观察初始降温 |
| C | 600 s | 30 s | 保留自动温控及默认工况；原模板默认运行 3 小时 |

这些是短程操作验收的设置，不代表实际设备性能或长期温控结论。仿真时长与等待的真实时间不同；计算慢时以真实仿真时刻和状态为准，详见[运行推进说明](RUNTIME_FEEDBACK.md)。

点击“运行”。需要练习暂停和单步时，先停止，改为“按真实时间运行”并设置足够的仿真时长，再开始：暂停后状态保留，“单步”推进一次并保持暂停，“继续”沿用同一会话，“停止”结束会话。暂停期间连接、工况和其他结构设置仍锁定。

## 调参并确认生效

双击设备，在“参数与型号”中修改，点击“预览并应用”，核对差异后确认。输入框里的草稿、已应用设置、实际运行采样是三种状态；保存工作区会保留草稿，不能替代应用。关闭窗口后仍可通过顶部“查看修改”找回未应用参数。

建议分别做一次小改动：

- A：先停止，将示例中 `V1` 的开度从 80% 改为 35%，应用并重新运行，查看该支路流量下降与压降变化。再将泵转速比改为 `0.7`，比较流量和轴功率。空白组装时选择自己插入的对应阀和泵，设备标识可能不同。
- B：在“基础模型”中给 `ROOM1` 增加 2 kW 附加热负荷，应用后重新运行，比较同一仿真时刻的库温。要改目标，修改库房“温控设定”并应用；模板的脚本会读取它。脚本接管的机组运行请求不能直接手动覆盖，手动试验需先停止，在控制页禁用相应脚本，再修改机组请求。
- C：停止后点击库温表中的“设置库温”，把冷冻库 1 的目标从 −24°C 改为 −23°C，确认后重新运行；核对其他库目标未变，并查看冷冻库 1 的响应。这个入口会调整该库的两个温控 PID，不需要逐个编辑。

活动运行中能否修改某项参数，以面板显示的权限为准。成功写入后等待新的接受帧；旧结果仍可查看，但“参数已变更／等待重新采样”不能当作新参数下的结果。控制者、脚本值和采样时刻以界面说明为准。

## 查看结果与对照

设备“总览”优先给出关键读数。泵轴功率按 kW、阀压降按 kPa、库温按 °C 显示；缺少采样显示“—”。数值没有变化可能是尚未采样、参数受控制接管或系统响应较慢，先查看结果状态、控制者和仿真时刻。

点击读数旁的观察按钮加入曲线，也可在曲线页“添加观察变量”。B 和 C 创建时已有库温等关键曲线。画布即时读数来自最新完整帧，曲线来自历史采样，两者时刻可能不同。

曲线页可选择当前运行或已保存记录。比较两次运行时选择同一个项目的两条已完成记录，先核对项目、运行和参数来源，再看差异。历史曲线不会随当前项目的新参数改写；断连时保留的最近结果也不能证明后台仍在正常推进。

## 保存、重开和复用

1. 点击右上角“保存工作区”，等待服务端确认。它保存全部项目和编辑草稿；“项目 → 管理”可以单独保存当前项目。
2. 关闭页面并重新打开同一服务，或停止后用同一数据目录启动服务，再打开项目。重新运行用当前已应用设置重新求解。
3. 项目卡片的“复制项目”创建独立副本。修改副本前核对当前项目名称，原项目与其结果应保持原样。
4. 在“项目 → 管理”导出单项目 JSON；通过“导入单项目”选择文件，导入方式选“创建项目副本”。导入后保存并重新运行，核对连接、控制、工质、曲线及关键读数。
5. 保存失败、容量不足或修订冲突时保留草稿，先导出备份，再处理冲突或重试。不要把点击保存当作已经保存成功。

“重新运行”和“从快照续算”分别使用项目初态和已接受的物理状态。只有运行记录带有受支持的完整快照、界面提供“从快照续算”时，才可按提示创建恢复副本；缺少快照或源码不兼容时重新运行。详见[断点续算范围](FOUNDATION_COMPLETION.md)。

## 实际试用反馈

按 A → B → C 完成“打开、检查、运行、调参、看结果、保存、重开”。记录卡住的步骤、屏幕提示、项目名称和仿真时刻；不要只记录“能运行”。还应确认自己能解释参数是否生效、结果属于哪次运行，以及保存是否成功。
