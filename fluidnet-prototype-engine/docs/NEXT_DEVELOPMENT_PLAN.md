## 1. 建议与顺序

主线顺序为：**单盘管的通用建模入口 → 双盘管系统 → 批量工况与方案比较**。三个阶段均已完成：前两个阶段完成专项验收，工程师可在界面中配置自己的单盘管或同一容器上的双盘管关系；第三阶段批量工况与方案比较已于 2026-10-28 完成定向验收（见[1080p 计划](NEXT_DEVELOPMENT_1080P_PLAN.md)）。

这一选择延续已经接通的热耦合能力，先解决“如何搭建和修改自己的系统”。批量工况是另一个高价值方向，能服务所有已有执行域，但宜在热耦合引用、保存和结果绑定稳定后接入该类项目。

原先取消的打包发版、变量别名、外部联调、24 小时稳定性专项和现场工程校核继续保持取消。本文的算例用于验证新增软件行为与物理关系，不要求现场数据，也不代表厂家标定。

## 3. 首批：单盘管的通用建模入口

**用户可见目标：**在已有项目或从空白画布搭建的合法系统中，选择一根液体管段和一个饱和制冷剂容器，建立热耦合、设置 UA、运行并查看结果；保存重载后继续编辑。整个流程使用界面完成。

首批保持一条耦合及现有物理范围：液体侧为无储量的内置单相网络，盘管绑定内置圆管唯一通路，制冷剂侧采用现有集总模型。现有模块库、画布、工况与计算接口继续复用。

### 首批验收任务

1. 使用内置设备搭建一个符合现有模型范围的制冷站和液体回路，采用与示例不同的设备编号；参数取自已有设计点，保持可复算。
2. 从项目入口选择管段、通路和容器，建立耦合并填写 UA；运行后看到对应盘管的热量、流量、进出液温度和累计热量。
3. 重绑定到另一根合法管段；旧结果显示过期，重算后指标与新关系一致。修改参数不保证存在稳态，失败时保留原诊断，允许按原有能力使用动态计算。
4. 运行或暂停时尝试修改关系、删除被引用设备，明确要求先停止；停止后验证删除影响提示，执行删除后再撤销，设备、关系和保存内容保持一致。检查复制单设备不会产生重复关系。
5. 保存、关闭、重载，核对关系、完整工质配置、求解设置、单位和曲线绑定；用保存项目运行入口复算。
6. 原 HX1 单盘管示例仍可载入并得到原结果；无效或越范围的关系在运行前明确拒绝。

相关修改落在 `frontend/cold-storage.js`、`frontend/studio.js`、`backend/fn_engine/bridge.py` 及必要的合同／编译诊断。优先复用 `tests/browser-thermal-coupling.mjs`、热耦合保存往返和物理专项入口。按实际改动运行必要检查；不把已取消的专项恢复为前置条件。

## 4. 第二阶段：双盘管系统

2026-10-27 状态：**已完成专项复验**。合同上限为两条耦合、同一液体通路不得重复绑定、两条须关联同一个饱和制冷剂容器；两种参考系统（同回路双支路、水与乙二醇独立回路）由 `GET /api/v1/examples/thermal-coupling?topology=parallel|independent` 提供，项目页「双盘管示例」可一键创建。`tests/test_dual_thermal_coupling.py` 与 `tests/browser-dual-thermal-coupling.mjs` 覆盖逐盘管热量、共同容器能量、反向流、关闭通路和历史绑定。原浏览器流程在 1366×768 下被画布遮挡工具栏而中断；本次修复后完成小窗口编辑、服务重启和保存项目复算，证据见[完成情况核查](DEVELOPMENT_COMPLETION_AUDIT.md)。下列原始工作包与完成标准保留。

首批完成后，建议把数量上限从一条扩到**两条**，先交付清楚的适用范围和两个可复现系统，再根据需求扩大。

- 合同和编译：耦合 ID 唯一，同一液体通路最多绑定一次；允许两根不同盘管向同一合法饱和容器传热。重复 ID、重复通路、无效容器或缺失工质锚点明确拒绝。
- 求解和观察：逐盘管显示热流、温度与累计热量；共同容器收到各盘管传热之和，失败试算不重复累计。补稳态、动态、单侧零流、反向流和反向温差验证，保持原物理容差。
- 两个软件参考系统：一个液体回路分成两支路、各有一根盘管；水和乙二醇两个独立液体回路、各有一根盘管并向同一容器传热。两个系统分别检查工质、流量和热量归属。
- 保存与界面：关系列表可分别编辑和观察，复制项目后互不污染，旧单盘管项目按原含义读取。

初估 **5–8 人日**，在 TC-4 结束后复估。多支路水力复用既有求解器；本阶段新增的是多条热耦合及其界面和验证。不同容器上的更多盘管不计入首轮交付。

## 5. 第三阶段：批量工况与方案比较（2026-10-28 已完成）

该方向对泵阀、冷库及热耦合项目均有价值。阶段已于 2026-10-28 实施并完成定向验收，当前能力与操作见[1080p 计划](NEXT_DEVELOPMENT_1080P_PLAN.md)、[验收记录](FHD_BATCH_ACCEPTANCE.md)与[批量工况说明](SCENARIO_BATCHES.md)。下列原始工作包与行为约定保留为当时的设计依据。

1. **生成工况：**先支持一个已有数值设备参数的显式值列表或等间距扫描，统一显示单位与范围校验，预览后生成工况。耦合 UA 当前不是普通设备参数，不在首版中假定能直接复用参数覆盖合同。
2. **顺序运行：**固定项目修订、模块和控制脚本快照，一键运行所选工况；显示逐项状态，取消剩余项，保留失败原因。复用现有后台运行，无需先增加并行能力。
3. **比较结果：**按工况列出选定变量末值、运行状态和版本来源，允许选择少量同单位曲线叠加并导出 CSV。未声明目标和约束时不自动判断“最佳方案”。

首个验收任务可用泵阀项目的 5 个开度工况：一次提交、依次求解、比较支路流量及泵功，重开后能找到同一批次和运行来源。正式拆包前先解决批次元数据与现有运行保留数量的关系，避免运行档案被清理后留下看似完整的比较；因此本次不承诺该阶段工期。
