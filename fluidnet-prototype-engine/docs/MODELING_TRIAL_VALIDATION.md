# 项目与建模工作流验收

日期：2026-10-15。本轮覆盖独立项目修订、模块版本升级、工况编辑、结果对照及可复现样例。

## 使用方法

1. 首次启动后保存完整工作区。在项目页点击“管理”，可单独保存、重命名、导出、删除或恢复项目修订；“服务器项目”可载入已保存项目，“导入单项目”支持创建副本或替换同 ID 项目。
2. 在工作台点击“编辑工况”，新建、复制或编辑设备参数覆盖。覆盖值使用面板显示单位，校验通过后应用；选择工况并保存项目，再发起运行。选择“基础模型”可复算原参数。
3. 项目内点击“模块版本”，选择已发布的 Python 模块版本并预览源码、定义、双哈希和兼容性。兼容升级先保存旧项目修订，再统一更新同模块的全部实例；删除参数、改变单位/端口等不兼容变更会被拒绝。项目修订可恢复旧绑定。
4. 在曲线页刷新服务端档案，选择同一项目的两次已完成运行，查看公共变量曲线、最终值差异和指标。显示各自项目修订、工况及模块版本；曲线使用已保存采样点。

独立项目保存按各项目修订号检测冲突，保留其他服务器项目。保存、恢复、删除和升级时应先停止该项目的活动运行。导入或载入项目之前会保留浏览器草稿副本；完整工作区 ZIP 备份仍通过顶部“备份与恢复”操作。

数据库版本 1 首次打开时自动迁移到版本 2，从最新工作区建立项目历史，保留已有工作区和运行档案。最近 5 个项目修订与最近 5 个完整工作区修订分别保留。

## 验证入口

在项目目录安装 requirements.txt 中的依赖及 npm 开发依赖后执行：

```powershell
python -m pytest -q
npm run test:browser
npm run check
git diff --check
python scripts/verify_trial_cases.py --output artifacts/trial-acceptance-new
python scripts/build_trial_candidate.py --acceptance artifacts/trial-acceptance-new --output artifacts/fluidnet-source-candidate.zip
```

样例脚本保存每项规范项目、运行请求、结果帧、参考来源 SHA-256 和误差检查，并生成报告及 ZIP。输出目录须不存在，候选 ZIP 也须使用新路径，以保留已有验收证据。候选包脚本仅在样例全部通过后打包源码、测试与验收文件，并核对逐文件 SHA-256 和 ZIP 完整性。

## 样例与交付范围

| 样例 | 参考依据 |
| --- | --- |
| 倍思鹿 TEST 的 MOD2 泵 | 外部缓存部件的入口/出口压力、多项式及运行质量流量；只重放该部件水力关系 |
| 泵阀并联管网 | 仓库固定模型与已有结果回归 |
| 水/30% 乙二醇换热 | 独立逆流 ε–NTU 解析热量及能量收支 |
| 层流进出水箱 | Hagen–Poiseuille 阻力及隐式 Euler 质量递推 |
| Python 可编程阀门 | 标准 Kv 关系、累计质量和接受步数 |

其中 1 项是外部缓存部件参考，4 项是内部回归或解析验证，不等同于 5 个现场项目验收。包含压缩机、两相节流、冷风机或库房等未支持模型的其他外部项目不计为通过。

候选包是需要 Python 3.11+ 和依赖安装的源码包。离线 Windows 运行时、干净机器安装/升级、24 小时持续运行终态以及归档批量写入优化仍需后续验收。
