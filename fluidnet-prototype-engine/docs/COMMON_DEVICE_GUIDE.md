# 常用设备整理

维护日期：2026-11-09。范围是已有内置离心泵、调节阀、圆管、双侧换热器，以及单库房使用的冻结物库房、冷风机和单级制冷机组，围绕连接、调参和结果阅读整理界面。

## 现在怎样使用

模块库中的这七种设备都有“说明”按钮。说明按显示单位列出参数默认值、范围和修改时机，并解释端口连接方式。模块编辑器的“设备与端口”“常用参数”，以及项目设备窗口，也提供“怎么连接与调节”。

| 设备 | 优先显示的参数 | 总览结果 | 连接方式 |
| --- | --- | --- | --- |
| 离心泵 `pump` | 转速比 | 质量流量、入口和出口绝对压力、估算轴功率 | `in0` 接泵前，`out0` 接泵后 |
| 调节阀 `valve` | 开度、Kv | 质量流量、压降、两端绝对压力 | `in0` 接上游，`out0` 接下游 |
| 圆管 `pipe` | 长度、内径、绝对粗糙度 | 质量流量、压降、进出口温度 | 两端分别连接上游和下游，分支另用连接节点 |
| 双侧换热器 `exchanger` | UA、阻力系数、水力等效内径 | 一次侧和二次侧分别显示入口温度、出口温度、吸热功率 | `in0/out0` 为一次侧，`in1/out1` 为二次侧 |

参数页按上表展示常用项；总览进一步优先展示泵转速、阀门开度、管长与内径、换热器 UA。其余参数放到“其他参数”中；其中有未应用修改时自动展开，保留草稿。总览和参数页显示待应用数量，参数仍需预览确认后生效。泵效率和扬程曲线可在其他参数中设置，运行期间的写入权限仍由设备定义和控制器决定。

自定义面板优先于上述默认布局。已修复内置模块库布局与新项目实例的字段绑定不一致问题；已有项目的布局仍保留在自己的模块快照中。

## 泵曲线点表

项目里双击泵，进入“参数与型号 → 其他参数 → 编辑点表与预览”。每行填写体积流量（m³/h）和扬程（m），可在行后插入或删除点；相邻有效点之间的插入值取中点，添加末点后需补齐数据。

至少保留两个点。起点流量为 0、流量严格递增、扬程严格递减、末点扬程为 0。空白、负数、重复流量和错误顺序会标明行号，并阻止保存。预览显示基准转速下按点连接的曲线；转速比仍由原设备参数控制。

“保存为设备草稿”只保存草稿，还需在设备窗口点击“预览并应用”才能生效。取消点表保留原草稿，取消应用预览保留尚未应用的点表修改。运行中不能编辑该曲线。高级 JSON 输入保留在折叠区，已有型号和项目数据继续使用原 `head_curve` 点对数组。

从“泵／风机”模板创建的 Python 模块，在“常用参数”中编辑扬程曲线默认值时，也使用点表。保存模块草稿后，通过“保存版本”发布可复用定义。

## 单库房设备

本轮整理的是以下三个集中循环模块；热端口表示冷量连接，制冷剂循环在机组内部计算。

| 模块 | 常用参数 | 默认结果读数 |
| --- | --- | --- |
| 冻结物库房 `storage_room` | 温控设定、附加热负荷、初始库温、室外温度、货物质量、初始货温、回差 | 库温、货温、冷风机制冷量、库房净得热 |
| 冷风机 `unit_cooler` | 空气侧 UA、风机功率、风机常开/随机组启停 | 制冷/融霜/滴水阶段、风机状态、空气侧换热量、融霜电功率 |
| 单级制冷机组 `condensing_unit` | 运行请求、容量请求、变容量模式、额定制冷量、冷凝器进风温度 | 机组状态、启停等待、实际制冷量、压缩机电功率、蒸发和冷凝温度 |

从空白项目搭建的步骤：

1. 从模块库插入上述三台设备。
2. 在设备窗口“连接”页连接 `机组 cold → 冷风机 supply`，再连接 `冷风机 heat → 库房 heat`。从库房输入端开始选择连接也会保存正确方向。
3. 在“设置 → 介质与单位”填写机组制冷剂；本轮验收使用 `HEOS::R290`。在运行设置中填写时长 600 s、步长 30 s。要加速试算，在“控制”页把计算节奏选为“快速计算”。
4. 核对初始库温和货温、库房负荷、冷风机 UA、机组额定点。默认空气侧 UA 为 1 kW/K、风机功率 0.3 kW、机组额定制冷量 10 kW。额定点以外的实际制冷量由模型求解。
5. 运行后在三台设备的总览查看实际结果；增加库房附加热负荷，预览并应用后重新运行，可比较库温变化。机组运行请求 0 为停机、1 为开机；最小开/停机时间仍有效。
6. 自动温控需要在控制页新建并启用脚本，声明库温、温控设定和回差为输入，机组运行请求为输出。温度超过设定值加回差时请求开机，低于设定值减回差时请求停机。只有填写库房设定值不会自动启停机组。项目页已有的 −18°C 单库房案例包含该温控脚本。

本模块的货物模型只计算已冻结货物的显热；初始货温需在声明的冻结模型范围内。融霜参数在“其他参数”中，由场景事件触发，本轮新增浏览器流程没有重新验收长时融霜和多库房工况。

温度输入会去掉单位换算产生的浮点尾数（例如 `-17.99999999999997` 显示为 `-18`），不会在展示时改写已存参数。结果仍读取当前计算帧，缺少采样时显示“—”；状态码按这三个模块的明确含义显示为文字。

## 默认值与单位核对

以下为本地计算目录的默认值，仅用于说明软件初始状态；项目实例、型号和已保存草稿可以使用不同数值。

| 参数 | 算法单位下的默认值 | 界面显示 |
| --- | --- | --- |
| 泵转速比 | `1` | `1 倍` |
| 泵效率 | `0.75` | `75%` |
| 阀门开度 | `0.8` | `80%` |
| 阀门 Kv | `16 m³/h` | `16 m³/h` |
| 管长 | `30 m` | `30 m` |
| 管内径 | `0.04 m` | `40 mm` |
| 管道绝对粗糙度 | `0.000045 m` | `0.045 mm` |
| 管道环境温度 | `293.15 K` | `20°C` |
| 换热器 UA | `2000 W/K` | `2000 W/K` |
| 换热器阻力系数 | `5` | `5` |
| 换热器水力等效内径 | `0.04 m` | `40 mm` |

说明页的数值已与显示单位一起换算。常用参数表从实际目录读取，避免把前端早期示例的默认值当成计算目录定义。参数面板的已应用设置保留有效数字，例如粗糙度 `0.045 mm` 会完整显示。

## 结果的含义

- 泵轴功率使用实际运行输出，按 kW 展示，标签保留“估算”含义。
- 阀门和管道压降使用实际入口至出口压降，按 kPa 展示。
- 换热器各侧吸热功率使用该侧的流体焓流增量，正值吸热，负值放热。这个基础模块用于项目内同一种工质的两条流路。
- 没有计算帧或缺少对应采样时显示“—”。已应用参数与计算快照不一致时，继续标出“结果已过期”。

## 实际缺口与后续顺序

本批没有发现泵、阀、圆管或基础双侧换热器模块缺失，已有设备可以完成基础水力与换热算例。记录的缺口主要是使用入口：

| 状态 | 发现 | 下一步 |
| --- | --- | --- |
| 已修复 | 模块说明将算法默认值与显示单位直接拼接，造成毫米、百分比、摄氏度的数值不一致 | 通过真实目录逐项核对 |
| 已修复 | 内置设备的模块库面板布局，在新项目中可能被误判为字段不兼容 | 按插入时冻结的字段保存布局绑定 |
| 已修复 | 常用参数与不常用参数混排，换热器两侧读数难以区分 | 四类设备采用明确的常用字段和结果分组 |
| 已完成 | 设备窗口里的泵扬程曲线需要手写 JSON | 增加点表、逐行校验和曲线预览，继续使用现有草稿与应用流程 |
| 待做 | 本批补充的汇总读数，在缺少对应变量定义的旧设备包装中没有直接加入曲线的按钮 | 后续统一这些读数的观察入口；原有端口读数仍可直接观察 |
| 已完成 | 单库房三台设备缺少简明连接说明和常用面板 | 已从空白画布搭建并验证降温、负荷增加、启停和温控设定变化；本范围未发现缺失的设备模块 |
| 待做 | 空白项目自动温控仍需手动创建脚本 | 基于已验证的三台设备整理可复用单库房模板，包含可直接使用的温控配置 |
| 待验证 | 新搭建的单库房还未完成模板复制和项目导入导出的专项验收 | 下一步覆盖复制、导入导出以及修改参数后重新运行 |

- `npm run test:browser:device-guidance`：四类设备说明与默认值、参数分组、草稿保留、真实运行读数、换热器两侧能量结果、保存刷新。
- `npm run test:browser:pump-curve`：点表校验、增删点、取消、保存草稿与应用、真实运行、运行锁定、Python 模板曲线发布、保存刷新。
- `npm run test:browser:cold-device-guidance`：空白项目插入三台设备并连接、单位核对、降温、负荷增加、手动停启、显式配置温控脚本、设定值变化、保存刷新。

- `node tests/browser-module-catalog.mjs`：目录说明与模块发现。
