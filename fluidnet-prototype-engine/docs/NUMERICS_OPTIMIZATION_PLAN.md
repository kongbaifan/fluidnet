## 1. 范围、颗粒度与决策规则

### 1.1 一种工作包颗粒度

每个工作包对应一个可评审 PR，估算 **0.5–2 人日**，统一列出前置依赖、代码落点、交付内容、可执行验收与预计投入。1 人日按 1 名熟悉代码的开发者的有效工作日计算，包含设计、实现、测试、相关文档和一次评审修订，不包含等待外部资料。

估算超过 2 人日时继续按行为或验收场景拆分，不能把测试、守恒验证或数据兼容从任务中删掉。某包验收失败时修复该包，或记录阻塞原因并重排依赖；不靠放宽全局容差获得通过。

所有工作包初始负责人：待分配；状态：未开始。实施时在 PR 中记录实际负责人、起止日期、实际耗时、测试证据和后续偏差，避免在多个文档维护互相冲突的进度表。

### 1.2 三条计算链分别验收

| 计算链 | 当前入口 | 本计划直接影响 |
| --- | --- | --- |
| 通用流体网络 | `compiler.py` → `solver.py` → `simulation.py` | 稀疏选择、Jacobian、串联压缩、分块、热力迭代、止回阀、困液模型 |
| 冷库 A / 理想冷源 | `refrigeration/cold_store.py` / `refrigeration/session.py` | Worker 启动；后续单独接入时间误差控制 |
| 冷库 B 集总制冷站 | `refrigeration/station.py` | Worker 启动；本轮时间误差控制的工程试点 |

三者由 `sessions.py::create_session` 分派。通用水力算法提速不能登记为冷库 A/B 的提速；冷库容器内部两相物性也不能登记为通用两相管网能力。

### 1.3 优先级与执行顺序

- **P0：收益可快速验证。** B 基准/计数、W Worker 复核、S 自适应稀疏选择；先形成一次可交付版本。
- **P1：结构与数值质量。** J 内置解析 Jacobian、C 受限串联压缩、D 依赖安全的分块、V 止回阀语义与关系修正、L 热力/物性迭代加速。J、C、D 不合成一个大 PR。
- **P1 专项：精度。** A 时间误差控制先交付理想热模型与冷库 B，通用管网和冷库 A 后续接入。
- **条件 P0：工程需求明确时。** I 困液压力。若它成为近期验收场景，则把 I0–I4 提到首批之后、结构优化之前；否则先完成性能主线。
- **P2：通过立项门后再执行。** X 分块并行、A 后续执行域、I 完整切换扩展、G 可变密度长输。

不推进通用两相管网、水锤、BDF2、求解器 C 重写或 GPU。本计划可以新增 Euler 时间误差控制，但不把它写成现有范围；落地时需同步修订 `ALGORITHM.md` 的“后续状态算法”说明。

### 1.4 与原 9 项建议的逐项对应

| 原建议 | 工作包 | 对齐后的首轮完成边界 |

## 3. 全部工作包共同的完成标准

### 3.1 正确性与兼容性

1. 每项优化保留可选择的参考路径，以同一项目快照做 A/B；模型语义改变的 V、I、A 另有独立参考，不能只对照旧实现。
2. 水力每次返回仍满足项目设置的压力/质量容差；默认 1 Pa 与 1e-8 kg/s。对照旧解的拟定差值上限：流量 `1e-8 kg/s + 1e-6×|q_ref|`，压力 `1 Pa + 1e-8×|p_ref|`，温度 1e-5 K。不同有效解或接近事件边界时必须解释差异，不能直接套用等价断言。
3. 动态状态仅在子步接受后提交；失败、误差拒绝、回退、取消不能增加模块提交次数、脚本次数、设备能量计数或参数修订号。PID 与日程按既有仿真时间语义执行。
4. 变量 key、原实例 ID、端口映射、曲线绑定、项目快照与模块哈希保持可解释。重命名指标或增加字段时保留旧读取路径。
5. 旧项目中显式保存的 dense/sparse、旧模块源码与契约快照继续按原配置运行。缺失新字段按旧行为解释；新建项目由创建入口显式写入新默认。
6. 涉及严格模型字段时，同步生成 JSON Schema/OpenAPI；涉及项目归一化时覆盖导入、保存、重启、复算。物理新模式不得静默替代旧模式。

### 3.2 性能测量协议

- 固定提交、Python/依赖、硬件、原生线程数、物性后端、算法开关与工况，保留完整配置；默认原生线程 1，同时记录进程/Worker 数。
- 冷启动用新进程，5 次；热运行在预热后重复 7 次。报告中位数、最小/最大值、失败次数；不把这么少的样本写成可靠 P95。
- 分开记录编译、Worker 启动/首次物性、残差、Jacobian、线性子问题可观测耗时、热力、序列化、归档和端到端耗时。嵌套/并行计时标注重叠，不直接相加。
- 同时报告真实残差调用、Jacobian 次数/扰动调用、RPC 次数/批量大小、物性调用、迭代轮数、子步接受/拒绝数与进程树峰值 RSS。
- 运行成功率和物理残差先过门，再比较速度。拟定性能回退门：目标环境中小模型端到端中位数回退不超过 10%；超过时复测并保留旧路径，不以单次机器噪声阻塞共享 CI。
- CI 对确定性的结构/计数/守恒作硬门禁；绝对墙钟性能由固定环境报告验收。每个里程碑以 B 基线单独对照，并附逐项增益，不能只给累计提速。

### 3.3 PR 和证据规范

- 分支使用 `codex/numerics-<工作包ID>-<说明>`；一个 PR 只交付一个工作包的行为。
- 每包提供测试入口、前后差异、适用/拒绝条件与回退方式；对应代码和文档随同提交。
- 机器原始结果放忽略提交的 `artifacts/numerics/<commit>/<case>/`；将精简、可追溯摘要提交到 `docs/numerics/results/`。未运行的结果明确留空。
- 范围内测试通过后执行所需 CI；纯文档包只检查链接、格式、工作包依赖与估算一致性，不为其重复运行物理测试。
- 包完成需满足：验收通过、评审通过、关联 PR 的 CI 通过、证据落盘；草稿、局部单测通过或存在补丁均不等于完成。

## 12. A：Euler 时间步误差控制（P1 专项）

**首轮范围：**理想热模型校验 + 冷库 B 集总制冷站。不是一次改完所有执行域。输出采样 `dt_s`、控制采样、内部积分步长必须区分。

### 12.1 冻结的算法和事务约定

- 从同一 accepted state 计算整步 `x_full(h)` 与两个半步 `x_fine(h/2,h/2)`，Euler 的细步局部误差估计采用两者差值的量级，不进行二阶 Richardson 外推。
- 对每类实际积分状态采用单位明确的 `atol_i + rtol*max(|x_old_i|,|x_fine_i|)` 归一化，以最大范数判定。质量、能量和温度分别设 atol，不用一个裸数混合 kg/J/K。
- 能量状态先相对固定参考态中心化，特征尺度在 A0 冻结；改变物性内能零点时误差接受结果应等价。对状态反演敏感的容器压力/温度另作细步与整步差值检查，避免内能归一化掩盖明显压力误差。
- `error_norm <= 1` 才接受细步路径；建议步长控制 `h_next = h*safety*error_norm^(-1/2)`，增长/收缩倍率、零误差情形、最小/最大步长均有界。默认控制参数在 A0 用参考解确定。
- 整步试算、两个半步、拒绝重试均不提交 PID、脚本、设备累计量、Worker 状态或缓存污染；接受时采用细步对应的能量/质量积分。
- 输出时刻、控制采样、日程、融霜与启停边界均截断内部步长。不能跨越事件计算平均控制；接近边界的细小截断步和因误差过大触及最小步长分开诊断。
- 最小步长仍不满足误差时明确停止并保留已接受历史；不静默放宽 atol/rtol。仅报告局部时间离散误差估计，不能称为全程误差或模型准确度保证。

## 13. I：困液定容压力（条件 P0，独立物理专项）

### 13.1 第一阶段先把范围做实

第一阶段 I0–I4 只交付**显式封闭、刚性、单一均匀液体容积**的压力/温度演化原型，并接入限定的封闭运行场景。首选 HEOS 纯水；其他流体/后端只有通过物性能力与相态测试后才放开。不支持 INCOMP、气垫、两相、弹性管壁、泄漏或水锤。

| I7 / I6、D2 | 运行中关阀捕获、重开释放与参数命令事务，重建水力计划/分块/初值 | 关→热→开、多次往复、拒绝后重试都守恒；失败不改变 accepted inventory；压力/能量异常不能靠删去困液状态消除 | 1–2 |
| I8 / I7 | 与管壁能量、管道状态输出、控制/曲线/运行归档整合；设计全程能量参考统一与旧模型边界 | 库存不与既有热容重复；每帧账本及原变量完整；归档重读可解释，重跑可复现；不扩展为跨重启续算 | 1–2 |
| I9 / I8 | 限定完整开闭循环算例、API/浏览器验收与文档，替换第一阶段原型能力标记 | 闭合/重开与模式切换均符合合同，证据完整后才标“限定网络困液压力”；任意多段/多容积/弹性体仍明确待实现 | 0.5–1 |

多段温度不均匀时应使用共同压力下的 `Σρ(p,T_i)V_i=M` 或等价一致方程；这是下一次扩展，不用平均温度无说明代替。若 I5 发现必须扩成通用可压缩动态网络，应止于设计结论重新立项，不挤进原估算。

I 的拟定数值门：封闭阶段相对质量漂移 ≤1e-10；能量账本残差 ≤`max(1 J, 1e-6×E_scale)`，其中 `E_scale` 取累计绝对热量/焓交换量与总储能变化幅值的较大者；物性闭合对独立 EOS 路径的压力差 ≤`max(10 Pa, 1e-5×|p_ref|)`。开放阶段改验质量账本残差 ≤`max(1e-8 kg, 1e-8×累计绝对质量交换量)`。先在 I0 固定参考算法和尺度，并用 I1/I2 结果确认可达；无法达到时先解释模型/求解误差，不把现有保压曲线作为正确答案。
