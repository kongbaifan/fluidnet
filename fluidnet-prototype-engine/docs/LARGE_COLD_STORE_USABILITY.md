# 六库案例实用性收尾

日期：2026-11-07。范围：保存/导入可靠性、简单自动温控、可读结果及实际编辑流程。没有增加专用物理设备或培训功能。

## 交付

- 项目页新增“六库自动温控”。51 台设备、72 条连接、6 个库房、4 张画布，复用已有设备与控制器。
- 六个库房各有两台冷风机，共用库温目标，界面一次设置同库的两个控制器。另有压缩机容量、补液及冷凝器调节；不向普通使用者展示 PID 参数作为必填步骤。
- 正常、增载后恢复、减载、停一台冷风机四种工况，快速仿真 10800 s，输出 30 s；六条库温曲线自动配置。
- 库温、目标、当前电功率和能力不足提示直接可见。结果变旧时不继续标为当前结果。
- 多库面板与同屏曲线展开时画布仍有最小高度，运行按钮不会被跨页连线区域遮住。
- 规范 Project 中中文页面名称导入时得到稳定、安全且不冲突的内部 ID，显示名称与设备/连线引用保留。

## 存储边界

项目替换前的备份统一经过工作区存储入口；大 JSON 优先做无损结构去重，为草稿和备份共同留出空间。
空间不足时，仅缩减已有完整服务端落盘凭证的运行缓存；手动保存的本地记录和未归档历史不删除。
从缩减的档案缓存点“查看该次曲线”会重读服务端完整概览。
容量仍完全不足时保持当前内存数据及旧备份，并报告失败；服务端保存成功与本地失败分别提示。
本轮未迁移到 IndexedDB，也不承诺浏览器无限容量。

## 实测

同一个浏览器流程中创建工程、复制两台设备及一条内部连线、撤销、运行四工况、下载 HTML/CSV、修改温度并保存重开、反复替换同 ID 工程均通过。
注入服务端 507 保存失败后刷新，未保存目标温度仍可恢复；缩减的运行档案可重新读取曲线。浏览器页面异常为零。

| 工况 | F01 末态温度 | 第二台冷风机末态风量比例 | 观察 |
| --- | ---: | ---: | --- |
| 正常 | -24.0000°C | 0.6500 | 维持目标 |
| 增载 100 kW，90 min 恢复负荷 | -24.0139°C | 0.5143 | 增载时提高制冷，恢复后回落 |
| 减载 100 kW | -24.0017°C | 0.3939 | 减小制冷与功率 |
| 一台冷风机停机 | -23.0769°C | 1.0000 | 明确显示剩余制冷能力不足 |

这些是本模型假设下的结果，温控版增加了冷风机及冷凝器的额定换热余量，不用于宣称原固定工况工程凭控制就获得额外容量。
独立全站质量/能量账及 15 s 内部步长对照通过；沿用原物理状态接受机制，未修改求解器。

定向验证：后端案例 12 项通过；相关前端、导入、草稿、目录与 CI 清单单元 70 项通过；新代码 Ruff、两文件 mypy、生成案例及 111 份合同检查通过。原固定工况浏览器回归与新温控完整流程均通过；另实测展开曲线后的运行按钮可达、修改设备热负荷并应用、保存重开后参数保持。未运行全量测试。
