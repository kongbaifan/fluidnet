# FluidNet 后续开发计划

制定日期：2026-10-15；2026-10-17、2026-10-18、2026-10-22 复核；2026-10-25 按倍思鹿定位修改目标。复核代码基线：master `98dadd5`（v0.5.0 + 数值专项）。

## 目标

交付一个**面向暖通/制冷工程师的可编程流体热工仿真平台**：

- 工程师用 Python 编写设备模块和项目控制脚本，在画布上组态项目，不需要自己写数据库、接口和界面；
- 项目既可在本地界面运行，也可**无界面后台运行**，由数字孪生、网页或 PLC 网关通过 REST/WebSocket 启停项目、读写变量；
- 交付形态为 **Windows 离线便携包**（含开发界面）加**无界面服务模式**；
- 计算范围为单相流体网络加制冷/冷库执行域；管网两相流、水锤、完整可压缩流动（含燃气长输）和电网不在本目标内。

目标依据倍思鹿公开资料中的产品定位：工程师无需复杂编程即可写模块化算法、组态项目、后台运行，并与 Unity、网页、物联网等第三方对接；部署分开发版、仅展示版和无界面嵌入版（[整体介绍](https://www.baselu.cn/article?id=moqz46qyu3mb)、[产品改进](https://www.baselu.cn/article?id=moqzzfwaj4jm)、[本地开发与云部署](https://www.baselu.cn/article?id=moqzravpx5rh)）。倍思鹿列出的领域是暖通空调、制冷、燃气管网和化工管网，另有电网瞬态；本目标只取暖通与制冷，其余需另立物理专项。仅展示版、云端多用户部署不在本目标内。

M0–M2 已完成。剩余 M3 → M3B → M4，按 **1 名全职开发，约 18–26 工作日（4–5 周）**安排；采用相对工期，启动后再确定日历日期。下列任务为阶段计划，已完成的内容单独列出。

## M3B：无界面服务与第三方对接

2026-10-25 新增，未开始。对应倍思鹿的“嵌入式版本”：无界面、纯后台运行，由第三方控制开闭项目。现有基础：后台 `RunManager` 会话独立于页面运行，REST 命令/变量读写、WebSocket 推送和 read/control 令牌已实现。现有缺口：`POST /api/v1/runs` 要求调用方提交完整 `Project` 合同，而已保存项目存的是原型文档，第三方需要自己读取并归一化；服务总是挂载前端；变量只能用完整规范键访问；24 h 复核中停止后残留 1 个 Worker。

- [ ] `serve --headless`：不挂载前端静态文件，其余接口、认证与工作区行为不变；health 报告当前模式。
- [ ] 按已保存项目启动运行：传项目 ID、可选修订号与工况，服务端读取项目文档并归一化后提交后台运行；运行记录关联项目修订。
- [ ] 变量别名：项目内为变量键定义稳定别名，REST 读写和 WebSocket 订阅接受别名；别名冲突、指向不存在变量在保存时报错。
- [ ] 修复停止运行后残留 Worker，补回收测试；作为 M4 持续运行验收的前提。
- [ ] 对接说明与示例：Python 和 JavaScript 各一个最小客户端（创建令牌 → 启动已保存项目 → 订阅 → 写变量 → 暂停/继续 → 停止）。

不做：仅展示版界面、云端多用户与目录隔离部署、Windows 系统服务注册、串口/PLC 协议（见“首版之后的扩展顺序”）。

验收：在 M3 便携包内用 `--headless` 启动，外部示例脚本不打开页面即可完成上述流程；停止后进程表中无残留 Worker；服务重启后可查到该运行的归档。

主要涉及：`cli.py`、`api.py`、`bridge.py`、`models.py`、`jobs.py`、`runtime.py`、`docs/API.md` 和新增示例目录。

### Python 控制脚本方案

| 对象 | 职责 | 与求解器的关系 |
| --- | --- | --- |
| Python 设备模块 | 定义设备通路关系、设备输出与内部状态 | `evaluate` 可在一次数值求解中多次调用，成功子步后 `commit_step` |
| 项目级 Python 控制脚本 | 读取已接受的变量，计算控制策略，写运行参数或 PID 设定 | 在仿真采样时刻执行，控制输出作用于后续子步 |
| 内置 PID | 提供可配置的常用反馈调节 | 保留现有采样、限幅、抗饱和与手自动行为；脚本可调整其设定值 |

已接通以下约定，数据合同和接口文档已同步：

- [x] **项目定义**：记录脚本 ID、语言 `python`、源码、源码哈希、启用状态、仿真采样周期和声明的输入/输出。每次运行固定脚本快照；编辑产生草稿，应用到后续新运行。
- [x] **生命周期**：提供 `initialize(ctx)`、`step(ctx, dt_s)`、`finalize(ctx)`；`dt_s` 使用实际仿真采样间隔，暂停时不推进脚本时钟。
- [x] **控制上下文**：提供 `ctx.read(key)`、`ctx.write(key, value)`、`ctx.state` 和诊断/日志接口。读写使用规范变量键和单位，所有写入先暂存，再统一校验与应用。
- [x] **执行时序**：读取最近已接受的状态 → 执行到期脚本 → 校验控制输出并更新 PID 设定/运行参数 → PID 采样 → 求解下一子步。时间推进对齐采样时刻，两次采样之间保持输出；数值求解器的重复迭代不触发脚本。
- [x] **控制权**：每个直接执行参数只有一个控制者。PID 已绑定的设备参数拒绝脚本直接覆盖，脚本可改该 PID 的设定值；多个脚本声明写同一目标时在启动前报冲突。
- [x] **状态与失败处理**：受管理状态放在可序列化的 `ctx.state` 中，随已接受子步提交；失败子步重试复用本次采样结果，避免重复累加。脚本异常、超时或非法写入给出脚本 ID、仿真时刻及可定位的诊断，并停止该运行，保留已接受历史。
- [x] **执行进程**：采用独立 Worker，复用现有 RPC、超时和回收机制；设备关系求值与控制脚本消息分别定义。
- [x] **编辑与迁移**：统一 Python 模板、语法校验和错误行提示。内置模板直接提供 Python 版本；用户旧版 Lua 文本保留原文与语言标记，经迁移、校验后才能作为 Python 启用。
- [x] **预览与记录**：在独立初始帧上试算一个周期并展示拟写入值；真实运行记录脚本哈希、采样时刻、控制输出与诊断，便于复现。

验收场景：Python 温控示例能实际调节一个 runtime 参数；脚本修改 PID 设定值后控制器按新目标运行；暂停/单步时采样和脚本状态连续；重复数值迭代及失败子步不会重复推进状态；非法变量、越界、控制权冲突、语法错误和超时均有明确诊断；运行参数写入整批通过或整批拒绝；旧脚本导入后原文可查看。
