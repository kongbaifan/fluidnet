# 按模块配置设备面板

2026-11-05。设备面板可配置常用参数、控件、结果顺序和分组。配置是显示元数据，不更改物理模块合同、源码或版本哈希。

## 入口和保存范围

- 模块编辑器顶部“配置设备面板”：作为该模块版本以后插入新项目的默认布局；已有项目保留原来的布局与绑定。
- 设备“参数与型号”页的“配置此项目面板”：明确更新当前项目同一模块的面板，其他项目与模块库默认不变。
- 配置窗勾选常用字段，填写分组和顺序，选择适合参数类型的控件。总览最多12个常用参数、12个结果；完整参数页始终保留其余参数。
- 勾选“恢复默认布局”后恢复原有自动总览。无配置的旧存档继续默认布局。

数值框、有限范围滑块、0–1数值开关、布尔开关、文本框、曲线JSON及只读显示按合同类型限制；单位和上下限仍由模块合同给出。滑块配套数值输入支持精确填写。输入写入现有设备草稿，仍经预览与确认事务生效。

结果只能选择已有的运行/端口变量，不添加虚构变量或公式；按实际运行绑定和单位显示。未计算/未采样字段继续显示“—”，可从结果旁加入曲线。只读参数、运行时不可写参数、被PID/脚本接管的参数不会被面板配置解锁。

## 版本与数据

`panelLayout`存储在前端模块包装对象上，包含配置schema、模块ID/版本/双哈希和参数/变量结构签名。配置不进入后端`ModuleDefinition`，不改冻结schema 1–4。模块库刷新保留显示配置；定义版本/哈希或字段不兼容时显示默认面板与明确提示，需重新配置。

项目模块快照保存自己的布局，后续编辑模块库默认不影响已有项目。界面改布局不改变实例参数、物理源码或模块哈希。工作区保存/重载和“导出此项目”封装文件保留布局；“导出计算项目”的规范Project仅包含计算合同，重新导入时按默认布局显示。

## 实现和验证

纯配置校验与编辑窗：`frontend/panel-layout.js`；实例展示：`frontend/device-panel.js`；绑定传播复用`engine-client.js`的模块快照路径。

`tests/panel-layout.test.mjs`验证版本/字段绑定、类型/范围约束、顺序、未知结果拒绝；`tests/device-panel.test.mjs`继续验证采样值和控制所有权，并补只读/非runtime参数禁用。真实浏览器`tests/browser-panel-layout.mjs`验证库默认、新实例继承、原项目布局隔离、显式项目覆盖、参数应用、保存重载、暂停运行权限、单项目导出导入。测试不运行全量后端或浏览器链，截图采用1920×1080/DPR=1。

本轮结果：配置与设备面板共8项逻辑测试通过；浏览器通过，页面错误为空，包含旧内置阀和Python选型阀两条真实运行，以及封装项目导出/导入后配置相等。截图`artifacts/configurable-device-panel-1080p.png`已目视核对。

## 同步工作区的重复备份修复

验收发现当前模块目录的工作区约3.2MB，刷新载入同一已保存内容时再做一份完整本地备份会触发浏览器配额。修复先对新旧工作区使用同样的规范化，再严格比较内容；只忽略顶层保存时间、工作区修订、项目修订表和已保存参数键缓存四项回执元数据。相同内容不重复备份；任何参数草稿、布局、模块哈希、运行记录或dirty差异仍必须备份旧内容。备份失败由原事务恢复旧工作区及参数定义表，不清理原有备份键。

两条新增工作区比较/回滚测试与原转换、缓存、面板定向共17项通过；初始工作区“保存→刷新”和完整配置流程均实测连接成功、无重复备份配额告警。配置签名只存必要字段/单位/权限/范围，示例单份布局2380字符。
