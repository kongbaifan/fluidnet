# 完整后续开发计划

编制日期：2026-11-05。2026-11-06用户已授权执行全部S0–S7，实际状态见[实施与证据索引](FORWARD_IMPLEMENTATION_PROGRESS.md)。适用目标是“制作可复用设备模块，通过设备和设备组搭建制冷、暖通系统”。各阶段仅以实际验收结果登记完成。

## 1. 目标与完成口径

目标流程：选设备与型号 → 按设计工况选型 → 组装设备/设备组 → 检查连接与适用范围 → 运行 → 查看工作点、守恒和运行范围 → 比较方案 → 保存、导出、重载及复用。

后续交付分两个里程碑：

- **M1：现有设备可高效用于自建系统。** 完成S0–S4，重点是选型覆盖、设备组复用、大项目编辑/保存和系统诊断。到此可停止新增基础操作，转入使用反馈。
- **M2：明确边界内的设备物理与联算增强。** 完成S5–S7，重点是持液换热/盘管中冷、多高度容器、跨域储热和综合组合验证。每项均要有明确设备设计卡和独立验证，不以名字相同代替物理等价。

厂家校准、完整通用两相管网和现场应用验收不包含在上述里程碑中。其完成不能由现有教学示例推断。

## 4. 各阶段工作包

### S0：固定当前开发基线

- **S0-1 当前能力矩阵。** 按设备列出执行域、端口类型、支持工质、稳态/动态、作者扩展、组合、独立验证和报告状态。区分“目录能插入”与“能在该域运行”。
- **S0-2 文档入口。** ROADMAP顶部指向当前计划，旧日期文档保留为历史证据；修正仍将已实现DX、储罐或交互功能写为未实现的入口说明，保留受限范围。
- **S0-3 增量审阅清单。** 按物理设备、工作流、事务修复、合同和文档划分当前未提交改动，记录实际测试及未运行项目。实施时形成可审阅提交；推送/合并/发布按当次授权，不在本计划编制时执行。
- **S0-4 定向验证地图。** 将改动对应测试、生成器、示例和浏览器脚本列成表，不重新跑全量来重复确认已有记录。

交付：一个当前能力入口和一份增量/证据索引。这里的“基线收口”不包含安装包、发版或恢复已取消的任务。

### S1：让选型流程覆盖常用设备

- **S1-1 设计输入与计算输出分工。** 在现有选型界面中明确目标条件、待求参数、适用范围和数据来源；设计目标不会自动当成实际运行值。扩展设计输入合同前验证旧design.py兼容。
- **S1-2 泵/风机曲线。** 输入设计流量、扬程/压差与工质，使用明确来源的多点曲线选工作点或转速；曲线交点、多解、无交点、零流、转速/效率范围都有解释。泵和风机各自验收，不直接混用单位。
- **S1-3 换热器设计。** 在已支持的单相区间，根据两侧流量、入口温度和目标能力估算所需UA，并复核夹点/能力范围。当前design只有一个工质上下文，双工质设计须先扩合同或分侧传入明确物性，不能偷偷用同一侧物性。
- **S1-4 型号资料。** 保存曲线来源、参考工质/密度、有效范围、设计输入和模块版本；从项目跳到型号，再返回原设备。用户数据可导入，缺厂家数据保持教学标记。

验收：水/乙二醇泵、空气风机、单相两侧换热各至少一个独立参考；设计方案在真实网络达到约定工作点，存档重载仍用同一曲线与版本。旧液体阀选型继续通过。产物包含模块/设计函数、型号示例、使用说明和定向测试。

### S2：从设备模块提升到设备组复用

- **S2-1 水侧设备组。** 复用现有泵阀、过滤器、止回阀、分集水器与补水组合，整理循环泵支路、并联泵组、换热二次侧等参数化设备组。已有AHU/FAHU/FCU不重复造算法，补统一入口与公开参数。
- **S2-2 风侧设备组。** 整理过滤/风机/盘管段、新回风混合与热回收段；显式标注空气、水和热接口、所需边界、含湿量合同。
- **S2-3 制冷搭建清单。** 将已验证单库、多冷风机、两级与DX recipe整理成可选择设备数量/规模的受限模板；名称和实例ID重映射，房间热容/容器存量不得重复。尚不支持的制冷组合仍用可编辑recipe，不能伪称已有普通composite支持。
- **S2-4 复用编辑。** 设备组公开参数映射、插入前工质/端口/版本预检、查看内部结构、子模块升级影响预览。参数公开必须真实传到子设备，复制状态只用于初始设定，不能复制接受累计量。

验收：同一项目插入两个副本，修改其中一个不影响另一个；设备、连接、测点、曲线和控制声明重新绑定；保存/导出/重载后副本独立；固定子版本可升级及回退。压力参考、外界边界和控制器显式可见。

### S3：让大项目易编辑、能可靠保存

- **S3-1 多选工程操作。** 框选、带内部连线复制、批量移动到其他页、对齐/分布、组名与撤销；复制遇到外部连接、测点或热耦合引用时明确预览处理方式。现有单设备复制和跨页移动继续复用。
- **S3-2 全项目定位。** 按实例ID/名称/模块/回路查找；显示重复命名、未连必需端口和失效引用；从搜索结果跳到真实画布位置。
- **S3-3 数据容量。** 先测量模块定义、项目快照、历史和草稿的体积分布，按完整定义哈希评估不可变源码去重或本地存储迁移方案。迁移必须可回退、保留未保存草稿和原始备份。此前修复的是相同内容重复备份，容量问题本身并未全部解决。
- **S3-4 代表性规模验证。** 选取约30、100、300实例的跨页开发参考项目，分别测量首次加载、编辑、保存、刷新、内存及求解耗时。数字是验证目标，不是当前性能承诺；实际支持上限按测量与现有前后端限制确定。

验收：大项目跨页复制不出现重复ID/悬空连接；大数据恢复不静默丢草稿；配额不足和服务保存冲突有明确恢复路径。先记录基线再设置性能预算，优化只针对测得的瓶颈，保持既有物理容差。

### S4：把设备结果组织成系统解释

- **S4-1 运行前预检。** 将现有编译诊断整理为可点击的实例/端口/回路清单：压力参考、必需端口、工质/相态、执行域、版本、运行范围和控制归属；修复后再验证。
- **S4-2 系统结果总览。** 在现有能量账、风系统页和报告上增加回路/设备汇总：输入电功、供冷/供热、排热、库存变化、残差和数据来源。区分水蒸气/凝水、轴功/电功、瞬时值/累计量，缺字段显示未知而不是0。
- **S4-3 工作范围解释。** 泵/风机实际工作点叠加曲线；换热器能力/夹点、容器液位与温度、阀压差和机组最小流量等超界定位到字段。仅展示模型实际声明的范围。
- **S4-4 对照与调试衔接。** 复用已有批量工况与冻结报告，按统一指标解释方案差异；从系统错误跳失败回调或原档案。只有完整捕获输入的设备才可生成可重复测试素材，全网不收敛不能伪装成单回调失败。

验收：每个汇总值能追到冻结运行变量及单位；跨工质/多回路热量不重算；历史项目变化后旧报告不变。以可解释的故障案例验证定位，不新增只会显示“失败”的通用面板。

### S5：有明确用途的物理增强

此阶段用[倍思鹿原始资料核对](BASELU_SOURCE_INTAKE_2026_11_05.md)的结构作参考，公式与系数必须有独立依据，不能用固定出口温度/焓冒充有限换热。

| 工作包 | 首版边界 | 独立验证要点 |
| --- | --- | --- |
| S5-1 持液管壳/管束换热核心 | 一个带M/U状态的冷媒壳侧＋独立管程，明确工质、取相、UA与压降范围 | 两侧热量/库存闭合、零流、反流适用性、液位边界、步长敏感性、失败不推进 |
| S5-2 有限UA盘管式中冷 | 复用S5-1状态/换热能力，区别已有开式闪蒸中冷 | 两级质量差、盘管换热、夹点、中间压力和总能量一致 |
| S5-3 多高度容器 | 新几何/版本增加明确封头、取口高度、浸没状态与静压；旧直筒模型保留 | 高度—体积独立积分，越过取口的事件处理、气液出口与质量/能量账 |
| S5-4 盘管几何设计层 | 由有来源的几何/关联式得到UA和阻力，依附现有盘管/末端接口 | 面积/热阻单位、正反向和范围、设计函数与运行函数一致 |

新增物理之前固定未知量、状态、端口与工程范围，确认能与现有接受事务相容。机械TXV、真实霜量/热气融霜、转子惯性暂列候选，不能因为倍思鹿有同名模块就自动全部加入本阶段。

### S6：扩大可组合范围

- **S6-1 风水联算中的闭式储热。** 从一个充分混合缓冲箱开始，将水侧储热与空气/水盘管联立；先解决热容量与压力语义、初态和统一接受。普通fluid中已有缓冲箱不意味着风水域已经支持。
- **S6-2 制冷—液体储热耦合。** 先在原受限热耦合上验证一个液体储量，再按独立合同扩展不同容器/多个换热关系；每次只增加一种自由度，检查耦合收敛与能量闭合。
- **S6-3 制冷设备组。** 对已明确角色的制冷设备定义公开端口、子模块固定版本、展开映射和独立状态；先限定可验收拓扑，作者角色按支持列表逐类开放。
- **S6-4 多冷风机扩展。** 在已确认系统规模下增加热口汇集或可变数量方案；每个库房只有一份物理热容，冷风机单独启停、融霜热量和风机热不重复。

验收：故意令某一域求解/Worker失败，所有域保留同一接受时刻与参数修订；合法运行的交换热量等量反向。组合和手工展开的对应结果一致。不能仅解除编译器拒绝就宣布支持。

### S7：综合自建系统与使用交付

提供三类可修改的开发参考项目：

1. **暖通机房与末端**：机组、水泵、阀、换热/盘管、房间；储热只在S6验收后加入。
2. **模块化冷库**：压缩、冷凝、容器、供液、同库多冷风机；S5后增加盘管中冷或持液换热变体。
3. **制冷与水/乙二醇耦合**：明确回路分离、换热接口及库存；按S6已验收的连接范围组装。

每类项目至少覆盖：正常负荷、部分负荷/参数变化、设备停用、能力或范围不足。基础PID或已有控制模板只用于让示例可复算，不转为新控制优化项目。

共同流程：空白画布插入 → 选型/型号 → 连接/设备组 → 批量编辑 → 运行/诊断 → 曲线和冻结报告 → 单项目导出 → 新项目导入与服务重启读取 → 版本升级/回退。使用任意生成实例ID，实例数、参数和拓扑由项目数据驱动。

交付：模块/设备组包、规范Project与recipe、面板默认布局、说明与适用范围、定向测试及截图、最终能力矩阵和遗留事项。该验收属于本项目开发参考场景，不恢复此前取消的现场工程校核或倍思鹿原工程数值对测。

## 5. 全阶段通用验收标准

- 合同、源码、示例、显示单位、读写权限和生成文件一致；旧schema/版本/双哈希不被静默改写。
- 按L1合同、L2逻辑、L3真实网络与事务、L4独立参考组织证据；参考值不由实现自身输出倒填。
- 状态仅在接受点推进；失败、缩步、重复请求不重复累计。已确认用户参数命令与未接受候选状态分别处理。
- UI验收固定1920×1080、DPR=1；真实用户流程操作，保存/重载和冻结报告有实际证据。
- 测试只跑当前模块及受影响路径、相关静态/合同/生成检查和必要浏览器流程；全量pytest、全量浏览器链继续按用户要求不运行。平台保留既有全量入口，但不将其执行记录冒称本轮结果。
- 每工作包结束记录改动、实际结果、未验证边界、失败及修复；只有退出条件满足才标记完成。

## 6. 暂缓与另立范围

继续保持此前取消：安装/便携包与发版、变量别名专项、源码环境外部真实服务联调、24小时墙钟稳定性专项、现场工程校核。已有REST/WebSocket、PID/Python控制、后台运行继续可用，但不因此自动恢复上述项目。

另立范围才推进：任意两相管网及充注迁移、水锤/完整可压缩长输、电气/机械多专业求解、机械TXV动态、真实霜量/热气融霜、四口分层储热、塔填料—池体双温、多用户云平台和跨重启原仿真续算。厂家曲线/现场数据可按用户提供资料登记来源，其缺失不能通过假定“已标定”补齐。

## 7. 实施方式与首批建议

首批建议启动 **S0 + S1-1/S1-2 + S2-1**：收口当前入口，做泵/风机选型和水侧设备组。随后接S3-1/S3-2与S4基本诊断，形成M1；数据容量S3-3在首次规模实测后确定具体技术方案。

采用小批次交付：UI/文档、独立设备设计、只读评审可并行；同一求解器/接受事务的改动顺序合并。每批开始先确认当前文件树、未提交改动、依赖和定向验证集，完成后报告实际实现与边界。

本计划不承诺未经拆解验证的固定总工期。S5/S6先完成技术设计/实验再估工期；S0确认基线后可给首批工作包的执行清单和时间范围。资料或拓扑缺失时保留明确待确认项，其他独立包继续推进。
