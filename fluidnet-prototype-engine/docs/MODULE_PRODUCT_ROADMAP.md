# 从设备模块到可复用系统：端到端路线图

制定日期：2026-11-09。此路线图承接当前“先制作设备模块，再用模块搭建系统”的方向，按用户最终要完成的操作安排工作。已有能力以当前源码及相应验收记录为准；历史计划中的待办不会自动恢复为新任务。

目标：用户能够从现有设备或模板开始，填写参数、编辑端口和算法，保存成可复用模块或型号；在画布上搭建暖通、制冷系统，配置控制、运行并比较结果，保存后继续修改或用于下一个项目。

普通搭建通过界面完成；自定义设备算法继续使用已有 Python 作者入口。每种模块标明工质、连接类型、适用工况和限制，系统只允许已经支持的组合方式。

## 接下来三批工作

| 批次 | 按顺序完成 | 本批完成标准 |
| --- | --- | --- |
| 第一批：单库房模板 | 固定三台设备的模板；带上可运行温控；明确温度、负荷和额定参数；配置关键曲线；完成保存、复制和导入导出 | 用户创建模板副本，调整库温目标或附加热负荷，即可运行和查看响应；另一个副本保持原设置；导出的项目在新工作区可复算 |
| 第二批：普通控制与结果 | 为单库房提供简明控制配置；整理降温、增载、设定值变化、停启等常用工况；补齐关键读数加入曲线及结果比较 | 用户能从界面完成这些工况，并看清目标、实际状态、控制者和等待原因；配置失败保留原草稿 |
| 第三批：组合复用与首版收尾 | 选择一套已有较完整工程，验证设备组/模板重复使用、多页连接、局部修改及版本；处理实际阻断问题；整理当前改动和验收记录 | 基础水系统、单库房以及选定完整工程均能按文档从创建走到保存、导出和重载，不依赖测试脚本直接修改应用状态 |

第三批只选择已明确支持的组合方式。三台集中循环冷库设备的模板，不会因为复制就自动成为共享压缩机、容器和制冷剂管路的完整制冷站；这类工程使用已有模块化制冷设备另行组装并验证。

## 设备缺口怎样进入开发队列

先在搭建中记录具体阻断，再决定修复方式。每条记录至少包含：使用场景、所需设备/过程、已有模块、实际限制、影响、能否组合解决、优先级、完成标准和证据位置。

处理顺序：

1. **已支持但难用**：补说明、参数入口、错误定位或默认面板。
2. **能由现有模块组合**：补设备组、参数映射或可编辑模板。
3. **现有模块有明确缺陷**：修复问题并验证原使用场景。
4. **缺少必要物理或接口**：先限定所需设备的输入、输出、状态和范围，再开发独立模型，并验证其进入系统后的行为。

影响当前选定系统搭建或结果正确性的缺口优先；可用且不阻断的增强项后置。各模块的独立验证、适用范围和与系统连接的正确性分别记录，不能由一个示例运行成功推断全部工况可用。

## 首版的明确完成线

满足以下条件后，本轮主线可以结束开发并进入实际使用反馈：

1. 用户能制作一个自定义设备模块，独立验证、保存版本、放入自建项目；旧项目的固定版本保持可追踪。
2. 用户能从设备库和模板完成基础系统与单库房，不必修改应用内部数据或前端源码。
3. 常用参数和常用温控通过界面配置，修改后能区分草稿、已应用设置与实际运行结果。
4. 同一设备组或模板复制后，两个副本的设备、参数、控制、结果引用互不串用。
5. 保存、重开、导出、导入后，连接、工质、单位、版本和控制保留；相同输入的复算结果在约定容差内一致。
6. 断开的必需端口、非法参数、不支持的组合或计算失败能说明位置和原因，用户草稿及已保存项目可继续处理。
7. 提供代表工程、简明操作说明、已知限制和可重现验收记录；当前代码变更形成可审阅基线。

交付方式沿用源码/可编辑安装及已有本地界面。培训暂缓；原已取消的安装包与发版、变量别名、外部真实服务联调、24 小时稳定性专项和现场工程校核，不作为本路线图的阶段或完成门槛。普通功能回归和新增设备必要的数值验证仍随改动进行。

排期按上述批次推进，每批通过后更新状态。此文没有给出日历承诺或总完成百分比；涉及新设备物理时，先核实缺口再估算投入。
