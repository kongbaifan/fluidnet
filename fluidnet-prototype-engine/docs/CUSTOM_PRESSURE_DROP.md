# 自己写设备压降公式，再拖到画布上计算

2026-10-31。适用范围：普通单相流体网络中的无独立储量、被动阻力设备。新增 SDK API **0.8.0** 与能力 `net.pressure_drop`；原有合同、模块版本和已保存项目继续使用原协议。

## 能做什么

设备作者现在可以直接使用正在试算的流量计算压降，把公式交给平台联立求解。作者不用先把自己的设备强行换算成管道、Kv 阀门或泵曲线。

这是一项通用接口。示范滤芯和分段限流阀只存在于各自模块包中，求解器不识别这两个设备的名字。作者可从同一个模板另写其他被动压降公式。

| 示范模块 | 作者公式 | 与原有固定阻力的区别 |
| --- | --- | --- |
| `porous_filter` · 自定义多孔滤芯 | `Δp=(1+堵塞比例)×(a·m+b·m·abs(m))` | 线性黏性项与二次惯性项并存；支持运行中调整堵塞比例 |
| `flow_limiter` · 自定义分段限流阀 | 拐点前斜率 `r1`，拐点后斜率 `r2`；开度改变拐点，零开度精确关闭 | 分段斜率，不是固定 Kv；这里的“限流”是压降增长加快，流量仍可能超过拐点 |

参数是公式演示，不代表厂家性能数据或现场标定。模块累计的通过质量是接受后观察状态，不是设备内的物理存量。

## 在界面中使用

1. 在“模块 → 新建模块”选择 **自定义压降公式**，设置自己的模块标识和名称。
2. 在代码页修改 `evaluate` 中的公式。参数、端口和输出仍在“契约与版本”配置。
3. 独立验证，检查不同压差、正反流和零压差下的流量，再保存新版本。
4. 新建空白项目，插入压力边界和自己的设备，点击端口连线。可把两个不同的作者设备串联或并联。
5. 运行后从同一帧读取流量、实际压降和累计量；普通参数草稿仍需“预览并应用”。
6. 编辑源码并发布新版本后，已有项目继续固定旧版本。通过项目“模块版本”显式升级或回退，保存、重载后绑定仍保留。

也可选择“自定义多孔滤芯”“自定义分段限流阀”作为新模块的起点，修改源码后发布为自己的模块。新增受本接口支持的设备，无需增加引擎分支或专用结果页面。

## 作者需要写的代码

```python
def evaluate(self, ctx):
    m = ctx.channel('main').mass_flow_kg_s  # 有符号 kg/s，来自当前数值试算
    a = ctx.parameters['linear_coefficient']
    b = ctx.parameters['quadratic_coefficient']
    ctx.net.pressure_drop(channel='main', pressure_drop_pa=a*m+b*m*abs(m))
```

模块合同使用 schema 2 或 3，声明：

```json
{"api_version":"0.8.0","capabilities":["net.pressure_drop","state.transactions.v1"]}
```

模板另声明观察、纯函数缓存和有符号初值等既有可选能力。每条启用通路每次 `evaluate` 仍须恰好返回一条关系。

平台把作者给出的压降代入 `p_in-p_out=Δp`，同时求解节点质量守恒。`m` 的正方向是通路的 `input_port → output_port`；反向流时被动设备的压降也应为负。压降必须是有限数值；本接口要求 `m·Δp ≥ 0`，不用于主动泵功、物理储量或相变设备。单个数值点的被动性检查不证明整条曲线单调或一定收敛。

`ctx.execution.channel_data` 在求解时为 `hydraulic_trial`；独立验证台的最终复核为 `converged`。试算流量可以反复变化，不能当作最终结果或在 `evaluate` 中累计质量。`observe` 读取最终结果，`commit_step` 只生成接受候选。流量和压降输入不能由设备代码修改。

`ctx.channel(...).heat_w` 在水力试算阶段不表示有效热流；供热或跨通路换热继续使用已有 `thermal` 回调与守恒合同。自定义压降参数中不接受伪造的轴功或热流。

## 联网、缓存与兼容

- 新协议把当前通路流量一起传到 Worker；纯函数缓存键也包含这些流量，压力相同而流量不同不会误用缓存。
- 同一作者设备可读取自己的多个通路流量；稀疏模式与混合求导保守记录这些交叉依赖，保持全网方程一致。
- 现有分块、串联压缩适用性检查继续有效。单未知量显式请求 sparse 时采用 dense，避开 SciPy LSMR 的二维子问题限制，并报告实际选用方式。
- 未声明新能力的模块不接收 `trial_channels` 字段；旧模块定义的规范化及双哈希不变。旧 SDK 声明新能力会在计算前被拒绝。
- 湿空气/风水、冷库、制冷角色和热耦合的适用性继续按各自合同检查；这次不开放这些路径中的新压降关系。
- 参数、项目版本、控制写入、组合、后台运行和外部 REST/WS 继续复用已有通用流程。

## 常见报错

| 提示/错误码 | 处理 |
| --- | --- |
| `MODULE_TRIAL_FLOW_REQUIRED` | 新能力需要完整的当前通路流量；使用配套引擎，不要手工发送缺字段的求值请求 |
| `MODULE_CAPABILITY_UNSUPPORTED` | 检查 SDK 0.8.0 及 `net.pressure_drop` 声明；源码中的直接调用会定位到行 |
| `MODULE_PRESSURE_DROP_ACTIVE` | 核对流向和压降符号；主动压升设备应使用明确的泵/功输入接口 |
| `MODULE_TRIAL_INPUT_MUTATION` | 不要给 `ctx.channels` 中的试算流量赋值，改为计算并返回压降 |
| `MODULE_PRESSURE_DROP_DOMAIN_UNSUPPORTED` | 新压降能力首批只用于普通单相流体网络 |
| 作者异常或非有限结果 | 查看源码行、实例与输入回放；修正公式或参数，再独立验证 |
| 水力未收敛 | 核对压力边界、曲线、初值与单位，检查关系是否有可达工作点；增加模块类型不会自动保证曲线有解 |
