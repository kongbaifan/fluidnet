# 桌面界面优化记录

日期：2026-11-12。分支：`codex/desktop-ui-refinement`。

目标是把现有建模平台整理为适合长期操作的桌面工作区，继续使用真实设备、参数事务和计算结果。1920×1080 是主要验收视口，同时检查较小窗口的入口可达性。

## 观察与调整

原界面将项目、模块开发、结果分析和外部接口等十二个入口排列在同一条窄导航中。运行按钮浮在画布右侧中央，浮窗边界必须额外避让；首页的新手引导占据项目列表之前的主要位置。

本轮调整如下：

- 导航分为“工作区”“结果与分析”“设备与扩展”，桌面宽度下采用图标与横排文字；设置和指南固定在末尾。模块编辑与节点定义正确标记所属的模块导航。
- 首页先展示最近项目和常用模块，提供“继续建模”；示例与模块开发引导移到右侧。
- 运行、暂停、单步、停止、同屏曲线和运行设置集中在顶部工具条。其后依次是画布页签、建模工具、扩展工具和物理显示，中央画布、右侧参数、下方曲线各有明确位置。
- 浮窗的上边界按画布起点计算，保证设备窗口不覆盖运行工具条。保留停靠、拖动、缩放、置顶和保存恢复。
- 保存反馈移至页脚，仍显示保存中、未保存修改、成功和失败状态。
- 使用浅灰工作区、白色工作表面和较小圆角；沿用橙色操作强调、绿色运行状态与实际工质颜色。调整同时适用于深色主题。
- 设备选中后不再出现橙色底色和外框；设备选择、拖动和参数编辑继续使用原有交互。
- 小窗口保留紧凑导航，备份、载入和保存采用图标入口；工具条仍可操作。

主要实现位于 `frontend/desktop-workspace.css` 和 `frontend/studio.js`，样式由 `frontend/index.html` 加载。

## 2026-11-13 工作台入口整理

- 首页展示调节阀、离心泵、圆管、双侧换热器、储水罐和压力边界六个常用设备入口；点击后打开当前项目的设备库并进入放置模式。“查找设备”打开设备库并聚焦搜索框。
- 首页和项目管理页统一使用“示例项目”弹窗，按基础系统、冷库与温控、制冷站与耦合分成三组，共九个示例。基础系统预选起始内容，双盘管保留拓扑选择，其余示例直接创建并进入工作台。
- 选择设备、连接端口、检查连接、撤销、重做和适应画布保留在工具条；工况选择保留在运行控制旁。扩展操作集中到“工况与工具”，物理量和标签设置集中到“显示”，选中设备的参数、变量、型号和旋转集中到“设备操作”。三个菜单互斥展开，点击操作或外部区域关闭，Esc 关闭后焦点返回菜单入口。
- 首页常用设备入口现在可直接进入放置模式；放置模式优先消费画布中的点击，即使点击落在已有设备图形上，也会按画布坐标插入设备。
- 放置时在已有设备或端口上按下、移动和抬起鼠标，不会启动旧设备拖动、框选或端口连接。浏览器回归确认插入圆管后已有阀门的画布变换保持一致。
- 保留选择、端口连接和框选的拖动尾随点击保护；显式放置操作不再被上次交互遗留的抑制窗口吞掉。
- 桌面浏览器回归覆盖真实设备插入、设备计数增加和放置提示清空。测试在停止单步运行后执行放置，以遵守运行中的项目不可编辑规则。
- 500 像素以下的设备库从实际画布起点展开，并在重绘、窗口缩放及设备库展开/收起时更新位置。390 像素窗口下，设备库不会遮住运行、曲线、运行设置和建模工具。

本轮最终验证：`npm run check` 通过；`npm run test:ui` 387 项通过；交互、浏览器分组与影响范围的专项检查共 27 项通过。`node tests/browser-desktop-workspace.mjs` 通过，覆盖 1920×1080、1280×800、760×800 和 390×844，并检查深色主题。浏览器服务使用 Python 3.11，通过 `PYTHONPATH=backend` 加载仓库引擎。

本轮交付的是界面骨架与操作布局。当前启动入口仍是 Python 计算服务与浏览器页面，尚未引入桌面宿主或生成 EXE。桌面封装还需落实窗口与服务的共同启停、用户数据目录、文件导入导出、发行资源和安装包。模块开发各子页与结果报告的进一步信息整理，可在这套骨架上继续做具体页面优化。
