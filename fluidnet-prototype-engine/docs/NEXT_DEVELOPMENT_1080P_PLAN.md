# 新一轮开发计划：1080p 基线、批量工况与方案比较

制定日期：2026-10-27；2026-10-28 按用户确认实施。状态：**六个工作包已实现并完成定向验收**，结果见[1080p 与批量工况验收](FHD_BATCH_ACCEPTANCE.md)，使用见[操作说明](SCENARIO_BATCHES.md)。

用户要求：“只有 16:9 的 1080p，不是 1366”，并进一步限定“只做 1 和 2”。本轮只包含：**统一 1080p 基线，以及批量工况、结果存档和方案比较**。本计划承接已完成的单／双盘管和加热器补修，基线为 `codex/development-consistency` 的 `2bf8391` 加[上轮核查修复](DEVELOPMENT_COMPLETION_AUDIT.md)。旧的[热耦合开发计划](NEXT_DEVELOPMENT_PLAN.md)保留为历史资料，后续安排以本文件为准。

## 1. 目标与固定条件

本轮顺序：**统一 1080p 基线 → 批量工况、结果存档与方案比较**。

| 项目 | 本轮约定 |
| --- | --- |
| 唯一目标分辨率 | **1920×1080，16:9** |
| 自动化界面基准 | `viewport: {width: 1920, height: 1080}`，`deviceScaleFactor: 1`，浏览器缩放 100%；新建页面和重启后的页面使用同一配置 |
| 本机核验 | 使用同一 1080p 显示器，默认以系统／浏览器缩放 100% 为基准；记录实际缩放和浏览器内容区域。浏览器栏、任务栏占用的高度按真实窗口核对，不另立一种分辨率适配任务 |
| 截图证据 | 自动化主截图为实际可见的 1920×1080 视口；长表通过正常滚动分段记录，不能只用整页长截图证明按钮在屏内 |
| 旧尺寸记录 | 1366×768、1600×1000、1700×1150 等仅是以前的测试环境；不再作为本轮设计目标或额外验收门槛，也不将旧截图改名为 1080p 证据 |
| 工作范围 | 1080p 测试与界面基线；批量数值参数工况、顺序运行、独立结果存档、比较与 CSV |

本轮没有其他分辨率适配工作包。既有模型适用范围和已取消的打包发版、后续外部联调、24 小时稳定性专项、现场工程校核不作为本轮新增任务。

DX 蒸发器、真实过热吸气状态与膨胀阀过热度自调已移出本轮，不作为本计划的前置条件、工作包或自动接续任务。

| 编号 | 工作包 | 交付内容 | 完成标准 | 前置 |
| --- | --- | --- | --- | --- |
| FHD-1 | 统一 1080p 测试环境 | 公共视口配置；迁移浏览器创建、重启和切换尺寸的入口；新截图与环境元数据 | 新验收不再使用分散的小尺寸常量；实际视口和主截图均为 1920×1080 | 无 |
| FHD-2 | 核对现有核心流程 | 在 1080p 检查建模、参数窗口、单／双盘管、加热器与保存重载，修复实际发现的布局问题 | 关键按钮可见且可正常点击；参数输入和提交完整；画布、曲线、结果区各自可操作 | FHD-1 |
| BATCH-1 | 批次合同与独立存档 | 批次／条目状态、固定来源、结果存档及数据库迁移；相应 API 和生成契约 | 源项目修订或普通运行被保留策略清理后，批次来源、结果表及已保存曲线仍可读取 | FHD-2 |

| BATCH-3 | 顺序执行与中断处理 | 一键启动所选工况、逐项状态与失败原因、取消剩余项、重启后处理未完成项 | 各项使用冻结快照，重复提交不重复建批；单项失败可保留并继续；取消和中断状态真实可查 | BATCH-2 |

## 4. 批量工况与方案比较的行为约定

首版生成器只扫描**一个已有设备数值参数**，支持显式值列表和等间距序列。输入采用设备面板的显示单位，规范请求按现有单位定义转换。耦合 UA 属于关系字段，不伪装成设备参数纳入首版扫描；多参数组合、寻优算法和跨不同拓扑的自动配对不在此批范围。

批次创建时固定规范项目、源修订标识、工质、求解选项、模块与控制脚本内容／哈希、工况覆盖及观察变量。每一项从相同初始快照独立开始，不继承上一项的末态。批次使用自己持久化的快照启动，不能在每一项启动时重新读取最新项目或依赖已被清理的旧修订。

每个批次内部顺序执行，首版采用一个活动批次。单项失败记录诊断并继续后续项；“取消剩余项”阻止尚未启动的条目，正在运行的一项仍可用既有控制停止。服务重启后，未完成运行标为中断，未启动项等待用户继续；继续时从冻结输入新建运行，不宣称跨进程续算。保存或服务故障须停止派发并保留可核对状态。

批次独立保存每项的状态、运行来源、目标参数、选定变量末值和受控采样曲线，并标明曲线抽样方式。首版每批最多 20 个工况、16 个曲线变量，每变量最多保留 2000 个抽样点；这些限制在预览和合同校验中一致执行。结果查询不依赖普通运行档案仍然存在；批次记录通过显式删除管理，不随普通运行保留规则清理。若原始运行已清理，仍可查看批次已保存内容，不能显示指向空档案的完整结果假象。

比较首版限定同一冻结模型的不同参数工况。结果表显示状态、单位及版本来源；曲线按仿真时间对齐，同一图只叠加同一变量、同一单位的少量工况。没有明确目标和约束时，仅显示差异，不自动评出“最佳方案”。

### 本阶段验收任务

1. 用泵阀项目生成 20%、40%、60%、80%、100% 五个开度工况，一次提交并依次运行；比较支路流量与泵功，结果与同输入的逐项独立运行一致。
2. 用加热器功率验证 kW／W 转换；创建批次后再修改源项目、模块或控制脚本，已创建批次保持原输入。
3. 设置一个参数合法但求解失败的工况，验证该行保留诊断、后续工况继续；验证取消剩余项及重复提交。
4. 运行中重启服务，核对中断与未启动状态；重新启动未完成项时记录新的运行来源，不覆盖已完成项。
5. 触发普通运行 20 条与项目 5 修订的保留清理后，重开原批次，核对结果、来源和所选曲线仍完整。
6. 在 1920×1080 完成生成、运行、比较、导出、重载；CSV 数值、单位、失败标记与界面一致。

## 5. 1080p 界面完成标准

在唯一 1920×1080 基准内，工具栏、运行控制、工况入口、参数窗口和结果入口均可正常操作。打开模块库、参数停靠区或曲线后，控件不得被画布覆盖。普通点击必须成功，不能用强制点击代替可操作性验收。

参数弹窗的标题、关键输入、错误提示与确认／取消按钮完整可用；长列表和多工况表使用局部滚动。画布可适应与缩放，图例、变量单位和选中工况来源可辨识；同屏曲线和结果区的操作不会触发误选设备。

界面证据须记录视口、像素比、浏览器版本及所用项目／批次。仅仅修改脚本尺寸或截图文件名不算 FHD-1／FHD-2 验收完成，须重新实际执行相应流程。

## 6. 完成登记

每个工作包依次记录“待实施 → 实现中 → 待验证 → 已验证”，附代码位置、执行命令、结果和原始证据。代码已提交、接口能返回或已有截图均不能单独作为完成依据。

验证按本阶段改动选择定向后端测试和 1080p 浏览器流程；明确记录未执行项目，不把过去的全量数量或小尺寸测试当作本轮结果。新增用户入口必须从输入走到运行结果、保存重载和必要的复算，不能在失败处结束后登记完成。
