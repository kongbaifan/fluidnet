# 开放制冷设备组前端验收

日期：2026-11-06。设计合同与适用范围见 [OPEN_REFRIGERATION_GROUPS.md](OPEN_REFRIGERATION_GROUPS.md)。本轮按 P1 范围执行专项检查，没有运行全量测试。

## 使用流程

1. 在完整、已接线的制冷项目中选择“封装设备组”，选择压缩机、泵、集管或冷风机等设备。生成草稿时保留完整宿主工况及真实外部连接。
2. “独立验证”显示宿主来源、被测实例、制冷剂和公开端口。修改本次测试参数后，后端将候选组代入宿主网络运行；界面显示公开变量和状态，不显示与该网络无关的普通压力边界。
3. “配置工况与预期值”默认创建一个宿主工况；新增工况复制宿主，允许分别设置时间、参数和结果断言。保存新版本再次运行真实宿主验证。
4. 发布后可插入多个组实例，连接其公开端口。模块卡片“宿主验收”从保存的工况创建独立项目，并使用该组当前发布版本；“载入为草稿”也恢复该已发布版本的宿主验证条件。
5. 没有宿主的开放组不能使用默认水力边界验证或发布，界面给出重新封装或连接实际回路的说明。

开放组浏览器验收从“2 库房 / 2 压缩机”参考系统开始，分别发布双压缩机与吸排气集管组（12 个公开端口）、供液泵与集管组（8 个公开端口）、单冷风机组（3 个公开端口）。三个组都完成真实宿主试算，冷风机组在验证台运行后再次发布为 v2，验证发布流程仍携带宿主。

随后通过界面删除对应原设备、插入上述三个组，其中冷风机组插入两个副本；通过公开端口完成 9 条外部连接。完整网络为 11 个顶层设备、13 条连接并成功运行。将一个冷风机副本风量比例改为 80%，另一个仍为 100%，两者净冷量产生区别。项目导出、导入、保存、页面重载后的全部数值结果与修改后结果比较到小数点后 6 位一致。最后通过“宿主验收”创建项目，验证使用已发布冷风机组并得到正净冷量。浏览器无未处理异常。
