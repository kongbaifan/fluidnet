# 冷库设备模块组装验收

日期：2026-11-04。目标是用可重复放置的设备合同和画布连接搭建冷库。沿用当前分支的设备面板与审查修复，保持原有未提交改动；只做相关定向验证，未运行全量测试。

## 已交付

- “新建项目 → 空白冷库画布”，默认R134a、设备相态检查、动态运行，画布不预放任何设备。
- 复用压缩机、冷凝器、高低压容器、节流阀、液泵、冷风机、库房、集管、CO₂储液器与复叠换热器合同。参数、端口和工质决定计算，不要求固定caseId或实例编号。
- 单库8设备9连接；双库双压缩机15设备18连接；NH₃/CO₂单库10设备13连接。三套清单及规范项目在 `examples/refrigeration-modular/`。
- 组装说明、可编辑相态策略、独立回路工质、多个同类设备的实际ID指标、报告和CSV。
- 热端口角色和配对编译诊断，避免非法连接在运行阶段才出现KeyError。
- 修复有限动态运行完成后的“停止”无响应，保留历史结果与草稿，允许继续编辑复算。

## 真实画布验证

`node tests/browser-refrigeration-modular.mjs` 与 `node tests/browser-refrigeration-modular.mjs --cascade` 均通过，无页面错误。每个变体均使用隔离服务和工作区，1920×1080、DPR=1。

流程：创建空白项目 → 逐台从模块库插入 → 根据规范参数转换显示单位并编辑 → 拖动布置 → 逐端口连线 → 分别配置工质 → 检查连接 → 运行60秒 → 查看实际ID概览与冻结报告 → 停止并提高库房附加负荷 → 复算 → 保存、导出 → 重新导入为新项目 → 刷新页面后复算。

这两个浏览器流程都没有导入完整项目作为起点，也没有通过JavaScript修改应用状态。实例由画布生成D-23等编号，与组装清单中的Low、High、Room等编号不同。

| 场景 | 初始库温 | 附加负荷改为6000 W后60秒库温 | 保存导入后复算 |
| --- | --- | --- | --- |
| R134a单库 | 255.150000 K | 255.261834481 K | 同结果（7位小数核对） |
| NH₃/CO₂单库 | 255.150000 K | 255.261812975 K | 同结果（7位小数核对） |

两例均核对质量守恒和能量残差；NH₃/CO₂分别核对两回路。600秒后端设计点的两回路质量残差均为0，累计能量残差约0.000406 J。初始恒温来自设计点平衡，并非已自动配置温控。

已实际查看截图：`artifacts/refrigeration-modular-single-room-assembled-1080p.png`、`artifacts/refrigeration-modular-cascade-assembled-1080p.png`。对应界面导出项目副本也保存在artifacts，便于重新载入本轮组装结果。

## 当前能力边界

设备可以按其声明合同重复组合；不表示任意拓扑都可计算。每压力等级一个饱和容器；冷风机须由液泵供液；一个冷风机对应一个库房。集总循环不求制冷管网两相压降；本轮没有增加直接膨胀过热度控制、双级、中冷、融霜或厂家性能图。

这些设备复用已有内置算法；Python作者制冷设备仍限于已开放的节流角色，并未把所有制冷角色改为Python插件。PID、压力控制和启停脚本可另行配置，本轮组合基线不隐藏绑定固定控制程序。

接口与端口说明见 [REFRIGERATION_MODULES.md](REFRIGERATION_MODULES.md)。
