## 1. 一句话定位

单机、单相的流体管网「建模 → 编译 → 水力/热力求解 → 运行控制 → 持久化」可编程引擎原型：FastAPI + Pydantic 契约 + 独立 Python Worker 模块体系 + 零构建的原型前端。工程化程度明显高于同类原型，但**发行、CI、24 小时持续运行、干净机器安装四道门未过**，目前是「开发者本机可用的原型级引擎」，尚不是可交付试用版。

## 4. 核心数据流

```text
原型项目 → bridge.py 归一化（显示单位→规范单位）
  → Project 契约（schema_version=1，实例上限 1000）
  → compiler.py：参数校验 → 并查集合并等压节点 → 通路转支路
                 → 子网络压力参考/边界冲突检查 → 按回路分配工质
  → solver.py：least_squares 解「节点压力 + 支路流量」→ 残差独立校核
  → thermal.py：节点焓输运 / ε-NTU / 闭合回路回退 / 全网能量残差
  → RunFrame → RunManager 会话发布（暂停/单步/改参/推送）→ 前端画布与曲线
```

Python 设备模块在**独立子进程**跑四阶段 `initialize / evaluate / commit_step / finalize`：`evaluate` 无副作用、每个 Newton 残差内可多次调用；`commit_step` 只在已接受子步调用一次。模块版本不可变存放于 `.runtime/module-packages/module-<id>/v<N>/`，保存前做语法/入口校验 + 独立边界试算 + 原子 rename，项目以双哈希（content_hash + definition_hash）锁定快照。

## 5. 硬实力：做得远超原型的部分

1. **契约工程化**：Pydantic 单一来源 → 脚本生成 30 个 schema + OpenAPI + 参考算例；`extra=forbid`、`allow_inf_nan=False`；三层哈希校验贯穿「加载→编译→项目实例绑定」。
2. **物理测试是真的**：解析解逐项对照——Kv 阀解析流量、Poiseuille 层流压降、管道散热解析解、ε–NTU（含 C_r=1）、水箱隐式 Euler 一阶收敛、PID 纯比例静差/无静差、稀疏与稠密逐变量一致；776 个 `assert`、77 处 `pytest.raises`。
3. **浏览器 E2E 打真后端**：每个脚本 `mkdtemp` + 临时端口 + 隔离 `FLUIDNET_MODULE_STORE`，msedge 无头打开真实页面，断言页面文本、localStorage、`/runs` 三方一致。
4. **存储层可靠性**：SQLite WAL + `synchronous=FULL`、工作区保留 5 修订、`expected_revision` 冲突 409、帧事务落盘、重启把未结束运行标 `interrupted`；ZIP 备份逐文件 sha256、恢复校验路径白名单/重复名/2 GiB/integrity_check/外键/修订号，**全过才 rename 发布**，只建不改；有只读 PRAGMA、坏 ZIP、目录锁等故障注入测试。
5. **范围纪律**：两相流、水锤、可压缩、加热器/止回阀、组合设备递归、跨重启续算等**明确写在能力表与编译期报错里**，属设计取舍而非遗漏；与竞品倍思鹿的对照克制（未运行对方程序就不下精度/速度结论）。

### P1：工程门禁与发行

- **无 CI、无 lint、无类型检查、无覆盖率**：仓库与项目均无 `.github`，无 ruff/mypy/eslint，前端只有 `node --check`；`ROADMAP.md:44` 的 M0-3（统一入口 + Windows CI）仍是计划。
- **文档数字脱节**：`ROADMAP.md:9` 写「276 项测试通过」，实测 326 项（另一日志 313 项）；`API.md:9` 硬编码 0.4.6；`.pytest_cache` 里还有已删除用例 id，不能当通过证据。
- **无发行包（M3）**：干净机器（无 Python/Node）无法离线完成核心流程，`dist/` 里是 2026-10-08 的 v0.2.0 Studio 便携包，不是当前引擎产物。
- **并发长停顿隐患**：`jobs.py` 的全局 `wake` 锁覆盖每帧 `save_run` 磁盘事务与 Worker RPC（`set/controller/write`、`close()` 的 finalize），一个卡死 Worker 可让全局停约 10 s；`runtime.py` 的 `stderr=PIPE` 从不排空，C 扩展/warning 写满管道会阻塞子进程直到超时被杀。

### P2：架构与体验债

- **求解器性能退化**：现用 `scipy.optimize.least_squares` + 稠密 2 点数值差分（无解析 Jacobian），文档实测 1000 支路 dense 103.9 s / sparse 2.33 s；而归档 v0.2 是解析稀疏 Newton + 回溯线搜索。含 Python 模块时每次残差评估还要每模块一次 JSON-RPC。
- **数值边界**：迭代中可能把负压交给模块 `evaluate`，模块查物性抛错会中止整次求解；`reference` 模式固定 ρ/μ 只对密度告警（95 ℃ 水黏度差数倍会改摩阻）；泵反向流/曲线外不可重试；无状态设备遇到参数/控制突变直接失败。
- **契约只覆盖一半**：一致性测试只断言 4/30 个 schema，且只遍历实际结果的键（期望侧多余键漏检）；18 个路由无 `response_model`（OpenAPI 中 17 个 200 响应为空 schema）；`ErrorResponse` 从未接线、错误码无集中注册表；路径动词式/资源式混用（`/delete`、`/validate`、`/design`），`API.md:254` 参数名写错、`:18` 与 `:34` 重复记录同一端点。
- **前端到临界点**：`studio.js` 单 IIFE、2,438 行、240 个同作用域函数；`handleAction` 是 131 个 case 的巨型 switch；全量重绘 + 手工焦点恢复；5 处 localStorage `try{}catch{}` 静默失败、`run.history` 2001 行随整树持久化，超配额时草稿静默丢；`'P1'/'V1'/'V2'` 与端口后缀硬编码在 `engine-client.js`。
- **模块体系边界**：可编程性止于四类水力关系（pipe/valve/pump/compressor）的参数化，不能新增方程；Worker 只是进程隔离（可读写文件、联网、无 CPU/内存限额），不是安全沙箱，唯一实际防线是默认只监听 127.0.0.1。
- **运维缺口**：无 HTTPS（需自己套 TLS 反代）、无多进程/集群、无空间回收（无 VACUUM、无 WAL checkpoint、无模块版本删除接口）、令牌无过期/审计、无定时备份。
